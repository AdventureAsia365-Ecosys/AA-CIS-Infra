# AA-993 Phase E, slice M2a — runner: expand header, apply lock, lock risk, CIC validity

Design: root `docs/audits/2026-10-26-S252-aa993-delivery-pipeline/design.md` §1 D2.3–D2.5, §2 M2a; critic points 5,
6, 11; root ADR 0017 decisions 3–5 (Proposed). Independent of I1 and M1 (based on `origin/main`). Nothing applies an
expand file automatically after this slice: `migration-apply.yml` is M3 and waits for M2b's runtime post-check.

## Decisions

- **Header `-- migrate: expand`** is a new `FLAGS` entry; `Directives.expand` shows in `--inspect` JSON and the DB
  Migrate summary line. No header = contract: every code path for such a file is unchanged (all 148 copies on
  `origin/main` lint and `--inspect` exactly as before; test `test_every_infra_copy_still_lints`).
- **Static lint (`expand_lint`) is an allowlist of statement heads** (CREATE, ALTER TABLE, ALTER of an object the file
  creates, GRANT, COMMENT ON, INSERT INTO, SET, BEGIN/COMMIT) plus per-statement rules on existing objects. DO blocks
  and SELECT calls are refused: their bodies are blanked in the statement code, so the lint cannot see what they do,
  and there is no runtime post-check until M2b. M2b may relax this once exit 14 exists.
- **Existing vs new object** = "created by a CREATE in this file" (name compare, schema optional). Policies, triggers,
  unique indexes, grants and ALTERs on new objects are allowed; on anything else they are contract.
- **GRANT targets** are limited to the owner's `runtime_roles` + `nologin_roles` (new `OwnerDir.grant_roles`,
  mirrored from `owners.yaml` and checked by `test_owners_registry`). GRANT ON SCHEMA / DATABASE / ALL … IN SCHEMA is
  contract.
- **Hot tables** live in `owners.yaml` (`expand_hot_tables`, `expand_hot_schemas`), mirrored by
  `EXPAND_HOT_TABLES` / `EXPAND_HOT_SCHEMAS`: `acp_shared.acp_quota_ledger`, `booking.job`, `crm.job`, `shared.job`,
  `shared.job_worker`, and every `catalog.*` object. `catalog` holds only views today (the reference has no
  `catalog.*` base table), so "catalog base tables" became "any catalog.* object". The only ledger in the live
  reference is `acp_shared.acp_quota_ledger`.
- **Lock risk (exit 15)** reads `pg_class.reltuples` for every existing table the file locks with `ALTER TABLE` or a
  non-concurrent `CREATE INDEX`, before any statement and before the apply lock, in check mode too (a check predicts
  the apply). Literal reading of ADR 0017 d4: "any ACCESS EXCLUSIVE statement on a table above 100k rows", so even a
  metadata-only ADD COLUMN on a >100k-row table is exit 15 (contract). Revisit in M5 if too strict.
- **`statement_timeout` 30 s** for transactional expand files unless the header sets a lower value; a higher one is a
  lint error. CIC (no-transaction) expand files keep 15 min.
- **CIC validity (exit 16)** runs before the registration statement, on both the switched and the plain path, only
  for expand files (contract CIC files keep today's behaviour). Missing or `indisvalid = false` → not registered.
- **Apply lock**: `pg_try_advisory_lock(993, 1)` (two-int form, cannot collide with the apps' single-bigint keys),
  polled every 15 s for up to 25 min (DB Migrate waits 30 min for the task), then exit 17. Taken by apply (owner dirs
  and roles/), set-password and run-script unless `READ_ONLY`. `check` takes none (read only; the design's M3 proof
  "a check waits" becomes "an apply waits"). Released when the task's connection closes (session lock).
- **Expand skips the job-table idle wait**; one that names a hot table (only a CIC may) waits for an open rerun wave
  with the usual three 20 s re-checks, then exit 7. The `override_busy_jobs` input keeps its meaning.

## Changed vs the design

- The design lists "two concurrent apply processes serialize" as a DB test. There is no PostgreSQL in CI for these
  tests (the `*_pg` tests are skipped unless a DSN is set, and no workflow sets one) and none locally, so the test runs
  two `run_task` coroutines against fakes that share one lock and asserts their statements never interleave. The live
  proof (M3) dispatches two runs on Dev.
- RLS ENABLE + FORCE on new tables in RLS schemas, function overloads, `pg_default_acl` and row-count deltas are M2b
  (runtime post-check). The static lint already refuses ALTER DEFAULT PRIVILEGES and CREATE OR REPLACE.
- `expand` is refused outside owner dirs (roles/ files are applied by hand).

## Tradeoffs

- A strict allowlist rejects some genuinely additive files (a `DO $$ … IF NOT EXISTS … $$` guard). They stay contract
  (manual apply, today's flow) until M2b's catalog diff can prove them.
- Waiting for the lock up to 25 min keeps a person's run from failing just because an auto-apply is running, at the
  cost of a long red run if something hangs; the error names the cause.

## Should know

- **Exit codes:** 14 reserved (M2b), 15 lock risk, 16 invalid CIC, 17 lock not taken. `db-migrate.yml` maps 15–17 to
  errors; its header and `db/README.md` ("Expand files") describe the rules.
- **Live proof (orchestrator, after merge):** DB Migrate `check` of an existing copy prints the same lines as before
  (no `apply lock` line in check); one `apply` of the next real contract file prints `apply lock: taken (apply …)`.
  The expand probe (`booking.aa993_probe`, Q15) is M2b's live proof.
- **Rollback (exact):** revert this PR. The runner is uploaded from `main` on every DB Migrate run, so the next run uses
  the old code; no copy carries the header yet, and the advisory lock disappears with the task's connection. No DB
  object, setting or AWS resource to undo.

## Review fixes (S255, independent reviewer)

- **Body `SET` allowlist.** A transactional expand file may `SET [LOCAL]` only `ROLE` (the normal role lint still
  applies), `search_path`, and `lock_timeout` / `statement_timeout` between 1 ms and 30 s. Before, `SET LOCAL
  statement_timeout = '15min'` in the body lifted the 30 s cap the header lint enforces (CIS files do write
  `SET LOCAL statement_timeout = '1min'`), and `SET LOCAL session_replication_role` / `lock_timeout = 0` passed.
- **Header `=0` refused.** `statement_timeout=0` / `lock_timeout=0` disable the timeout; the header check now needs a
  value in (0, 30 s] for both keys (transactional expand files only; CIC files keep their header rules).
- **Serial columns** (`serial`, `bigserial`, `smallserial`, `serial2/4/8`) added to an existing table are contract:
  their `nextval()` default rewrites the table like any volatile default.
- **Unknown size is lock risk.** `pg_class.reltuples` is -1 until the first VACUUM/ANALYZE (PostgreSQL 14+) and 0/-1
  for a partitioned parent (autovacuum never analyzes it; `crm.audit_event` is one). The size query now returns -1 for
  "never analyzed and not empty" (exit 15, "ANALYZE it first") and the sum of the leaf partitions for a parent.
- **`CREATE … IF NOT EXISTS` of an existing relation is lock risk** (exit 15, before any statement): the lint treats
  every created name as new, so `ALTER TABLE … ADD CONSTRAINT`, policies, grants or inserts on it pass; when the
  relation already exists the CREATE is a no-op and those statements change a live object. Transactional files only
  (CIC files: the validity check covers IF NOT EXISTS).
- **An already-registered expand file skips the pre-check** (it ends in "skip: already applied" as before), so a
  re-run of an applied file never turns into exit 15 because its table grew or its IF NOT EXISTS objects now exist.
- Still not provable without PostgreSQL: the new size SQL (`pg_partition_tree`, `pg_relation_size`) runs only in the
  fake. First live DB Migrate `check` of an expand file is its proof (M2b probe).
