## Decisions

- **`var.guardduty_enabled` default false**: merging creates nothing. The orchestrator flips it to true in a
  one-line follow-up PR after the cost note (~15-20 USD/month) is accepted.
- **Features fixed in code, no per-feature variables**: RDS_LOGIN_EVENTS on (issue scope), S3_DATA_EVENTS on (D4,
  +0.30 USD/month, CRM documents bucket), EBS_MALWARE_PROTECTION / EKS_AUDIT_LOGS / LAMBDA_NETWORK_LOGS /
  RUNTIME_MONITORING off and managed explicitly, because a detector created by the API turns several on by default.
  The draft had variables for RDS and S3 (S3 default off); the decision D4 made S3 on, so the variables went.
- **EKS_RUNTIME_MONITORING not managed** next to RUNTIME_MONITORING (the provider documents drift when both are set).
- **Finding rule severity >= 4** (medium and up) -> alerts topic; the e-mail carries severity, region, type, title, id.
- Feature names checked offline: a fake-credential `plan -refresh=false` with provider 6.69.1 accepted all six
  (7 to add).

- No Runtime Monitoring: +7.40 USD/month (Fargate 2 vCPU + NAT 2 vCPU) and a sidecar memory budget on 0.5 GB tasks.

  no cost difference.
