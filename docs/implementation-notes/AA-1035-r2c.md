# AA-1035 R2 close-out (S269, lane l2-aa1035-r2c) — AA-CIS-Infra half

Root ADR 0019 d3 ("the `cis-reviewer` group stays as an alias for one release") and ADR 0006a A10. CIS half: AA-CIS-App
`docs/implementation-notes/AA-1035-r2c.md` (CIS 375 moves the A10 E2E row to `content`).

## Decisions
- The WORKFORCE trigger's A10 entry is now exactly `("cis-content",)`; `cis-reviewer` leaves `DEFAULT_STAFF_GROUPS`
  (and so `STAFF_GROUPS` from `identity.tf`), so a leftover membership is stripped like any non-staff group.
- The `cis-reviewer` Cognito group is removed from `local.id_staff_groups` (Terraform destroys
  `aws_cognito_user_group.workforce["cis-reviewer"]`). Deleting a group also drops its memberships; by then the CIS
  Staff page Sync has moved the A10 user to `cis-content`.
- `tools/identity/workforce_bootstrap.py STAFF_GROUPS` follows (its test compares it with `identity.tf`).

## Changed
- `accounts/aa365/identity.tf`, `accounts/aa365/lambda_src/identity_triggers/workforce.py`,
  `accounts/aa365/e2e_mailbox.tf` (comment), `tools/identity/workforce_bootstrap.py`, the two test files.

## Tradeoffs
- No transition window that accepts both group sets for the A10 address: the allow-map stays one exact tuple per
  address (ADR 0006a A10 guard). The cost is a few minutes on Dev where the E2E Cognito sign-in is refused (between the
  CIS Sync and this apply); there are no real users on Dev.
