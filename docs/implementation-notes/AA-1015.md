# AA-1015 (Infra): TripPlanner daily AI spend cap set explicitly

## Decisions

- `TP_DAILY_SPEND_CAP_USD` is now set on the browse and assembly Lambdas from
  `var.tripplanner_daily_spend_cap_usd` (default `"5.0"`), so the live cap is visible in Terraform instead of being
  the app's implicit code default. The value equals the app default: no behaviour change.
- A string variable, like the other Lambda env values (Lambda env values are strings).
- The per-stage caps (`TP_DAILY_SPEND_CAP_SEARCH_USD`, `TP_DAILY_SPEND_CAP_COMPOSE_USD`, AA-TripPlanner-Web AA-1015)
  are not set: unset means the combined cap only.
- The per-visitor limits (`TP_RATE_*`) keep their code defaults; nothing to set here.

## Changed

- `accounts/aa365/tripplanner.tf`: one env entry on each of browse and assembly.
- `accounts/aa365/tripplanner_variables.tf`: `tripplanner_daily_spend_cap_usd`.

## Tradeoffs

- The CIS Apps board mirrors the cap as a constant (AA-CIS-App `api/core/app_registry.py`
  `TP_DEFAULT_DAILY_CAP_USD`). Changing the variable without that constant makes the board's percentage wrong; the
  variable description says so. Reading the cap from the Lambda config in CIS is a later step.

## Should know

- The plan shows an in-place update of the two functions' environment only (no code change: `ignore_changes` keeps
  the app's deployed zip). An env update restarts warm containers, nothing else.
- The tp-023 migration copy is a separate branch/PR (normally opened by the Migration Sync bot).
