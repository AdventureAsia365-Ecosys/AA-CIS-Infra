# AA-979 CRM-P2b: the Content studio on Fargate behind the agency host portal. (Infra side)

Session S252, agent Claude Code. Branch `feat/aa-979-p2b-portal-service` (Infra PR-1 of the P2b runbook). Design:
AA-Ecosys `.tmp-session/s252/aa979/design.md` §2.5 (critic-fixed) and root ADR 0010a. Nothing here changes what users
see while `crm_agency_live = false` (the default): the portal. CNAME keeps pointing at Vercel.

## Decisions

- **Third distribution `crm_agency`**, not an alias on `crm_partner`: adding a name to the partner distribution swaps
  the certificate of a live host. VPC origin, origin secret and managed policies are reused ($0).
- **Wildcard certificate `*.lumiguides.it.com`** on `crm_agency` only (critic C1, Q11): `portal.` CNAMEs to Vercel and
  that target's CAA set has no Amazon entry, so a `portal.`-only certificate would fail with CAA_ERROR before the flip.
- **One cutover switch** `crm_agency_live` = the DNS target of `portal.` only (critic C4). The record moved from
  `aws_route53_record.vercel_frontend["portal"]` with a `moved` block (plan: update in place, TTL 300 -> 60), stays a
  CNAME on both sides, so cutover and rollback are a one-value UPSERT with no gap.
- **ALB rules 7 / 8 / 9 / 12** under the deny rule (20); `/portal*` covers `/portal-assets/` too, which keeps the studio
  at two rules within the 5-condition-values limit. `tools/terraform/alb_rule_order.py --source` passes.
- **Web env**: `WEB_PARTNER_HOSTS = partner-dev.,portal.` (the web answers both with a per-host public origin, AA-Partner
  PR 3c). `WEB_PUBLIC_ORIGIN`, `CRM_API_ORIGIN` and the API's `PARTNER_WEB_ORIGIN` / `MAIL_OAUTH_REDIRECT_BASE` stay on
  `partner-dev.` until the clean-up (Q12).
- **Portal service** = the `crm_web.tf` pattern: 0.25 vCPU / 0.5 GB ARM64 FARGATE_SPOT (Q13), desired 0 at create,
  `ignore_changes [desired_count, task_definition]`, logs in the shared `/ecs/aa-crm-dev` group with stream prefix
  `portal` (Q8), alarms no-healthy / unhealthy / 5xx > 5 in 5 min. SG egress 443 only (it calls the CIS API and Sentry).
- **Session key shared** (Q2): the execution role reads `crm/dev/web` and maps only `session_secret`; IAM cannot scope a
  JSON key, so the role could read the CRM Cognito client secret too. Accepted on Dev; the split option
  (`crm/dev/web-session`, +$0.40/month) is in the design.
- **M2M scope `cis.tenant/activate`** added to the `cis.tenant` resource server; `m2m_crm` takes every scope of that
  server (in-place client update, same id and secret). After apply, add the scope to the `scopes` value of
  `aa-crm/dev/m2m-booking-client` (informational only: the CRM asks for one scope per call).
- **partner-web callbacks** add `https://portal.lumiguides.it.com/auth/callback` and `/signed-out` (in-place client
  update).
- `tools/terraform/crm_edge_live_check.py` gains the agency checks (`--agency-cf-domain`), which connect to the
  distribution with SNI / Host = `portal.` — the pre-cutover `--resolve` check without a DNS change.

## Changed

- No CIS task-definition change (critic S3: the CIS exchange reads the partner pool ids as code constants).
- `custom_domain_urls.frontends` still lists `portal.` (added explicitly after it left the Vercel map).

## Tradeoffs

- A wildcard certificate is broader than needed; it is attached to one distribution and AWS holds the key. Swap to a
  `portal.`-only certificate at clean-up if wanted (`cloudfront.net` CAA has only `issuewild`).
- TTL 60 for the whole window costs a few more Route 53 queries (cents).
