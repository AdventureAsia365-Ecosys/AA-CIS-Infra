# AA-993 Phase E, slice M1 — the schema-dump root PR merges itself after an apply

Design: root `docs/audits/2026-10-26-S252-aa993-delivery-pipeline/design.md` §2 M1 and D2.9; root ADR 0017
decision 9 (Proposed); root ADR 0011a (Proposed, same session: ci-bot may merge schema-dump PRs in the root repo).
Stacked on I1 (`feat/aa-993-i1-db-auto-apply-role`): it adds `db/schema_dump_automerge.py` to the Migration Copy
Guard's scope list that I1 introduces. Merge I1 first.

## Decisions

- **Explicit trigger input `after_apply`** (boolean, default false) instead of parsing the free-text `reason`.
  DB Migrate passes `after_apply=true` only for `mode=apply` (run-script dispatches the dump too, but its changes
  are not a reviewed migration file, so it stays manual). M3's `migration-apply.yml` will pass it as well.
- **Merge only a PR this run opened.** If `bot/db-schema-reference` was already open (an earlier nightly with an
  unexplained change, or an earlier run that stayed open for a reason), the content now merged would include that
  change: a person looks. Design text "a nightly structural change that no apply explains stays manual" is read
  this way.
- **Conditions** (pure logic in `db/schema_dump_automerge.py`, unit tested): after_apply; no `design_ref` (a drift
  check test run); not `publish=true`; PR opened by this run; drift fingerprint computed and unchanged; design ERD
  drift step outcome `success`; the PR diff holds only `docs/architecture/db-schema-reference.md` and top-level
  `docs/architecture/erd/*.md` (never `design/`); every check run on the PR head complete, none red, and `Docs lint` +
  `gitleaks` present and green. Polls every 15 s, at most 10 min. Merge with `--squash --match-head-commit <sha>`
  so a concurrent force-push of the branch is never merged unseen.
- **Design ERD drift moved before the PR step**, `continue-on-error: true` with an `id`: a red drift still publishes
  the PR (unchanged behaviour), its outcome only gates the merge. `design_ref` pages are now extracted with
  `git archive` into a scratch dir instead of `git checkout FETCH_HEAD -- …` into the root checkout, because the PR
  step now runs after it and commits from that checkout (`git add -A -- docs/architecture/erd`).
- **The merge step is `continue-on-error`**: the dump, artifact, S3 copy and PR already exist; a failed merge must
  not turn the run red and hide that. The summary says why the PR stayed open.
- **CRM latest key** added to `schema_dump.py` (`crm-NNN`), the reference header (only when present), the ERD
  owner label and both summary lines. The first dump after merge shows it, which is one ERD index/header diff.

## Changed vs the design

- The design lists "root `docs-lint` / `contracts` checks green". `Contracts` never runs on dump PRs (path filter:
  `docs/contracts/**`, `docs/adr/**`, …), so the required list is `Docs lint,gitleaks` and *any* other check that
  does run must be green too.
- Steering `.kiro/steering/db-schema.md:25` ("merge it") is root-repo text: updated in the root PR of this session
  (`docs/aa-993-adr-0011a`), not here.

## Tradeoffs

- No `allow_auto_merge` on the root repo (and it has no branch protection to auto-merge against), so the job polls.
  Up to 10 min of runner time per after-apply run; free while public.
- Squash merges by the App leave the branch to be deleted by the repo setting; the next run re-creates it from master.

## Should know

- **Live proof** (orchestrator, after merge): the next DB Migrate `apply` → DB Schema Dump run → root PR opened and
  merged by `app/aa-ecosys-ci-bot` within minutes (`gh pr view <n> --repo AdventureAsia365-Ecosys/AA-Ecosys --json
  mergedBy,mergedAt`). Negative: the next nightly with a structure change stays open (summary: "not dispatched after
  an apply").
- **Rollback (exact):** revert this PR (one commit): DB Migrate stops passing `after_apply`, the dump goes back to
  "merge by hand", the ERD drift step returns to its old place. No AWS or GitHub setting to undo. Nothing merges
  unless every condition holds, so there is no per-run switch to flip.
- ci-bot's token for the root repo already had Contents + Pull requests write (AA-901); no new permission.

## Review fixes (S255, independent reviewer)

- **Drift not computed no longer reads as "unchanged".** The PR step keeps `DRIFT_CHANGED=false` when the drift job
  failed (`NEW_DFP` empty) so a failed replay never opens a PR by itself; the merge step got that same `false` and
  could merge with no drift check at all, against the decision above ("drift fingerprint computed and unchanged").
  The step output is now `drift_changed=not-computed` in that case, so the PR stays open; the PR body no longer
  promises a self-merge then. A wiring test pins it.
- **Should know:** `after_apply=true` is a plain dispatch input: anyone with write access who dispatches DB Schema
  Dump by hand with it set gets the after-apply rules (still: PR opened by that run, drift computed and unchanged,
  design ERD green, generated files only, root checks green). Acceptable in the dev phase; restrict to
  `github.triggering_actor == 'github-actions[bot]'` if that ever matters.
- **Should know (stacking):** this branch's base is I1's first commit (3dd4bc0), not I1's review fix. After I1's
  squash merge, rebase with `git rebase --onto origin/main 3dd4bc0`.
