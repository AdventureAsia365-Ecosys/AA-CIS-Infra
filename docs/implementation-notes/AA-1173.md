## Decisions

- **GOVERNANCE, not COMPLIANCE mode**, with the bypass denied to every principal in the bucket policy. COMPLIANCE
  cannot be undone even by the account root, `tools/terraform/plan_guard.py` refuses it on Dev, and the issue asks for
  "bypass denied" (S287 Q8). Retention is `var.compliance_evidence_retention_days` (365, root D-09 security/audit
  class). Changing it after the first apply is an Object Lock configuration update that plan_guard refuses without
  `allow_guarded` (tech lead).
- **Write-once by S3 conditional writes**: the bucket policy denies a PutObject without `If-None-Match` (condition key
  `s3:if-none-match`), so an overwrite of an existing key answers 412 and a plain PUT 403. With versioning on, an
  overwrite would otherwise only add a version; this makes the key itself immutable. Multipart uploads are refused too
  (the collectors upload single objects; `aws s3api put-object`).
- **The bucket policy only denies**: the collector role's allow is in its identity policy (same account), and every
  other principal (administrators included) is denied the tamper actions and any write. Undoing it is a reviewed
  change of this file and a CloudTrail management event.
- **Trust pinned to the workflow file**: the immutable repo subject + `ref` + `job_workflow_ref` (supported by STS for
  GitHub tokens since 01/2026, IAM "Available keys for AWS OIDC federation"). Only the root "Compliance evidence"
  workflow on master and this repo's "Compliance AWS" workflow on main can assume the role; a pull request never can.
- **Prowler from its public ECR image pinned by digest** (5.48.0, the multi-arch index digest, checked against the tag
  on 24/11/2026): the pull verifies every layer, no release download, no pip install of Prowler. Prowler's own output
  goes to a file that is sealed privately; the public log has counts only.
- **No acc4 / acc1 scan yet**: the issue names Prowler on acc2 and acc4 and a read of the acc1 invoker role. That needs
  a read-only role in acc4 (another Terraform root, applied locally with MFA) and a cross-account trust; follow-up.
- **The alerts topic is matched by its name suffix** (`-acp-alerts`, aws_checks.toml), never an ARN in the repo.

## Tradeoffs

- The nightly AWS checks are graded in the collector (security invariants: logging on, MFA, no port open to the
  internet beyond 80/443); only the Prowler critical / high tolerance is a CIS setting
  (`cis.compliance.prowler_critical_high_max`), since a known finding goes through an exception, not a higher number.
- The credential-report poll count and pause are in `aws_checks.toml`: a CI tool has no Platform › Settings
  (follow-up if the tech lead wants them editable).
- SSE-S3 instead of a KMS key (1 USD/month + requests would break the ~0 USD budget, advisory D.5).
- No CloudTrail data events on this bucket (billed per event); bucket policy changes are management events.
