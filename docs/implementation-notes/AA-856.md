# AA-856 — TripPlanner Lambda may invoke Cohere Embed v4 through the global profile (S239)

Infra half of AA-856. Branches: `fix/aa856-tp-embed-global-iam` (this IAM change) and
`chore/aa856-copy` (byte copy of CIS migration 238). App halves: AA-CIS-App
`feat/aa856-cohere-global-profile` (migration 238), AA-TripPlanner-Web
`fix/aa856-search-embed-cache` (query-embedding cache + keyword fallback).

## Decisions

- Add `arn:aws:bedrock:*:<acc2>:inference-profile/global.cohere.embed-v4:0` to
  `local.tp_embed_model_arns` (statement `BedrockEmbedDirect` of the TripPlanner Lambda role). The
  global profile's models are the regionless `foundation-model/cohere.embed-v4:0` (already granted)
  and the source-region one (covered by the `*` region wildcard): `aws bedrock get-inference-profile`
  on acc2 us-west-1, 16/10/2026.
- Keep the `us.` grants: the Lambdas' built-in route (catalog unreadable) and a rollback of 238 use it.
- CIS needs no change: the ECS task role allows `bedrock:InvokeModel` on `*` (modules/ecs).

## Changed

- Not in the issue text: found while preparing migration 238 — without this grant the switch would
  turn every TripPlanner search embed into AccessDenied.

## Tradeoffs

- One extra ARN, no wildcard on the profile name: the role stays scoped to Cohere Embed v4.

## Should know

- **Order**: this IAM change is live (Terraform Apply workflow) first, then DB Migrate check/apply
  of `cis/238` (after the owner PR is merged), so the catalog never points at a profile the
  Lambdas cannot call.
- Quota: `L-7089DC7D` (global, adjustable) increase to 2,500 rpm requested, case 179212369200770;
  `L-EB8C1F30` (`us.`) is not adjustable.
