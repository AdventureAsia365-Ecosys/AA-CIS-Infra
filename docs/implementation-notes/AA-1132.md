# AA-1132 — Docs impact caller (slice A4)

The full notes of the docs sync engine are in the AA-Ecosys root repo, `docs/implementation-notes/AA-1132.md`.

## Decisions

- This repo adds only `.github/workflows/docs-impact.yml`, a caller of the root reusable workflow
  `AA-Ecosys/.github/workflows/docs-impact.yml`. The doc map and the tool live in the root (tech lead S283: one central
  map) and are read from root master at run time, so a map change needs no change here.
- Warn only: the job posts one sticky PR comment and warning annotations, exits 0, and is never a required check.

## Changed

- Nothing in the app code.

## Tradeoffs

- The reusable workflow is pinned to a root commit (workflow lint WL6, org setting for SHA pins); the root repo has no
  release tags, so the trailing comment is `# vYYYY.MM.DD`, the date of that commit with a leading `v`: the Infra
  action-pin test (`tools/terraform/tests/test_workflow_action_pins.py`) needs the `v`, and every repo's workflow
  lint accepts it. The five callers keep the same pin and comment. Only a change of the root workflow file needs a
  re-pin here.

## Should know

- Ship order: the AA-Ecosys root PR that adds the reusable workflow merges first (squash), then this caller is
  re-pinned to that master squash commit (`# v<date of the commit>`) and only then pushed. The branch first carried
  the root feature-branch commit, which never reaches master after a squash merge, so a caller run could not resolve
  it.
- The job listens to `pull_request` and `merge_group` without a `paths:` filter (merge-queue rule); on `merge_group`
  the called job is skipped, so a queue group never waits on it.
- Answer a warning with one line in the PR body: `Docs-impact: <AA-Ecosys PR link>`, `Docs-impact: updated-here` or
  `Docs-impact: none: <reason>`.

## Docs-sync role reads the current manifest (S284, lane l14)

- Decision: the docs-sync role (`accounts/aa365/docs_reader.tf`) gets `s3:GetObject` on the one object
  `docs-reader/manifest.json`, statement `ReadCurrentDocsManifest`. The root Docs sync workflow downloads the manifest
  it is about to replace and uploads it as `docs-reader/manifest.previous.json` (Put is already granted on
  `docs-reader/*`): the one-step undo of a bad publish (advisory A1 item 5, follow-up of root PR #875).
- Tradeoff: a download + upload, not a server-side `aws s3 cp` copy: the CLI's S3-to-S3 copy also reads tags and
  metadata (GetObjectTagging, HeadObject with copy-props), which would need more than one action. No KMS grant: the
  bronze bucket is SSE-S3.
- Should know: the root workflow skips the copy with a notice until this is applied (Terraform Apply Dev), so the
  merge order does not matter. Guard: `tools/terraform/tests/test_aa1132_docs_sync_manifest_read.py` (one Get
  statement, one object, no wildcard, write/list unchanged, bronze SSE-S3).
