## Decisions

- **Thin caller** (`.github/workflows/spec-trace.yml`): `pull_request` + `merge_group`, no `paths:`, `contents: read`,
  no secret. The called job reads the PR title and body (merge queue: the group's commit messages) and checks the spec
  of each named issue, in this repo's `.kiro/specs/` or in the root's, plus every spec the PR changes; a PR with no
  spec passes at once.
- **One pin for both** `uses:` and `tools-ref`: the root commit the checker and the root specs are read from. The
  same commit is pinned by `change-guard.yml`.

## Changed

- New `.github/workflows/spec-trace.yml`.

## Tradeoffs

- Not a required check: a red Spec trace shows on the PR but does not hold the merge queue. It becomes required only
  if the tech lead adds it to the ruleset.
