# AA-1196 — the AA-973 B2B seed plan has a room on every night (CRM E2E Dev green again)

S296, 27/11/2026, Claude Code (lane l11-crm-e2e). The CRM side lives in AA-Partner
`docs/implementation-notes/AA-1196.md`.

## Decisions

- **Cause.** The CRM E2E spec `aa-lines.spec.ts` asks Booking for a tailor-made quote ("our own date") of the AA-973
  seed tour, a 6-day tour. Since AA-Booking #304 (23/11, the can-operate check) a tailor-made `tp:` quote line of a
  blocked tour is refused 422 `invalid`; rule N1 blocks a night without a room component, and the seed plan had its
  room on day 1 only. Booking's log of run 45981939192 shows `POST /booking/b2b/v1/quotes` 422 at 10:26:44Z, and the
  CRM line read `failed`. Booking is right: the synthetic data no longer describes an operable tour.
- **Fix in the seed, not in Booking or the spec.** The seed now gives the plan its room type on every night
  (days 1 .. duration - 1 of `catalog.v_tour.duration_days`) and the service on day 1. No "no hotel needed" marker and
  no admin sale exception: both would hide the rule the live checks should exercise.
- **Additive on Dev.** A plan with the earlier day-1 rows gets only the missing nights (inserts, no delete); a set that
  is not a subset is replaced as before.
- **Merged as DRY RUN** (`READ_ONLY = True`, the file had stayed `False` since #311): dispatch, read the plan, then the
  one-line apply PR, then back to read-only (the #981 / #982 pattern).

## Changed

- `db/scripts/aa973_b2b_seed.py`: `room_nights`, `wanted_components`, the component step; docstring.
- `db/tests/test_aa973_b2b_seed.py`: a 6-day tour gets rooms on days 1..5; an earlier day-1 seed gets the four missing
  nights only, and a second run writes nothing; `room_nights` table.
- `db/scripts/README.md`: the components sentence.

## Tradeoffs

- The quote of the whole tour now costs five room nights instead of one (synthetic money, no check reads the amount
  beyond "more than 0").

## Should know

- The existing seed contract (23/10 .. 21/01/2027) no longer covers today + 60 (`MIN_COVER_DAYS`), so the same run
  expires it and publishes a fresh 90-day one, and tops the departures up to two future ones. Nothing else changes.
- The seed tour is the first `catalog.v_tour` row by `source_id` with no plan (the CRM E2E variable `E2ECRMAATOUR`).
