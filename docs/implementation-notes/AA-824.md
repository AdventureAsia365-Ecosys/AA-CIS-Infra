# AA-824 — RDS guardrails, RDS alarms, TripPlanner Lambda reserved concurrency

Session S237 (Claude Code, lane infra, task inf-824). Scope here is the Terraform half only. The
connection-budget half that lives in app repos (per-role `CONNECTION LIMIT` owner migrations,
TripPlanner pool max 1, CIS API pool cap, `application_name` per pool, `CREATE EXTENSION
pg_stat_statements`) is NOT in this PR.

## Decisions

- **Custom parameter group `aa-cis-dev-pg15`** (family `postgres15`) replaces `default.postgres15`.
  Checked live on 15/10/2026 (`describe-db-parameters default.postgres15`):
  `shared_preload_libraries = pg_stat_statements`, `rds.force_ssl = 1` and `track_io_timing = 1`
  are already the RDS system defaults. They are still set explicitly so the group documents them
  and an engine default change cannot drop them. Net behaviour change is only:
  `log_min_duration_statement` -1 -> 500 ms, `log_lock_waits` 0 -> 1,
  `idle_in_transaction_session_timeout` 24 h -> 60 s, and `log_parameter_max_length` -1 -> 0
  (review fix, see below).
- **`log_parameter_max_length = 0`** (added in review, not in the issue text). The apps use
  asyncpg prepared statements, so with the default (-1) every slow-query line would carry
  `DETAIL: parameters: $1 = '...'` with full bind values: Booking customer PII, staff sign-in
  codes, tenant API keys. The log is exported to CloudWatch for 14 days, so it would copy that data
  out of the database. 0 keeps the statement text and the duration, which is all the slow-query
  log is for. Dynamic; checked modifiable on `default.postgres15` (15/10/2026).
- `shared_preload_libraries` keeps the same value and uses `apply_method = "pending-reboot"`
  (static parameter). All other parameters are dynamic.
- **Instance class `db.t4g.small`** (decision E5) set as the module default; `modules/rds` has a single
  consumer (`accounts/aa365/main.tf`). `describe-orderable-db-instance-options` confirms
  postgres 15.17 + gp3 + PI + storage autoscaling on t4g.small in us-west-1a/1c.
- **Performance Insights** on with retention 7 days (free tier). t3.micro supports it too, but it
  ships with the resize so there is one reboot window.
- **Log group** `/aws/rds/instance/aa-cis-dev-db/postgresql` is created by Terraform (14 days)
  before the export is enabled (`depends_on`), so RDS does not create it with no expiry.
- **`apply_immediately`** is a module variable wired to a new root variable
  `rds_apply_immediately` (default `false`). The orchestrator can take the reboot now with
  `-var=rds_apply_immediately=true` in a window where `shared.job` and `booking.job` are idle.
- **`final_snapshot_identifier = "aa-cis-dev-db-final"`**, static. `deletion_protection` stays on, so
  this only matters after a reviewed PR turns protection off.
- **Alarms**: the three existing RDS alarms are edited in place, not duplicated:
  `rds_cpu_high` 2 -> 3 periods (15 min); `rds_connections_high` > 70 for 10 min -> > 60 for 5 min;
  `rds_free_storage_low` 4 GiB -> 50% of the configured base size (10 GiB of 20 GB). New:
  `rds_freeable_memory_low` (< 100 MiB, 2 x 5 min) and `rds_cpu_surplus_credits_charged`
  (Maximum > 0 in 5 min). All go to the existing `aws_sns_topic.alerts`.
- **Lambda reserved concurrency = 5 each, not 10.** The task spec says 10, but the orchestrator
  journal (15/10, ~01:40Z) records that AWS approved the 1000 quota before AA-824 shipped, so a
  manual `put-function-concurrency 5` was set on browse and assembly, and says Terraform must encode
  5 each until the TripPlanner pool max 1 lands. Live value read 15/10: 5 / 5. Encoded as variable
  `tripplanner_lambda_reserved_concurrency` (default 5); raising it is a one-line change.

## Changed (vs. the issue text)

- FreeableMemory alarm uses 2 x 5 min (the issue gives no duration) to avoid one-sample noise.
- FreeStorageSpace threshold follows the configured base size (`module.rds.allocated_storage`),
  not the autoscaled size: after autoscaling grows the disk, the alarm still fires at 10 GiB free.
- Alarm dimensions now reference `module.rds.db_identifier` (new output) instead of a hard-coded
  string; the value is the same (`aa-cis-dev-db`), the plan shows no dimension change.

## Tradeoffs

- One reboot instead of two: parameter group attach + class change + PI all ride on the class
  change restart in the maintenance window (mon 04:00-05:00 UTC), or one immediate apply.
- `idle_in_transaction_session_timeout = 60 s` is the only setting that can break running code: a
  session that opens a transaction and then waits > 60 s (for example an LLM call inside a
  transaction) is terminated. It is dynamic, so it can be raised or set to 0 without a reboot if a
  job fails after the apply.
- Static final snapshot name: a second delete/recreate would collide with an existing snapshot of
  that name. Acceptable on Dev with deletion protection on.
