# AA-1119 — Release safety (AA-CIS-Infra part)

Whole picture, decisions and merge order: root `docs/implementation-notes/AA-1119.md` (S291, lane e-release-safety;
S282 audit R31, R32, R40).

## Decisions

- **DB Migrate `inputs` job** before `target` (and so before `migrate`, its environment and the OIDC role): no
  environment, no AWS, no secret; `db/db_migrate_inputs.py` reads `db/owners.yaml` (owners, password roles,
  environments) with a small stdlib reader (checked against PyYAML in `db/tests/test_aa1119_db_migrate_inputs.py`) and
  prints every reason at once.
- New refusals: a run from a ref other than `main` (before: every job skipped, the run looked green), an empty input
  for the mode, a symbolic link or a path outside `db/scripts/` / `db/migrations/`. The rest mirrors the existing
  "Unused inputs" and "Validate input" steps, which stay unchanged (defence in depth; they also compute the version key
  and run the lint).
- The override-reason limit (one line, 200 characters) mirrors the existing step: an input format, not a policy value.

## Should know

- No change to the `migrate` job; root tools that follow a DB Migrate run by its run name are unaffected.
