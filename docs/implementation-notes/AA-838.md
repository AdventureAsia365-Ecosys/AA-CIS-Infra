## Decisions

- **`crm_app = 6` joins `local.rds_role_connection_limits`** (observability_ecosys.tf), so the existing for_each
  creates `aa-cis-dev-rds-role-connections-crm_app` with the same shape as the other roles (Maximum of
  `AA/RDS RoleConnectionLimitPct{Role=crm_app}`, > 80 %, 1 of 2 x 5 min, notBreaching, ALARM + OK to the alerts
  topic, database runbook). The sampler already publishes the metric (the report read 5/6 = 83 % on 24/10).
- **Threshold not tuned for CRM.** Pool 3 x 2 tasks = the limit 6, so a rolling CRM deploy can alarm. The alarm then
  says the truth (the next connect would be refused); the fix is the pool budget (report D-list), not a higher
  threshold.
- **Probe scripts copied for DB Migrate `mode=run-script`** (master login, full statement text):
  `db/scripts/aa838_capacity_probe.py` (byte-identical to the lane file) and `db/scripts/aa850_dead_table_dry_run.py`
  (one line changed, below). Both `READ_ONLY = True`; `python3 db/run_migration.py --inspect-script` passes for both.
- **aa850: one-line change for the shape check.** Its ECS-exec fallback ran `SET default_transaction_read_only = on`,
  which the runner's check refuses in a READ_ONLY script (any literal naming `transaction_read_only`). Replaced by
  `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` (same effect: sets the session default), the form the
  capacity probe already uses. The lane's source in the root `.tmp-session/S255/aa850/` still has the old line.
