# AA-78 — Brand Brief Parser Lambda (Terraform Phase)

## Decisions
- Used `brand_brief_parser_zip` as a standalone variable (not folded into `lambda_zip_dir`) to match spec and allow CI to override independently.
- Reused `aws_iam_role.lambda_exec` (shared Lambda exec role) — no new role created.
- ECS task role referenced by name `${local.name_prefix}-ecs-task-role` (verified against `modules/ecs/main.tf:49`).
- Placeholder ZIP committed to `dist/lambdas/` so `terraform plan` can resolve `filebase64sha256` locally; CI will replace with real build artifact.

## Changed
- No deviation from spec. `depends_on` block omitted from `aws_lambda_function.brand_brief_parser` because `aws_cloudwatch_log_group.brand_brief_parser` references the function name (forward dependency), unlike other Lambdas that declare `depends_on` pointing to their log group.

## Tradeoffs
- Standalone zip variable vs reusing `lambda_zip_dir`: adds one root-level variable but gives CI flexibility to build and inject the path without coupling to the shared dir convention.
- IAM inline policy on ECS task role (not Lambda resource policy): allows ECS→Lambda invocation via boto3 without needing `aws_lambda_permission` resource, consistent with the RequestResponse pattern.

## Should know
- `dist/lambdas/brand_brief_parser.zip` in repo is a placeholder stub — CI must build real ZIP from `AA-CIS-App/services/acp_brand_brief_parser/` before `terraform apply`.
- `terraform apply` will create the Lambda with the placeholder handler; invoke test (step 9) requires the real ZIP deployed.
- ECS task role name must remain `aa-cis-dev-ecs-task-role`; renaming it (e.g. during ECS module refactor) will break this inline policy attachment.
