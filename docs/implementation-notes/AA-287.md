# AA-287 — AWS Budgets (S102 Phase 3a)

Repo/file: `accounts/aa365/observability.tf`

## Decisions

- Single `aws_budgets_budget` — $250/mo total account cost, no cost-filter
  scoping. Reused the Execute Plan program-level number as instructed
  (not re-confirmed with Nghiep).
- Notifications: two thresholds (80% and 100% of ACTUAL cost), delivered via
  direct email (`var.alert_email`) rather than via the SNS topic created for
  AA-284.

## Changed vs. original ask

- The task allowed either "reuse the AA-284 SNS topic" or "email directly if
  simpler" for budget notifications — went with email. AWS Budgets → SNS
  requires an SNS topic resource policy granting `budgets.amazonaws.com`
  publish rights (extra IAM surface); direct email avoids that for no loss of
  function, since Budgets' own email notification already exists as a
  first-class delivery method.
- Did NOT implement the tag-based ACP $180 / total $250 split mentioned in
  the task. This account has no cost-allocation tags applied per project yet
  (confirmed by inspecting existing resource tags — `Project`/`Environment`/
  `ManagedBy` only, nothing that scopes ACP vs. non-ACP spend). A tag-filtered
  budget today would just report $0 spend, which is worse than no budget at
  all (false confidence). Flagged in the PR for Nghiep to decide: either add
  a real cost-allocation tag first, or accept the single total-budget as
  sufficient for now.

## Tradeoffs

- No `cost_types` block override — uses AWS default cost calculation for a
  basic COST budget. Not customized since the task didn't specify special
  cost-type handling.
