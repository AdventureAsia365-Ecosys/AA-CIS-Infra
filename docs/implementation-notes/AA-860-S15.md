# AA-860 — X1 S15 Infra: two read-only run-scripts (connection snapshot, photo itinerary parity)

Branch `feat/x1-s15-scripts`. Companion of AA-CIS-App `feat/x1-s15-cis-runtime-prep` (photo sync on `geo`,
connection-site inventory in that repo's `docs/implementation-notes/AA-860-S15.md`). No apply, no AWS change,
no new env var.

## Decisions
- Both scripts declare `READ_ONLY = True` (session `default_transaction_read_only = on`, idle check report-only),
  print `SCRIPT …` aggregate lines only and return nothing (exit 0).
- `x1_connection_snapshot.py`: `pg_stat_activity` client backends of the whole instance (every database: the
  role limits and `max_connections` are instance-wide), grouped by `usename`, `application_name`
  (`<empty>` = the ad-hoc `asyncpg.connect()` calls that set none) and `state`; then every login role (not
  `rds*`) with its sessions, `rolconnlimit` and percentage; `max_connections`, `superuser_reserved_connections`
  and the UTC time. No query text, no client address. One snapshot per dispatch (README time-limit rule).
- `x1_photo_itinerary_parity.py`: the OLD query is the pre-S15 `itinerary_places` SQL verbatim; the NEW one is
  the S15 SQL with the liveness rule of `services/places/store.py` `_LIVE_SQL` copied (scripts import no app
  code), both without the country filter so one run covers every country. Pairs are compared on
  `(tour_id text, destination_id)` per `shared.destinations.country`; the master tenant GUC is pinned inside
  the script's own transaction like the app does. The master reads `tripplanner.*` through its `tp_owner`
  membership (rl-001).

## Changed (vs the lane plan)
- Nothing material. Lines are `SCRIPT sessions …`, `SCRIPT role …`, `SCRIPT parity …` / `parity_total …`.

## Tradeoffs
- The snapshot is a point sample, not a minute-by-minute series: plan XD6's "every minute across one busy
  wave" became 2–3 dispatches (the run-script ceiling is 30 minutes and a script must not loop), plus the
  CloudWatch `AA/RDS RoleConnections` series that already exists for the limited roles. The master has no
  role metric; the snapshot is the only per-`application_name` view of its sessions.
- `old_only > 0` is expected for countries the CIS place pipeline has not processed; the session log explains
  each non-zero country (S15c).
