# AA-860 — X1 step S20: role bootstrap `rl-002` (`cis_owner`, `db_migrator`)

Plan: `AA-Ecosys/docs/audits/2026-10-17-S241-x1/x1-plan.md` §5 S20 (Wave 5), with §1.4, XD2, XD4, XD8, XD9,
review A1/A10/B10/C2/C3 and the S242/S243 amendments. One `roles/` file (key `rl-002`), one Terraform alarm row,
static tests. Applied after merge by DB Migrate `apply` (`roles/002_x1_cis_owner_db_migrator.sql`, runs as the
master) and a Terraform Apply (alarm only).

## Decisions
- **Same shape as rl-001.** Session guard (`session_user = 'aa_cis_admin'`), `CREATE ROLE` inside a guarded `DO`
  (idempotent), then `ALTER ROLE … NOLOGIN` / `LOGIN CONNECTION LIMIT 5` restated; the other attributes are
  guarded, not restated (PostgreSQL 15: a non-superuser CREATEROLE role cannot name SUPERUSER / REPLICATION /
  BYPASSRLS in `ALTER ROLE`).
- **`db_migrator` attributes:** `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS CONNECTION LIMIT 5`, default
  INHERIT (review A1: NOINHERIT would cut `pg_read_all_stats` and the owner roles' catalog visibility the schema
  dump needs). The plan line names only `NOCREATEROLE NOBYPASSRLS`; the extra `NOSUPERUSER NOCREATEDB` match
  `cis_app` and the probe's attribute rule (review C5).
- **`GRANT CREATE ON DATABASE aa_cis_dev` with the name written out** (plan text, reviewable, statically tested),
  plus a guard that `current_database() = 'aa_cis_dev'` so a run anywhere else fails with a clear message. A
  `current_database()` + `EXECUTE format()` variant was rejected: the static tests cannot see a grant inside a
  string, and `owners.yaml` lists only `dev`.
- **Guards (all RAISE):** `cis_owner` NOLOGIN, no elevated attribute, member of nothing, CREATE on the database,
  master a member; `db_migrator` LOGIN + INHERIT + limit 5, no elevated attribute, **direct memberships exactly**
  `owners.yaml` `migrator_member_of` (literal array, sorted `COLLATE "C"`, distinct: PostgreSQL 16 can hold
  several rows per pair), each one with USAGE (inherited), and never (even through a chain) `aa_app_user`,
  `aa_cis_admin`, `rds_superuser`, `pg_read_all_data`, `pg_write_all_data`; members of `cis_owner` only the master
  and `db_migrator`, of `db_migrator` only the master (PG 16+ records the creator there; PG 15 nothing); the
  master still not a member of `aa_app_user` / `catalog_owner` (§1.4, restated from rl-001).
- **Probe cron already staggered** (`db-schema-dump.yml` 03:43 UTC, `db-isolation-probe.yml` 04:13 UTC, since S2):
  no workflow change.
- **No `owners.yaml` change.** `migrator_role`, `migrator_member_of`, `password_roles.db_migrator`,
  `owner_role: cis_owner` were written in S1/S3; `owner_role_today` and the "DB Migrate login" text change in
  S21/S22, not here. The isolation probe already keys `owner_role.cis_owner` and
  `sessions.db_migrator_below_limit` on `rl-002`.

## Tradeoffs
- **Alarm at limit 5:** the 80 % threshold means it fires only at 5/5 sessions, and a 5-minute sample rarely sees
  a short DB Migrate task. Kept for parity with every other limited role and because it costs ~$0.10; the hard
  signal is the probe's `sessions.db_migrator_below_limit` cell and the workflow failing on SQLSTATE 53300.
- **Guard on direct memberships equal to a literal list** instead of "contains": a stray extra grant (e.g. someone
  adding `aa_app_user`) fails the file. Cost: none later — once applied the file never re-runs; adding a role
  to `migrator_member_of` is a new `roles/` file, and the static test compares the registry with the union of
  all files' grants.
- **Undo drops `db_migrator` with `DROP ROLE` only, not `DROP OWNED BY`:** on PG 15 `DROP OWNED BY db_migrator`
  needs the master to have its privileges, i.e. a temporary membership that would also make the master a member
  of `catalog_owner` for the transaction (§1.4). X1 grants `db_migrator` memberships only (no pg_shdepend row), so
  the undo refuses if it ever holds a privilege and says what to revoke.

## Should know
- **Dry run on PostgreSQL 16 (local, throwaway cluster), not 15.** Master simulated as `aa_cis_admin NOSUPERUSER
  CREATEROLE CREATEDB`, owner of `aa_cis_dev`; rl-001's end state created by the superuser. PG 16 needs ADMIN on a
  role to grant it and counts that ADMIN grant as MEMBER, so the master had ADMIN (INHERIT FALSE, SET FALSE) on
  `catalog_owner` and the file's last guard ("master not a member of catalog_owner") fired on the unmodified file —
  every earlier guard passed. With only that one check replaced by `false` (PG 16 artifact): rl-002 applied, re-ran
  idempotently, produced the intended rows (`db_migrator` member of the six roles, INHERIT; `cis_owner` CREATE on the
  database; master member of `cis_owner`); four mutations each tripped their guard (`cis_owner` in `catalog_owner`;
  `db_migrator` in `aa_app_user`; `db_migrator CREATEDB`; `booking` in `cis_owner`). On RDS 15 the master grants
  under CREATEROLE without ADMIN, so the check holds as written.
- **RDS major upgrade to 16+:** the master would need ADMIN on `catalog_owner` to grant it (a new rl- file after
  the upgrade), which makes it a member and breaks §1.4. Revisit before any engine upgrade (the grant is already
  in place by then; only a re-grant would hit it).
- **`db_migrator` is a member of `cis_app`**, whose policies since CIS 244 are `USING (true)` on all 16 RLS tables
  (S243 amendment, FORCE ones included, not only the ENABLE-only ones the plan's S20 text mentions). Effect: as
  `db_migrator` (no `SET ROLE`) every RLS table reads unfiltered — same as the master today, and its results are
  never tenant evidence (probe header). Files run under `SET ROLE cis_owner` do not get this (cis_owner is not a
  member of cis_app): that is S21's design point.
- **Order on Dev:** merge → DB Migrate `check` then `apply` `roles/002_x1_cis_owner_db_migrator.sql` (idle check
  as for any apply) → Terraform Apply (alarm only; no ECS/Lambda change, no idle gate) → secret value + DB Migrate
  `set-password role=db_migrator` (expect `current_user=db_migrator rolconnlimit=5`) → probe. Until S22 nothing
  logs in as `db_migrator` except the set-password test login; DB Migrate keeps the master.
- **Secret `aa-cis/dev/db-migrator`:** exists (Terraform, S11), no value yet (`describe-secret`: no versions,
  19/10/2026). The migrator task role can read it (`local.db_migrate_task_secret_arns`); the CIS task role is denied
  (S19).
