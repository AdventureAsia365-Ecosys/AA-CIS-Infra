# AA-933 — CRM-05 AA-Partner runtime on Dev (lane aa933-partner-skeleton, S248)

Source: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §6.3 card CRM-05; root ADR 0010 decisions 1-3;
ADR 0004 / 0004b (ECS service, own security group); the AA-932 handoff (task role name, heartbeat kind, DSN secret,
connection budget row). App side: AdventureAsia365-Ecosys/AA-Partner (`CONTEXT.md`, `docs/implementation-notes/AA-933.md`).

## Decisions

- **One self-contained file `accounts/aa365/crm_app.tf`** (Booking pattern, `booking.tf`): ECR, log group, Sentry
  secret shell, execution + task roles, task definition, target group, one ALB listener rule, ECS service, GitHub OIDC
  deploy role, three service alarms. Only the security group (`app_security_groups.tf`, joins the list RDS admits) and
  the job backlog alarms (`observability_ecosys.tf` `job_backlog_owners`) live elsewhere.
- **Names follow the CRM naming contract of `cicd_crm.tf`** (`aa-crm-<env>-*`, tag `App = crm`): ECR
  `aa-crm-dev-api`, service and family `aa-crm-dev-api`, roles `aa-crm-dev-ecs-execution-role`,
  `aa-crm-dev-ecs-task-role` (the exact name the AA-932 key policies trust, `local.crm_task_role_name`),
  `aa-crm-dev-app-deploy`. The CI apply role may create ECR repos only under that prefix (`CrmEcrRepoManage`).
- **Task role holds no KMS / S3 / SES grant yet**: ECS Exec channel, exec session logs, `PutMetricData` into
  `AA/Jobs/Crm` only. The cards that use keys, buckets and mail add their statements (CRM-06, CRM-12, CRM-17).
- **ALB rule `crm_api` at priority 5**, above the AA-931 spike rule (10) and the origin deny (20): host = partner host,
  `X-AA-Origin` = the CloudFront secret, path `/crm` or `/crm/*`. Every other path of the host still reaches the spike
  until the CRM web (AA-935) takes the host's default. `alb_rule_order.py --source` passes (R3: exact-origin rule with
  a host condition above the deny). API Gateway traffic carries no origin header, so `/crm/*` is unreachable from
  `api-cis.` / `api-booking.`.
- **Service desired 0 at create**, `ignore_changes = [desired_count, task_definition]`; the first image comes from the
  AA-Partner Deploy Dev workflow (placeholder tag `bootstrap` is never pushed). FARGATE base 1, Spot for extras, ARM64.
  Without the edge (`crm_edge_on = 0`) the service has no load balancer block (ECS refuses an unattached target group).
- **Identity env from Terraform only** (public app repo, DM-6.10): WORKFORCE issuer + `cis-admin` / `breakglass`
  client ids, EXTERNAL issuer + `cis-portal` (Dev bridge until AA-939). PARTNER pool and `crm-staff` client do not
  exist yet: empty = the class accepts nothing.
- **OIDC deploy role trusts only the immutable subject** `repo:AdventureAsia365-Ecosys@276539096/AA-Partner@<id>:`
  with the single context `environment:dev` (`crm_github_repo_id = 1430388300`, read with
  `gh api repos/AdventureAsia365-Ecosys/AA-Partner --jq .id`; the repo already uses the immutable subject).
  Review round: `ref:refs/heads/main` was dropped (booking.tf still has it). Every deploy job runs with
  `environment: dev`, and a ref subject would let a future job on main without an environment bypass the
  environment's branch policy. Order constraint: the AA-Partner `dev` environment (deployment branches: main only)
  is created **before** this role is applied, else a branch job naming `environment: dev` would auto-create an
  unprotected environment that matches the subject.
- **Connection budget**: the AA-932 `fixed: 2` row is replaced by the service's `deployment_maximum_percent` (200 x
  0.01 = 2 processes) and the pool source `AA-Partner api/app/db.py` (`max_size=3`), so a pool or overlap change fails
  `check_connection_budget.py --verify-sources`. Totals unchanged (crm_app 6 / 6, total 168 under the accepted overage).

## Changed (vs the card / brief)

- The brief named `/partner/health`; the app serves `/crm/health` and `/crm/health/ready` (the design's single `/crm`
  prefix, the only path this ALB rule forwards). Target-group and container health checks use `/crm/health`.
- The brief named ECR `aa-partner-*`: the CI apply grants and the KMS key policies already fix `aa-crm-*`.

## Tradeoffs

- **`jobs-sampling-stopped` for crm fires while the service sits at desired 0** (missing data = breaching, same as
  Booking). One ALARM e-mail after the apply, OK once the first task samples. Accepted rather than a per-owner switch.
- **CPU alarm without the edge gate**: it reads the ECS service metric, quiet at desired 0 (missing data not breaching).

## Should know

  `main`), then this PR, then the apply, then the copies PR (`crm-001` + `crm-002`), DB Migrate, the crm_app password,
  and only then the first deploy + `desired-count 1`.

  with one ARM64 0.25 vCPU / 0.5 GB task around the clock.
