# AA-1046 R4b part 1: isolation probe off the Booking B2C objects (S271)

Root plan: AA-Ecosys `docs/audits/2026-11-05-S270-aa1037-b2c-drop-dryrun/README.md` section 4. Booking bk-045
(destructive) drops `booking.customers` and the view `booking.v_ops_inquiry_inbox` (bk-035).

## Decisions

- **Cross-app cells read `booking.trip_cases`** instead of `booking.customers`: a read of a missing table raises
  42P01, not 42501, so every cross-app cell on `booking.customers` would FAIL right after the drop. `trip_cases` is
  kept, holds traveller data of the kept b2c cases, and is granted to role `booking` only (schema reference), so the
  same five roles (`tripplanner`, `aa_app_user`, `cis_app`, CIS runtime, `crm_app`) still get 42501.
- **Consumer grant cell `bk-035` removed** (probe + `owners.yaml`): after the drop the view is absent while bk-035 is
  registered, which the probe reports as a missing contract grant. Removing the cell before the drop is safe: the
  probe checks expected grants only, it does not flag an extra one.

## Changed

- `db/README.md` cell list; `db/tests/test_isolation_probe.py` (cell names, key tuple, a guard that no cross-app
  cell names `booking.customers`).
- Not changed: `db/rls_catalogue_rules.py` keeps `booking.v_ops_inquiry_inbox:cis_app` (byte copy of the CIS file;
  a stale allowlist entry is reported, not fatal). Remove it in both repos after the drop.
- Not changed: the old one-off `db/scripts/aa682_*_live_check.py` and `dm65_consent_capture.py` name the dropped
  tables; they are history (run once, never scheduled) and would fail cleanly on a missing table.

## Tradeoffs

- Moving the cell target rather than deleting the cells keeps the X1 S2 isolation guarantee for every role.
