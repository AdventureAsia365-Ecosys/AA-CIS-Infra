# AA-272 — VPC Link V1 + NLB (account 2 only)

## Decisions
- NLB, its SG, target group, attachment, listener, and the `aws_api_gateway_vpc_link`
  all live in `modules/alb/vpc_link.tf` (new file, same module as the ALB) — per
  spec, since the module already owns `aws_lb.main` and the VPC Link's only job
  is to front that same ALB.
- Target group attachment (`target_id`) references `aws_lb.main.arn` directly
  instead of the literal ALB ARN string given in the ticket — same module, so
  the resource reference is authoritative and avoids drift if the ALB is ever
  recreated. Verified it resolves to the same ARN
  (`arn:aws:elasticloadbalancing:us-west-1:005097885195:loadbalancer/app/aa-cis-dev-alb/736e3d6857cade37`).
- NLB subnets wired via `var.private_subnet_ids` (new module input, sourced from
  `module.vpc.private_subnet_ids` in `accounts/aa365/main.tf`) rather than the
  two hardcoded subnet IDs in the ticket — those IDs are exactly what that
  output already returns, and using the output avoids a second hardcoded copy.
- New SG ingress CIDR wired via `var.vpc_cidr_block` (new module input, sourced
  from the existing root `var.vpc_cidr`, default `10.2.0.0/16`) instead of a
  hardcoded literal — same reasoning.
- `alb_dns_name` variable in `modules/api_gateway` is kept (not deleted) even
  though after this change no `aws_api_gateway_integration.uri` in that module
  references it anymore — `accounts/aa365/main.tf` still assigns it in the
  `module "api_gateway"` call and grep showed no reason to break that wiring.
  Per explicit instruction: don't delete if still referenced elsewhere.

## Changed
- `modules/alb/variables.tf`: +`private_subnet_ids`, +`vpc_cidr_block`.
- `modules/alb/vpc_link.tf` (new): `aws_security_group.nlb` (ingress tcp/80 from
  `var.vpc_cidr_block`, egress all), `aws_lb.vpc_link_nlb` (internal network LB,
  `var.private_subnet_ids`), `aws_lb_target_group.vpc_link_nlb` (target_type=alb,
  TCP/80, TCP health check), `aws_lb_target_group_attachment.vpc_link_nlb_to_alb`
  (target_id = `aws_lb.main.arn`, port 80), `aws_lb_listener.vpc_link_nlb`
  (TCP/80 → the above TG), `aws_api_gateway_vpc_link.this` (target_arns =
  [`aws_lb.vpc_link_nlb.arn`]).
- `modules/alb/outputs.tf`: +`nlb_dns_name`, +`vpc_link_id`.
- `modules/api_gateway/variables.tf`: +`nlb_dns_name`, +`vpc_link_id` (both
  required, no default — every environment wiring this module must supply them).
- `modules/api_gateway/main.tf`: all 8 `aws_api_gateway_integration` resources
  (`root`, `health`, `auth`, `admin`, `content`, `docs`, `openapi`, `v1`) gained
  `connection_type = "VPC_LINK"` + `connection_id = var.vpc_link_id`, and their
  `uri` domain changed from `var.alb_dns_name` to `var.nlb_dns_name` (path/proxy
  suffix unchanged). This covers every route, not just `/v1/*`.
- `accounts/aa365/main.tf`: `module "alb"` call gained `private_subnet_ids =
  module.vpc.private_subnet_ids`, `vpc_cidr_block = var.vpc_cidr`. `module
  "api_gateway"` call gained `nlb_dns_name = module.alb.nlb_dns_name`,
  `vpc_link_id = module.alb.vpc_link_id`; existing `alb_dns_name` assignment
  left untouched.

## Tradeoffs
- Ran `terraform fmt -recursive` once, which reformatted whitespace across the
  whole repo — including account-1's root `main.tf`, `envs/dev/terraform.tfvars`,
  and unrelated modules (`ecs`, `lambda`, `monitoring`, `rds`, `step_functions`,
  `waf`, `eventbridge`). Caught via `git status` before validate/plan and
  reverted everything outside the AA-272 file set with `git checkout --`.
  Lesson: use `terraform fmt -diff <explicit file list>` for scoped changes in
  this repo, not `-recursive`, since account 1 and account 2 share top-level
  `modules/`.
- Did not add a `vpc_id` input to the NLB target group separately — reused the
  module's existing `var.vpc_id` (same VPC the ALB is already in), no new
  variable needed there.

## Should know
- Scope explicitly excludes tightening `sg-05b3f6475701b468d` (ALB SG, currently
  0.0.0.0/0 on 80/443) — that's Phase C, done after VPC Link is verified working.
- V1 VPC Link (`aws_api_gateway_vpc_link`), not v2 — provider doesn't support
  v2 VPC Link direct-to-ALB (hashicorp/terraform-provider-aws#45230, open).
- `terraform fmt` (scoped) and `terraform validate` (from `accounts/aa365/`)
  both pass clean.
- `terraform plan` in this task must show ADD-only for new resources + MODIFY
  on existing `aws_api_gateway_integration.*` (connection_type/connection_id/uri).
  Any unexpected DESTROY stops the task for review — no auto-fix.
