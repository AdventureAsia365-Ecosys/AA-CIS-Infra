# AA-947 (CRM-19) — BOOKING_API_URL on the CRM task and the crm_booking_sync idle exemption

Infra slice of AA-947 (CRM-19 B2B client + AA lines, AA-Partner `feat/aa-947-b2b-client`). The CRM calls
`booking.b2b.v1` (quotes, holds, confirms, the `/events` feed) from its `crm_booking_sync` job and the AA product
look-up. The migration copy (crm-017) is the separate branch `chore/aa-947-crm017-copy`. Session S251, agent Claude
Code.

## Decisions

- **`BOOKING_API_URL` from a variable** `crm_booking_api_url` (default `https://api-booking.lumiguides.it.com`, the
  live Booking REST API custom domain), the same shape as AA-978's `crm_cis_api_url`: a validation keeps it empty or
  an https origin without a path or trailing slash (the app appends `/booking/b2b/v1`). Empty = the app keeps AA
  requests pending (the outage queue), it does not crash.
- **No routing change.** The Booking REST API is a greedy proxy (`ANY /booking`, `ANY /booking/{proxy+}`,
  `booking.tf`), so `/booking/b2b/v1/...` already reaches the Booking task (AA-972 serves it). Unlike CIS (AA-978
  had to add `/tenant/membership`), nothing is added at the gateway.
- **No Cognito, IAM or secret change.** The CRM M2M client already holds the four `booking.b2b/*` scopes and
  `cis.catalog/read` (`identity_m2m.tf`); the task already reads the `M2M_CLIENT` secret (AA-978). Booking already
  trusts the CRM client (`COGNITO_M2M_CRM_CLIENT_ID`, AA-972).
- **`crm_booking_sync` is idle-exempt** (`db/owners.yaml` `idle_exempt_kinds`, `run_migration.py`
  `IDLE_EXEMPT_KINDS["crm"]`, README, test): it is re-queued every 60 s with a key per slot (AA-Partner
  `app/jobs/kinds.py` `DEPLOY_GATE_EXEMPT`), like `crm_membership_pull`; each request / event is its own short
  transaction. Without the exemption every DB Migrate apply would wait on its queued-ahead slot. `crm_catalog_sync`
  (hourly, its row exists only while due) is not exempt.

## Tradeoffs

- One branch for the env and the registry entry (AA-978 split them because another registry PR was open at the
  time). Both must land before the AA-Partner code runs, so one PR keeps the order simple.

## Should know

- **Cost per month: none.** One environment variable on an existing task definition (a new revision); no new
  resource. The extra M2M token requests (one cached token per scope, about an hour each) and the per-minute Booking
  calls (through the existing REST API, a few tens of thousands of requests a month on Dev) are inside the API
  Gateway and Cognito M2M amounts already paid for, well under 1 USD.
- **Apply order:** root registers (DM-7 rows) -> crm-017 copy + DB Migrate apply (crm-016 then crm-017) -> this branch
  (`terraform apply`: the task definition revision and the exemption) -> AA-Partner merge + deploy. The service
  ignores task definition changes (`ignore_changes`), so the app deploy picks up the new revision.
- `terraform plan` not run by the lane (MFA); `terraform fmt -check` clean, `python3 -m unittest
  db.tests.test_run_migration` 94 passed.
