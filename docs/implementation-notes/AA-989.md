# AA-989 — Infra: place pipeline auto on, dead ACP schedules removed

Source: root `docs/audits/2026-10-26-S252-propagation-audit/README.md` §5.4, §5.5, §6 items 8 and 15.

## Decisions
- `PLACE_PIPELINE_AUTO=on` on the CIS **api and worker** task definitions through a new `modules/ecs` variable
  `place_pipeline_auto` (bool, default false) and `local.place_pipeline_auto_env`, the `PLACE_SHAPES_ENABLED` /
  `SEGMENT_GC_MODE` pattern. Set `true` in `accounts/aa365/main.tf` (audit item 8, approved after the AA-905 place
  backfill finished at $4.31). Both services carry it: the automatic triggers run on the worker (end of A3 atomize,
  place-card relink) and AA-CIS-App `services/places/enqueue.py` `auto_enabled()` reads it wherever it is called.
  Accepted values there: `1/true/on/yes`; the module writes `on` / `off`.
- Removed `aws_scheduler_schedule.acp_daily_ingest`, `acp_weekly_export` and `acp_veto_window_close`
  (`modules/eventbridge/main.tf`). They put `ACP.DailyIngest` / `ACP.WeeklyExport` / `ACP.VetoWindowClose` on the ACP
  bus, and nothing consumes those: no `aws_cloudwatch_event_rule` targets the ACP bus anywhere in this repo (every rule
  in `accounts/aa365` is on the default bus for CloudTrail alerts), AA-492 measured 0 rules / 0 targets on the bus, and
  AA-CIS-App has no handler for those detail types (its `acp_shared/event_constants.py` lists only `acp.*` stage
  events). The pipeline is job-driven (`shared.job` on the worker).
- Kept: the bus, the DLQ and its alarm, the schedule group (the `dfs_balance` / `retention` / `photo_sync` /
  `booking_uptime` / `rds_snapshot_expiry` schedules in `accounts/aa365` live in it), and the module's scheduler role
  (now unused by any schedule; removing it is a separate IAM change, not worth the bootstrap churn).

## Changed
- `accounts/aa365/cicd.tf`: comment only (the scheduler statement's `/*` still covers the group's other schedules).
- The gate on set-active / restore (audit §5.4) is not needed: with auto on, every trigger is allowed.

## Tradeoffs
- Auto on costs about $0.006–0.019 per new tour (S252 re-sync and 30-day stage costs); off would leave every new tour
  without places in TripPlanner.
