# AA-828 — Per-app budgets on the `App` cost allocation tag (S238)

Repo/files: `accounts/aa365/observability.tf`, `accounts/aa365/variables.tf`

## Decisions

- One `aws_budgets_budget.per_app_monthly` with `for_each` over
  `var.per_app_monthly_budgets` (map of App tag value -> USD). Budget names:
  `aa-cis-dev-monthly-app-<app>` (same `local.name_prefix` as the existing
  `aa-cis-dev-monthly-total`).
- Filter: `cost_filter { name = "TagKeyValue", values = ["user:App$<app>"] }`.
  Built with `format("user:App$%s", each.key)` — in an HCL string `$${` is an
  escape, so `"user:App$${each.key}"` would produce the literal text
  `user:App${each.key}`.
- Tag values come from the code, not assumed: `local.bk_tags` (`booking`),
  `local.tp_tags` (`tripplanner`), `local.ecosys_tags` overrides (`cis`,
  `shared`, `booking`, `tripplanner`). Provider `default_tags` (versions.tf)
  carry no `App` key.
- Notifications: 80 % ACTUAL + 100 % FORECASTED, e-mail to `var.alert_email`
  (same subscriber as the total budget). The total budget keeps its own
  80 %/100 % ACTUAL pair unchanged.
- Default amounts (variable comment explains them): cis 150, tripplanner 25,
  booking 25 = 200 of the 250 total, leaving ~50 for shared/untagged spend.
- Validation on the variable: keys must be one of the DM-10.1 App values
  (`cis`, `tripplanner`, `booking`, `crm`, `shared`), amounts > 0.
- Budgets themselves are tagged `ecosys_tags + App + Issue` (CI role already has
  `budgets:TagResource`, AA-287).

## Changed

- Scope addition from the S238 comment: replaced the stale AA-360 "Bedrock
  daily cost" note with the actual decision (ledger in `shared/cost_guard.py` +
  `shared.spend_budget`, alerts to `shared.notifications`, Cost Operations UI,

  acc2 tags). Removed both `AA-364` week_run blocks. The AA-287 "no
  cost-allocation tags" note now points at the per-App budgets.
- Not done here (issue scope bullet 1): adding `App` tags to RDS, snapshots,
  the S3 archive bucket, the CIS log groups, and flipping `default_tags`.
  Re-tagging everything built from `local.common_tags` hits the CI role's

  own targeted plan.

## Tradeoffs

- The `cis` budget reads close to $0 until CIS resources carry `App = "cis"`
  (today only the REST API execution log group does). Built anyway because the
  tag is now active and the budget starts working the day tagging lands; the
  comment says so, so nobody trusts a $0.
- No "shared"/untagged budget: shared infra is not tagged `App = "shared"` yet
  (RDS lives in `modules/rds` with `common_tags`). A `shared` key is a one-line
  addition once it is. An untagged budget (`user:App$` with an empty value)
  was considered but not built: the semantics should be checked in the console
  first.
- FORECASTED alerts need some spend history; for a tag activated today AWS may
  not forecast for the first weeks. The 80 % ACTUAL alert still works.
