# AA-896 (S255) — budget refresh on acc2, IMMEDIATE anomaly alerts on acc3

Session S255 (28/10/2026), Claude Code Infra lane. Branch `feat/aa-896-budgets-acc3-anomaly`.
Source: root audit `docs/audits/2026-10-28-S255-finops-security/` (decisions D1, D2) and its `tf/` drafts.

## Decisions

- **Account budget 250 -> 300 USD, now a variable** (`var.total_monthly_budget_usd`). acc2 ran at ~8.6 USD/day on
  20-27/10 (~261 USD/month) after the CRM api/web/portal services and the identity WAF; AA-873 adds ~18 USD/month.
  At 250 the budget would breach every month from November.
- **FORECASTED 100 % on the account budget.** It had ACTUAL 80 % / 100 % only, so an overrun was e-mailed after it
  happened. The per-App budgets already had FORECASTED 100 %.
- **Per-App: shared 100 -> 120, crm 25 -> 35, new identity 10**; cis 90, booking 25, tripplanner 10 unchanged. Sum
  290 <= 300. `identity` joins the validation list: identity.tf tags the Cognito pools, WAF web ACL and secrets with
  `App = "identity"`, which no per-App budget covered.
- **Precondition: sum of per-App budgets <= account budget**, on `aws_budgets_budget.total_monthly`. Cheap guard
  against a later bump of one App that silently exceeds the total.
- **acc3: own SNS topic `aa3-cost-alerts` + IMMEDIATE subscription (>= 15 USD)** in a new file
  `accounts/acc3-bedrock/cost_anomaly_immediate.tf`. IMMEDIATE needs an SNS subscriber in the same account. The
  topic policy is the AWS default statement plus `costalerts.amazonaws.com` limited to `aws:SourceAccount` = acc3
  (the draft also allowed `budgets.amazonaws.com`; dropped: no budget publishes to this topic).
- **The acc3 budget keeps its direct e-mail** (not repointed to the topic): pointing it at both would send two mails.
- **No App-tag anomaly monitor.** AWS creates cost-allocation-tag monitors only in the management account; acc2 is a
  member of the TrueIDC payer. Recorded in CONTEXT.md instead of a commented block in code.

## Tradeoffs

- 15 USD IMMEDIATE on acc3: a wave day is 20-36 USD, so the first wave days after apply may alert. That is the point
  (catch a runaway wave within hours); raise the variable if it is noise, do not remove it.
- shared at 120 leaves ~20 % headroom over the run-rate; it will still FORECAST-alert if the NLB/ALB or RDS grows.
