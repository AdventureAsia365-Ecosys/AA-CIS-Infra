# AA-807 — Data phase 1 foundation

## Slice 1 (S237): Migration Copy Guard

CI check that every DB Migrate copy in `db/migrations/<owner>/` is byte-identical to the same file
on the owner repo's `main`. The other AA-807 slices (per-app owner roles, nightly schema-drift
job, Dead Table Registry, `shared.countries`) are not in this slice.

### Decisions
- **Stdlib-only Python script** (`db/check_migration_copies.py`) plus a thin workflow
  (`.github/workflows/migration-copy-guard.yml`). No install step, no AWS, no secret. The logic
  lives in the script so it can be unit-tested and run locally.
- **GitHub contents API** (`Accept: application/vnd.github.raw`), not `raw.githubusercontent.com`.
  The raw CDN caches for about 5 minutes, so a copy PR opened right after the owner merge could
  fail on stale content. The API reads `main` directly.
- **Auth:** `GITHUB_TOKEN` (the workflow's `github.token`) is sent when set, only to lift the rate
  limit. If GitHub answers 401/403 for that token, the call retries anonymously, because the app
  repos (AA-CIS-App, AA-TripPlanner-Web, AA-Booking) are public. A 404 means "not on main".
- **GitHub errors are a per-file FAIL, not a crash** (review fix). Rate limits (401/403/429 after
  the anonymous retry), 5xx and network errors are retried 3 rounds with a short backoff, then the
  file is reported as `cannot compare with … : could not read … from GitHub` and the run goes on to
  the next file. Locally, `GH_TOKEN=$(gh auth token)` lifts the 60/hour anonymous limit.
- **Owner map** in the script mirrors `docs/database/schema-ownership.md` rule 4:
  `cis` → AA-CIS-App `api/migrations/`, key `NNN`; `tripplanner` → AA-TripPlanner-Web
  `migrations/`, key `tp-NNN`; `booking` → AA-Booking `migrations/`, key `bk-NNN`.
- **Prefix check** reads the version keys inside the file's `INSERT INTO shared.schema_versions`
  statements (the first value of each VALUES row), not any quoted number in the file. The file's
  own key (prefix + the filename's NNN) must be among them, and every key must have the owner's
  prefix. TripPlanner `007` registers `tp-001`…`tp-007`, which is allowed.
- **Path rule** = the regex `db-migrate.yml` already uses at dispatch
  (`<cis|tripplanner|booking>/NNN_lowercase_name.sql`), so a file DB Migrate would refuse fails
  at PR time instead.
- **Which files:** on `pull_request`, the files the PR adds/changes/renames under
  `db/migrations/` (`git diff --diff-filter=ACMR base...HEAD`). Deleted files are skipped. On the
  nightly schedule, on manual dispatch, and on a PR that only touches the guard itself, every copy
  is checked, so an owner editing an already-copied file on its main also shows up.

### Changed
- Spec said "fetch with raw.githubusercontent or gh api": used the REST contents API through
  `urllib` (same endpoint `gh api` uses), for the cache reason above.
- Added `__pycache__/` to `.gitignore` (test runs create it next to `db/`). The already-tracked
  `db/__pycache__/run_migration.cpython-313.pyc` is left alone.
- README, `db/README.md` and `CONTEXT.md` describe the D8 order: migration-only PR on the owner's
  main, then the Infra copy, then DB Migrate check/apply, then the code PR.

### Tradeoffs
- **Compare against owner `main`, not the owner PR head.** This forces the owner's
  migration-only PR to merge first (S237 D8). The alternative (compare with an open PR head)
  would let a copy land for a file that might still change in review.
- **Nightly `--all` makes ~23 API calls a night.** That is well under the token limit. A
  scheduled failure emails whoever last changed the cron line. Nothing posts to Slack.
- The version-key parser is a regex, not an SQL parser. Unusual shapes (a key built with `format()`
  or a `SELECT` instead of `VALUES`) would read as "does not register its version". Every current
  copy (23 files) passes, and the fix for an odd file is to use the standard `VALUES ('key', …)`.

### Should know
- **Branch protection is human-only.** To make the check required, add "Copies match owner main"
  to the AA-CIS-Infra `main` protection. The workflow has a `paths:` filter, so a required
  check would wait forever on PRs that touch no migration. If it becomes required, drop the
  filter first: a PR with no copies then checks every copy, which takes seconds.
- **Prove it live** (Done-when): the workflow runs only once it is on a PR branch / main
  (lesson: a CI workflow must run for real once before Done). Record two run URLs on AA-807: a
  green run on a correct copy (CIS 228 from AA-712, or this PR's own `--all` run) and a red run
  on a throwaway commit with one changed byte.
- Local results (14/10/2026): `python3 db/check_migration_copies.py --all` → 23 files, 0 failed
  against GitHub main. With a trailing space appended to `cis/226`, the run fails with

  "not found on … AA-Booking@main … merge the migration-only PR in the owner repo first". Unit
