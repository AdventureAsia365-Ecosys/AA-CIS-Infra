# AA-703 — Ecosystem identity on Cognito (Phase 0 draft)

Source of truth: root ADR 0006 "Ecosystem identity" (Proposed, S236). Files:
`accounts/aa365/identity.tf`, `identity_variables.tf`, `lambda_src/identity_triggers/`,
tests in `lambda_src/identity_triggers_tests/` (`python3 -m pytest -p no:cacheprovider lambda_src/identity_triggers_tests` from `accounts/aa365`).

## Decisions
- Allow-list for WORKFORCE Google sign-in = the WORKFORCE pool itself (exactly one enabled native
  user with that email, pre-created by the staff directory), per ADR decision 5. No DynamoDB/SSM:
  triggers are outside the VPC with a 5 s limit.
- Google `hd` is enforced by default (`identity_workforce_require_hd = true`), reading `custom:hd`.
  `custom:hd` is created only when `identity_workforce_map_google_hd = true` (after the spike).
  Until one of the two is changed, Google staff sign-in is refused (fail closed).
- EXTERNAL pre sign-up identifies the app client by NAME via `DescribeUserPoolClient` (client ids in
  the Lambda env would be a Terraform cycle).
- Four functions (pre sign-up + pre token V2_0 per pool), published versions behind alias `live`.
- One shared REGIONAL WAF web ACL for both pools.

## Changed (vs ADR text)
- `PASSWORD` stays in `allowed_first_auth_factors` (Cognito requires it). `EMAIL_OTP` only once the
  SES identity variable is set (AA-811). Before that, EXTERNAL native sign-up is refused by the
  trigger (`NATIVE_SIGNUP_ENABLED=false`).
- Clients that offer a social IdP can write `email`, `email_verified`, `name` (+ `custom:hd`):
  Cognito requires write access to mapped attributes. No client has the
  `aws.cognito.signin.user.admin` scope, and native SignUp setting `email_verified`/`custom:*` is
  refused by the trigger.
- WORKFORCE link targets may be `CONFIRMED` or `FORCE_CHANGE_PASSWORD` (AdminCreateUser without a
  usable password); `UNCONFIRMED` is never accepted. EXTERNAL link targets must be `CONFIRMED`.

## Tradeoffs
- Break-glass is not technically pinned to the `breakglass` client (pure pre token trigger cannot
  know client ids); every break-glass token raises an alarm instead.
- Lambda `Errors` counts refusals too, so the Errors alarm uses a burst threshold (20 / 5 min) and
  unexpected exceptions get their own log-metric alarm.
