# AA-841 — Untrack the plaintext envs/dev tfvars, add a PR secret scan (code side, part 1)

Rotation (DataForSEO password; acc2 RDS master password only if it equals the old acc1 one) is
Nghiệp's manual step and is not in this branch.

## Decisions

- **`envs/` is dead, evidence:**
  - Both Terraform workflows run in `accounts/aa365` (`terraform-plan.yml`, `terraform-apply.yml`
    `working-directory: accounts/aa365`); `db-migrate.yml`, `db-schema-dump.yml`,
    `migration-copy-guard.yml` do not touch `envs/`. No Makefile in the repo. No `-var-file`
    usage anywhere except a historical note (AA-246, a one-off acc1 plan).
  - `envs/dev/terraform.tfvars` was the var-file of the repo-root acc1 stack, and that root
    (`main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`) was deleted in AA-587 (#43).
  - `envs/dev/main.tf` is 1 byte (a newline), so `envs/dev` has no module calls and no backend;
    its `outputs.tf` references `module.step_functions`, which no longer exists (retired in #88),
    so the root could not even plan. `envs/prod` and `envs/staging` are six 0-byte files.
  - README ("historical, not live — do not run Terraform there"), CONTEXT.md and
    `.claude/CLAUDE.md` already describe `envs/` as an inactive scaffold.
- **`accounts/aa365/terraform.tfvars` stays tracked.** Checked by variable name and value shape
  only (no values printed): `database_url`, `dataforseo_login`, `dataforseo_password` are all
  `REPLACE_ME` placeholders (DSN host included), `redis_url` is empty, `db_password` is not in the
  file (comes from `TF_VAR_db_password`). The rest is non-secret config (CIDRs, ARNs, a GitHub repo
  id, an e-mail). Its git history never added a non-placeholder value for those keys (5 added
  secret-key lines across history, 0 non-placeholder).
- **`.gitignore`:** `*.tfvars`, `*.tfvars.json` and an explicit `**/terraform.tfvars`, with only
  `*.tfvars.example` and `accounts/aa365/terraform.tfvars` re-included. The old
  `!envs/dev/terraform.tfvars` exception is gone.
- **No history rewrite.** The issue lists the purge as a decision for Nghiệp (rotation makes it
  optional); no decision comment was on the issue when this branch was cut, so nothing is
  rewritten here and the decision still has to be recorded on AA-841.

## Changed

- `git rm envs/dev/terraform.tfvars` (file deleted from the repo; its values stay in history and
  in every existing clone until rotated).
- `.gitignore` rule above.
- Separate commit: `git rm -r envs/` (whole dead scaffold, including `envs/dev/terraform.tfvars.example`,
  which only described that root; the live aa365 tfvars is its own template). CONTEXT.md, README and
  `.claude/CLAUDE.md` now say it was removed and must not be recreated. This commit can be dropped
  on its own if Nghiệp prefers to keep the example file; the first commit does not depend on it.

## Tradeoffs

- Keeping the aa365 tfvars tracked keeps CI plan/apply simple (no tfvars secret to inject); the cost
  is that one tracked tfvars remains, which the secret-scan job and the placeholder convention
  guard.

## Should know

- When the merge is pulled into the main checkout, git deletes the local
  `envs/dev/terraform.tfvars` too. Nothing reads it, so no backup is needed for Terraform.
