# AA-841 — Untrack a legacy tfvars file, add a PR secret scan (code side, part 1)

Credential follow-up for this change is tracked privately in Linear AA-873.

## Decisions

- **The legacy per-environment scaffold was dead, evidence:** both Terraform workflows run in
  `accounts/aa365` (`working-directory: accounts/aa365`), no other workflow, Makefile or `-var-file`
  call used the scaffold, and the repo-root stack it belonged to was deleted in AA-587 (#43), so it
  could not even plan. README, CONTEXT.md and `.claude/CLAUDE.md` already described it as inactive.
- **`accounts/aa365/terraform.tfvars` stays tracked.** Checked by variable name and value shape
  only (no values printed): `database_url`, `dataforseo_login`, `dataforseo_password` are all
  `REPLACE_ME` placeholders (DSN host included), `redis_url` is empty, `db_password` is not in the
  file (comes from `TF_VAR_db_password`). The rest is non-secret config (CIDRs, ARNs, a GitHub repo
  id, an e-mail). Its git history never added a non-placeholder value for those keys (5 added
  secret-key lines across history, 0 non-placeholder).
- **`.gitignore`:** `*.tfvars`, `*.tfvars.json` and an explicit `**/terraform.tfvars`, with only
  `*.tfvars.example` and `accounts/aa365/terraform.tfvars` re-included. The old per-environment
  exception is gone.
- **No history rewrite.** The issue lists the purge as a decision for Nghiệp (rotation makes it
  optional); no decision comment was on the issue when this branch was cut, so nothing is
  rewritten here and the decision still has to be recorded on AA-841.

- **Secret scan: pinned gitleaks image, not `gitleaks/gitleaks-action`.** The action needs a
  `GITLEAKS_LICENSE` secret for repos owned by an organization (AdventureAsia365-Ecosys), which
  would be a manual secret to set up. The image is pinned by version and digest
  (`ghcr.io/gitleaks/gitleaks:v8.28.0@sha256:cdbb7c95…`), runs as the runner uid so git accepts the
  checkout, no third-party action, `contents: read` only.
- **PR scope = `base.sha..head.sha`** (`gitleaks git --log-opts`): only lines the PR's commits add.
  Old history is not scanned in CI (no history rewrite), and deletions never fail the check.
  `workflow_dispatch` scans the working tree instead (`gitleaks dir`).
- **Two repo rules on top of the defaults.** The default rules miss credentials written as plain
  Terraform variable values. Added `uri-embedded-credentials` (scheme://user:password@host) and
  `terraform-plaintext-secret` (`*_password` / `*_api_key` / `*_secret_key` / `*_token` …
  `= "literal"` in .tf/.tfvars/.hcl). Key names like `secret_*_arn` do not match by design (the value
  is an ARN, not the secret).
- **Allowlists.** Rule-level: placeholders (`REPLACE_ME`, `changeme`, …), `${…}` interpolation,
  `<…>`. Global: `dist/lambdas/*.zip` and `.terraform.lock.hcl`. `.gitleaksignore` starts empty
  (comments only) for single fingerprints.

## Changed

- A legacy variables file was untracked and removed from the repo (follow-up: Linear AA-873).
- `.gitignore` rule above.
- Separate commit: removal of the whole dead legacy scaffold (the live aa365 tfvars is its own
  template). CONTEXT.md, README and `.claude/CLAUDE.md` now say it was removed and must not be
  recreated.

- New `.github/workflows/secret-scan.yml`, `.gitleaks.toml`, `.gitleaksignore`; README section
  "Secret scan" (local commands, false-positive handling).

## Tradeoffs

- Keeping the aa365 tfvars tracked keeps CI plan/apply simple (no tfvars secret to inject); the cost
  is that one tracked tfvars remains, which the secret-scan job and the placeholder convention
  guard.

- The `\$\{` interpolation allowlist is broad: a literal secret glued to an interpolation in one
  string would pass. Accepted: the alternative flagged ordinary names such as EFS `creation_token`.
- No scheduled full-history scan: it would re-report old findings on every run until a history
  purge, which is the tech lead's decision (Linear AA-873).

## Should know

- When the merge is pulled into the main checkout, git deletes the local copy of the removed
  variables file too. Nothing reads it, so no backup is needed for Terraform.
- Branch protection: to make the scan blocking, add the check `gitleaks` (workflow Secret Scan) to
  the required checks of `main` (GitHub settings, by hand).
