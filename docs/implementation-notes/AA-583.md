# AA-583 — API Gateway: add missing `/redoc` + `/docs/oauth2-redirect` resources

Real `terraform apply` run, per this task's explicit authorization ("Terraform plan/apply thật,
không chỉ code").

## Decisions

- **Cloned the existing `/docs`/`/openapi.json` block exactly** (`modules/api_gateway/main.tf`)
  — `aws_api_gateway_resource` + `aws_api_gateway_method` (GET, `authorization = "NONE"`) +
  `aws_api_gateway_integration` (`HTTP_PROXY`, same VPC Link, `uri` pointed at the matching
  FastAPI path on the NLB). No new pattern introduced.
- **`/docs/oauth2-redirect` nested under the existing `docs` resource** (`parent_id =
  aws_api_gateway_resource.docs.id`, `path_part = "oauth2-redirect"`), not a second top-level
  resource — matches the real FastAPI URL shape (`/docs/oauth2-redirect` is a child path of
  `/docs`, confirmed by the app returning `Invalid admin secret` — same gate as `/docs` itself —
  once reachable).
- **Added both new integrations' `.uri` to the deployment's `triggers` hash** (and to its
  `depends_on`) — this is the exact AA-432/AA-465 lesson already documented inline in this file:
  a new resource/integration existing in the config does not by itself force the `dev` stage to
  redeploy. Confirmed via `terraform plan` showing `aws_api_gateway_deployment.this` as `must be
  replaced` (trigger hash changed) before applying — if that line had been absent, this would
  have repeated the AA-432 bug on a new pair of routes.

## Changed

- `modules/api_gateway/main.tf` — 2 new resource/method/integration triples (`redoc`,
  `docs_oauth2_redirect`), plus their `.uri` added to the deployment's `depends_on` and
  `triggers.redeployment` hash. Nothing else touched.

## Tradeoffs

- None of real weight — this mirrors an existing, already-reviewed block 1:1. The only judgment
  call was where to nest `/docs/oauth2-redirect` (under `docs`, not top-level), justified above.
