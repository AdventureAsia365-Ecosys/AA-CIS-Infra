# AA-1134 — Docs-audit code follow-ups (AA-CIS-Infra part, slice C)

Lane l5-docs-audit-fixes, S285. The S283 docs audit (root `docs/audits/2026-11-17-S283-docs-audit/README.md`
section 4.1) found places where the docs are right and the code is wrong. This PR holds the Infra items 2, 9, 10 and
16, plus the re-sync of the vendored docs tools (item 5).

## Decisions

- **No idle exemption for booking.job (item 2).** `IDLE_EXEMPT_KINDS["booking"]` and `owners.yaml`
  `idle_exempt_kinds` are empty. The only entry was the B2C intake pull `bk_inquiry_pull`, retired by AA-1046 (no
  handler, no schedule; the Booking worker cancels a leftover row, `app.b2c.RETIRED_KINDS`). Booking drops it from its
  deploy-gate exempt list in the same wave. Consequence: a leftover queued/running row would now make DB Migrate
  `apply`, Infra Migration Apply and the Terraform Apply idle gate wait. Live check before merge (below).
- **cis-portal removed (item 10).** Every repo was searched for the client name and its callback paths. The app repos
  only mention it in comments or in tests that mint a token every class must refuse (AA-Partner `tests/tokens.py`);
  no runtime reads its id or secret (AA-Partner retired `COGNITO_CIS_PORTAL_CLIENT_ID` at AA-979 P2b). Inside Infra
  its references were its own wiring: the client map entry, its callback URLs, the module input
  `cognito_external_cis_portal_client_id` used only by the `crm_partner_signin_enabled = false` branch of
  `crm_web_client_id` (that value is refused by the variable's validation since P2b), and the EXTERNAL trigger's
  `PORTAL_CLIENT_NAMES`. All removed; `crm_web_client_id` is now the partner-web client id outright.
  `PORTAL_CLIENT_NAMES` becomes empty: the trigger keeps its fail-closed rule (a sign-up on any non-traveller client
  is refused), so nothing new is allowed. The managed login style of the client goes with it (the branding resource
  iterates the external clients). Users of the EXTERNAL pool are not touched (a client holds no users).
- **web-secret defaults to the partner pool (item 9).** `--pool` has no global default any more: `web-secret` uses the
  partner pool, every other pool command keeps the external default of AA-935. `web-secret --pool external` is
  refused (that pool has no CRM web client now).
- **Migration-number comments (item 16).** The settings env overrides were retired by CIS 424
  (`424_aa1096_retire_settings_env_overrides.sql`), not CIS 428 (the TripPlanner custom domain table):
  `accounts/aa365/main.tf`, `modules/ecs/main.tf`, `tools/terraform/tests/test_aa1096_l6_infra_cleanup.py`.
  `db/scripts/dm65_consent_capture.py` (the audit placed it with CIS; it lives here): its docstring said bk-045 dropped
  `booking.customers`. bk-045 is the finance migration; the table and its consent columns are still live (schema
  reference, Verified 2026-11-18), read-only since AA-1046, until the B2C table-drop migration. Comment only: the
  script still does not read those frozen rows (the consent query page's gap is a docs follow-up).
