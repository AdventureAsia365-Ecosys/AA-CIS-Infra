# S245: DM-6.5 consent capture run-script (`db/scripts/dm65_consent_capture.py`)

One step of the legal-pages issue: the "a test inquiry stores consent value, time and source (query output)"
line needs a query over `booking.*` and `tripplanner.*`, which only the RDS master can read after X1 S18/S19.
The master path for one-off reads is DB Migrate `mode=run-script`, so the query ships here as a reviewed script.

## Decisions

- **The file is the Python block of the root repo's `docs/legal/consent-capture-query.md` ("Script for
  AA-CIS-Infra"), copied byte for byte** (checked with `cmp` against the root branch `docs/consent-capture-query`).
  The root doc is the reviewed source of the query text and the run steps; this repo only hosts the runnable copy.
- `READ_ONLY = True`: the runner opens the session with `default_transaction_read_only = on` and the idle check only
  reports, so the script can be dispatched while a job wave runs.
- Four queries, one `SCRIPT <tag>` line per row: `coverage` (value × has-time per app/source), `integrity`
  (value/time disagreement), `chain` (TripPlanner customer → Booking lead by `external_ref = tripplanner.customers.id`,
  value/time/source mismatches), `test_inquiry` (the three hops of a test inquiry by e-mail pattern).
- Test inquiries are found by `lower(email) LIKE 'aa886-consent-test%@example.com'` (bound as `$1`, never printed).
  `example.com` is the IANA reserved domain, so the pattern cannot match a real customer.

## Changed

- New `db/scripts/dm65_consent_capture.py`, `db/tests/test_dm65_consent_capture.py`, entry in `db/scripts/README.md`.
- No Terraform, no workflow, no migration, no data change.

## Tradeoffs

- A run-script instead of ECS exec: ECS exec now logs in as `cis_app`, which cannot read `booking.*` or
  `tripplanner.*` by design (X1). The run-script path costs one workflow dispatch and leaves the output in the job log.
- Unit test with a fake connection (repo convention for `db/tests`, CI has no Postgres here) plus a one-off local
  run against PostgreSQL 16 with the Dev column shapes (see "Should know"). The unit test pins the shape
  (read-only flag, SELECT-only, the three tables, no name/phone/address, e-mail only as the `LIKE $1` filter,
  soft-deleted Booking rows excluded) rather than the SQL text, so a reviewed edit of the query does not need a test
  rewrite unless it breaks one of those rules.
- No test that compares the file to the root doc: the root repo is not checked out in this repo's CI. The README
  entry says to keep the two identical.

## Should know

- Column names come from `AA-Ecosys/docs/architecture/db-schema-reference.md` (verified 2026-10-19): every column the
  queries use exists with the expected type (`booking.customers.source` CHECK `manual|otp|tripplanner_lead`,
  `booking.inbox_events.contract/payload/received_at`, `tripplanner.customers.contact_consent(_at)`).
  Payload keys `customer.email/consent/consent_at` match TripPlanner `backend/assembly/handoff.py`; `external_ref`
  is `tripplanner.customers.id` per AA-Booking `backend/app/inquiry/contract.py`.
- Local smoke (S245): throwaway PostgreSQL 16, the three tables with Dev columns, a few rows (one consenting test
  inquiry through all three hops, one v1.0 inbox event without consent, one manual Booking customer). In a
  `default_transaction_read_only = on` session all four queries ran and printed the expected lines; an INSERT in the
  same session failed with `ReadOnlySQLTransactionError` (25006). A v1.0 inbox event shows `consent=None` (no key),
  which is expected for pre-v1.1 events.
- Run after merge: DB Migrate on `main`, `mode=run-script`, `script=db/scripts/dm65_consent_capture.py`, after a live
  test inquiry with an `aa886-consent-test+<yyyymmdd><letter>@example.com` address (the root doc's run steps). A successful run also dispatches DB Schema Dump
  and DB Isolation Probe (runner behaviour for every successful run-script).
