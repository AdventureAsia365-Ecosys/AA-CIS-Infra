  by keeping `main` and adding the identity line:

  The PR's merge commit `7af10c1` is gone (linear history).
- **New group `booking-content_creator`** (S241 Q4/Q5). AA-Booking `backend/app/auth/staff.py`
  `STAFF_ROLES = ("admin", "sales", "contracting", "content_creator")` (checked on Booking
  `origin/main`); every role now has a `booking-<role>` group, precedence 70. The name keeps the
  underscore so `group.removeprefix("booking-")` equals the Booking role string exactly. The trigger's
  fallback `DEFAULT_STAFF_GROUPS` gets the same entry (Terraform passes `STAFF_GROUPS` anyway).
- **SES on by default, wired to `ses.tf`.** `ses.tf` (AA-811) now lives in the same root, and a
  read-only check on 17/10/2026 showed identity `lumiguides.it.com` VerifiedForSendingStatus=true,
  DKIM SUCCESS, MAIL FROM SUCCESS, and the account has production access (out of the sandbox,
  50,000/24h). ADR Phase 0 "done when" needs a staff email-code sign-in, which needs SES. So
  `identity_ses_enabled` defaults to `true`; the identity ARN and the two configuration sets default
  to `local.ses_identity_arn` and `aws_sesv2_configuration_set.stream["workforce"|"external"]`
  (the variables remain as overrides). The precondition that required a hand-copied ARN is reduced
  to "from address set".
- **EXTERNAL native self sign-up is a separate gate** (`identity_external_native_signup_enabled`,
  default false). Before, `NATIVE_SIGNUP_ENABLED` followed the SES switch; turning SES on would have
  opened public traveller sign-up with WAF off. Phase 0/1 is staff only (S241 "Cognito Phase 0+1
  (staff)").
- **WAF off by default** (`identity_waf_enabled = false`). S241 D-19: each new AWS spend is quoted
  and approved first. Quote recorded in the variable and in `identity.tf`.
- **Native sign-up gate is enforced** (review S241): two preconditions on `aws_cognito_user_pool.external`
  refuse `identity_external_native_signup_enabled = true` unless `identity_waf_enabled = true` (D-19)
  and `identity_ses_enabled = true`. Before, the gate was a silent AND: true with WAF off opened public
  sign-up unthrottled, true with SES off was ignored without notice.
- **D-20 and D-09 applied here, ahead of their lanes** (review S241). The 14 identity alarms carry
  `ok_actions = [aws_sns_topic.alerts.arn]` (D-20 "e-mail on OK too"), and the 4 trigger log groups
  keep 365 days (D-09: security/audit logs 365; these hold break-glass token issued, admin-create with
  staff email, refused sign-ups). The rest of the topic's alarms stay ALARM-only until the D-20 lane;
  `CONTEXT.md` names the identity alarms as the exception so that lane neither misses nor undoes them.

## Tradeoffs
- **WAF.** Cost when on (us-west-1 list prices): $5/web ACL + $1/rule × 2 rules + $0.60 per million
  requests ≈ **$7/month** for the single shared ACL in this file; ADR 0006 quotes **$12–15/month**
  for two ACLs. Without it, abuse protection is: WORKFORCE is admin-create only (SignUp refused by
  Cognito and the trigger), EXTERNAL native sign-up refused by the trigger (no user created, so no
  MAU, no mail), `prevent_user_existence_errors`, Cognito's own per-account quotas, and the SES
  bounce/complaint alarms in ses.tf. Remaining exposure: InitiateAuth email-code requests against
  existing staff addresses (each one is an SES mail, ~$0.0001) — accepted for Dev.
- **SES default true vs a tfvars switch.** CI auto-loads the tracked `accounts/aa365/terraform.tfvars`,
  which has no `identity_*` keys today, so the variable defaults are what CI applies. A key added to
  that file later overrides the default silently; keep the switches in one place (the defaults)
  unless there is a reason. Turning SES off later is a one-line flip; it updates the pools in place,
  it does not replace them.
- **Break-glass user not created by Terraform** (unchanged from #105): Terraform would hold its
  password. ADR Phase 0 lists "break-glass user"; it is done by the Phase 1 one-off script
  (AdminCreateUser with `MessageAction=SUPPRESS`, set password + TOTP out-of-band, then
  `AdminDisableUser`). Phase 0 ships the secret container `aa-identity/dev/breakglass` (no value)
  and the break-glass token alarm.
