## Tradeoffs
- **WAF.** Cost when on (us-west-1 list prices): $5/web ACL + $1/rule × 2 rules + $0.60 per million
  requests ≈ **$7/month** for the single shared ACL in this file; ADR 0006 quotes **$12–15/month**
  for two ACLs. Without it, abuse protection is: WORKFORCE is admin-create only (SignUp refused by
  Cognito and the trigger), EXTERNAL native sign-up refused by the trigger (no user created, so no
  MAU, no mail), `prevent_user_existence_errors`, Cognito's own per-account quotas, and the SES
  bounce/complaint alarms in ses.tf. Remaining exposure: InitiateAuth email-code requests against
  existing staff addresses (each one is an SES mail, ~$0.0001) — accepted for Dev.
- **SES default true vs a tfvars switch.** CI auto-loads the tracked `accounts/aa365/terraform.tfvars`,
  which has no `identity_*` keys today, so the variable defaults are what CI applies. A key added to
  that file later overrides the default silently; keep the switches in one place (the defaults)
  unless there is a reason. Turning SES off later is a one-line flip; it updates the pools in place,
  it does not replace them.
- **Break-glass user not created by Terraform** (unchanged from #105): Terraform would hold its
  password. ADR Phase 0 lists "break-glass user"; it is done by the Phase 1 one-off script
  (AdminCreateUser with `MessageAction=SUPPRESS`, set password + TOTP out-of-band, then
  `AdminDisableUser`). Phase 0 ships the secret container `aa-identity/dev/breakglass` (no value)
  and the break-glass token alarm.

# Phase 1 step I2 — WORKFORCE bootstrap tool (S242, 18/10/2026, Claude Code)

Branch `chore/aa854-workforce-bootstrap-tool`. Plan: root `docs/audits/2026-10-18-S242-cognito-phase1/plan.md`
§2 "I2". New `tools/identity/workforce_bootstrap.py` + `tools/identity/tests/` + README.

## Decisions
- **Location `tools/identity/`**, not `scripts/` (gitignored, LES:15). Checked with `git ls-files tools/identity`.
- **Break-glass address stays `admin@adventure.asia`** (D1, Nghiệp S241): default `--email` of
  breakglass-init/-verify equals `identity_breakglass_email`'s default; `identity_variables.tf` untouched.
  `create-staff` refuses that address (break-glass is only made by breakglass-init).
- **Secret JSON shape** `{username, password, totp_seed, created_at}` (plan A2; no shape was defined
  before, reader map). `created_at` is UTC ISO-8601. The R1 ADR amendment should record it.
- **Rotation without reading the old secret.** A re-run of breakglass-init calls
  AdminSetUserMFAPreference(TOTP disabled) before the password sign-in, so Cognito sends no
  SOFTWARE_TOKEN_MFA challenge for the old seed; then a new seed is associated, verified and
  preferred. breakglass-init therefore never calls GetSecretValue (only PutSecretValue).
- **Fresh TOTP window.** Before answering SOFTWARE_TOKEN_MFA the tool sleeps to 1 s past the next
  30 s boundary. breakglass-init used the current step's code in VerifySoftwareToken, so a verify
  started in the same step would otherwise reuse a code (Cognito refuses reuse). Costs up to 31 s.
- **Challenge loop.** InitiateAuth USER_AUTH with `PREFERRED_CHALLENGE=PASSWORD` + `PASSWORD` +
  `SECRET_HASH`; answers SELECT_CHALLENGE (`ANSWER=PASSWORD`), PASSWORD and SOFTWARE_TOKEN_MFA;
  anything else (NEW_PASSWORD_REQUIRED, MFA_SETUP, …) stops with an error and the finally block
  disables the user. After the first response the USERNAME/SECRET_HASH use
  `ChallengeParameters.USERNAME` (the internal user name) when Cognito returns one, because the pool's
  username attribute is email.
- **User lookup by ListUsers `email = "…"`**, not AdminGetUser (ADR 0006: AdminGetUser counts as MAU).
- **Account guard.** Every subcommand first calls sts:GetCallerIdentity and refuses any account but
  005097885195 (`--expect-account`), per the CLAUDE.md "verify account before creating" rule. The
  tool reuses the AWS CLI assume-role cache (`~/.aws/cli/cache`), so one MFA prompt is shared.
- **Spike helpers.** `authorize-url` limits `--client` to cis-admin / booking-staff (break-glass's
  managed-login test is C4, production callback only). `exchange-code` prompts for the callback URL
  with getpass when `--url` is omitted, deletes the pending file before the exchange (single use),
  checks state with `hmac.compare_digest` and the redirect URI's scheme/host/path, and revokes the
  refresh token in a finally block. Tokens are decoded for display only (not verified: they come
  straight from the token endpoint over TLS).
- **`--trigger-refusal-test` on create-staff** (not in the plan): skips only the client-side domain check
  so A5 can show the pre sign-up trigger's server-side refusal; SUPPRESS is still sent (tested).

## Tradeoffs
- **Redaction as a second line of defence.** Code paths never format secret values, and every line
  also goes through `Output.redact()` (registered password, seed, codes, client secret, tokens,
  verifier, auth code). Errors print `ERROR <Type>: <message>` with no traceback, since botocore
  param-validation messages can echo values. A 6-digit TOTP code is registered too; in theory it can
  mask a matching digit run in another line (cosmetic only).
- **Cleanup order** revoke → AdminUserGlobalSignOut → AdminDisableUser, each in its own try so a
  failure never skips the disable; failures print the exact `admin-disable-user` command.
- **The password sign-in window during rotation** (TOTP preference off, user enabled) lasts a few
  seconds and is inside the tool's own run; the alarm fires for it like any break-glass sign-in.
- **No pyotp/requests**: TOTP on hmac (RFC 6238 SHA1 + SHA256 vectors in the tests), HTTP via urllib.
