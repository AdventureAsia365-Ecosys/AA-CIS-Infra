# AA-1004 — management account root of the lean AWS model (prepared, not applied)

Root `accounts/management/` (runbook: its `README.md`). Decision record: root ADR 0018 "Lean AWS account model"
(Proposed, branch `docs/aa1004-adr-lean-aws` of the root repo). Design source: root
`docs/audits/2026-10-29-S258-aws-org-blueprint/` §0 (lean variant), §2, §4, §7.

## Decisions

- **The organization is imported, not created.** Enabling the Identity Center organization instance in the console
  (a step Terraform cannot do) creates the organization, so `aws_organizations_organization.this` is brought in by an
  `import` block keyed on `var.organization_id`. One code path whether the tech lead created the organization first
  or let Identity Center create it.
- **Member accounts in one map keyed by role** (`nonprod`, `ai`, `prod`). An invited account sets `account_id` and
  is imported by a `for_each` import block; prod leaves it null and is created. `ignore_changes` on name, e-mail,
  `role_name`, `iam_user_access_to_billing` (an invited account keeps its own; the API cannot read the last two),
  `prevent_destroy` on every account and on the organization.
- **Transitional place = directly under the root.** SCPs attach only to the OUs `NonProd`, `Prod`, `Suspended`
  (brief: never to the root). A freshly invited account therefore has no SCP of ours and can still leave if billing,
  credits or Bedrock break (blueprint §3 step 5, "OU Transitional" of the full design without a sixth OU).
- **SCP text as JSON templates** under `accounts/management/policies/`, minified with `jsonencode(jsondecode())`.
  Sizes after rendering with the defaults: 248 / 1,210 / 1,529 characters (limit 5,120).
- **SCP 3 has two statements**: everything except global services and `bedrock:*` is limited to
  `allowed_regions`; `bedrock:*` is limited to `allowed_regions` + `bedrock_extra_regions` (`us-east-2`,
  `unspecified` for `global.` inference profiles).
- **SCP 2 exemptions by role-name pattern** (`ArnLike` with `*` for the account): `OrganizationAccountAccessRole`,
  `AWSReservedSSO_AA-Admin_*`, `aa-cis-infra-tf-apply` (today it manages the nonprod account's own trail),
  `aa-terraform-apply` (blueprint name of the future per-account apply role). A variable, so no account ID appears.
- **Four permission sets, not three.** Session duration is a property of the permission set; "admin with 1-hour
  sessions in prod" and "full rights for a working day in nonprod" need two sets. `AA-Admin` (1 h),
  `AA-Developer` (8 h, nonprod and ai only), `AA-ReadOnly` (ViewOnlyAccess, prod), `AA-Billing`
  (AWSBillingReadOnlyAccess, management). Names are final: a rename destroys every assignment.
- **No users or group membership in Terraform**: personal e-mails would land in a public repo.
- **Budgets count gross cost** (`include_credit = false`, `include_refund = false`), so the AI account's Lift credit
  cannot hide spend; ACTUAL 80/100 % + FORECASTED 100 % per account, plus 50 % for the organization.
- **Anomaly detection: one CUSTOM `LINKED_ACCOUNT` monitor and one DAILY e-mail subscription per account.** E-mail
  subscribers cannot be IMMEDIATE (that needs SNS, not wanted in the management account).
- **Organization trail bucket in the management account** (lean: no log-archive account yet), SSE-KMS with its own
  key, versioning, Object Lock GOVERNANCE 365 days, Standard 90 days then Glacier IR, TLS-only, BucketOwnerEnforced;
  policy with the organization-trail write path `AWSLogs/<organization id>/*` bound by `aws:SourceArn`.
- **Centralized root access** (`aws_iam_organizations_features`) enabled with trusted access for
  `iam.amazonaws.com`: free, deletes nothing by itself.
- **Pins as `accounts/aa365`**: Terraform `1.15.5` exactly, AWS provider `~> 6.69`; lock file copied from the
  aa365 lock (same provider version 6.69.1, full hash set) so it is valid on CI's platform.
- **Partial S3 backend**: key, region, encryption and lockfile in code; bucket (it carries the account ID) and the
  local profile at `terraform init` time.

## Changed

- The brief's "Identity Center groups Admin / Developer / Billing with permission sets": groups are named
  `aa-admins`, `aa-developers`, `aa-billing` (blueprint naming), with 4 permission sets (see Decisions).
- Added `aws_iam_organizations_features` and the `account.amazonaws.com` / `iam.amazonaws.com` trusted access, from
  the lean blueprint's break-glass row; not named in the issue.
- No AI services opt-out policy, tag policy or backup policy: outside the 3-SCP scope of the issue.

## Tradeoffs

- **Import block for the organization vs letting Terraform create it**: Identity Center's organization instance
  needs the organization first, and only the console can enable that instance, so creating the organization in
  Terraform would mean two runs with a gap anyway. Import keeps one apply.
- **Managing invited accounts as `aws_organizations_account`** gives Terraform the OU placement (`parent_id`) and the
  account ID for budgets and assignments, at the cost of a resource whose destroy would remove the account from the
  organization; `prevent_destroy` and the `plan_guard.py` rule (CI wiring item 5) cover that.
- **SCP 2 exemptions by role name** are only as good as the names: anyone who can create a role named
  `aa-terraform-apply` in a member account bypasses SCP 2. Accepted for now; the apply-role names are protected by the
  existing permission boundaries in the nonprod account, and a `ProtectOrgRoles` SCP is a later addition (blueprint
  `aa-scp-baseline`).
- **CMK on the trail (1 USD/month)** vs SSE-S3 (free): kept to match the nonprod trail (AA-873) and to make reading
  logs an explicit KMS grant.

## Should know

- **Where the management account ID lives**: in the local, git-ignored `accounts/management/terraform.tfvars`
  (`*.tfvars` is ignored; only `terraform.tfvars.example` with placeholders is committed) for human applies, and in a
  GitHub environment variable of the `org` environment once CI is wired (README §11). Never in a committed file.
- **Brand-new account, region trap**: its console opened in eu-north-1. Identity Center must be enabled in
  us-west-1 (README §2 step 3); an instance enabled elsewhere has to be deleted to move.
- The Identity Center instance needs no import (data source only); the organization is adopted by the import block.
- Nothing was planned or applied; no AWS call was made. `terraform fmt`, `terraform init -backend=false`
  (providers from the local aa365 cache) and `terraform validate` pass.
- `account:CloseAccount` in SCP 1 is listed defensively; confirm the action name in the Service Authorization
  Reference at review. If it does not exist the statement is a no-op, and closing from inside already needs the
  member's root user, which centralized root access can remove.
- `bedrock_extra_regions` must be checked against the Bedrock cross-Region inference page before apply 3 of the ai
  account; the test is one real call per route (README §7 step 5).
- The agent's current local profile must not resolve to any role in `scp_exempt_role_arn_patterns`; check the role
  name it assumes before apply 3 of the nonprod account.
- First apply expectation: 1 import, 1 in-place change (trusted access list), about 44 adds, 0 destroys.
- Cost: about 1-2.5 USD/month (README §10). Organizations, Identity Center, SCPs, budgets without actions and
  anomaly detection are free.
- CI wiring (OIDC roles in the management account, GitHub environments `org` / `org-plan`, plan/apply/drift jobs,
  plan-guard rules) is listed in README §11 and not built.
