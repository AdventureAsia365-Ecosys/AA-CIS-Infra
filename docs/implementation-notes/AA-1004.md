# AA-1004 — management account root of the lean AWS model (prepared, not applied)

Root `accounts/management/` (runbook: its `README.md`). Decision record: root ADR 0018 "Lean AWS account model"
(Proposed, branch `docs/aa1004-adr-lean-aws` of the root repo). Design source: root
`docs/audits/2026-10-29-S258-aws-org-blueprint/` §0 (lean variant), §2, §4, §7.

## Decisions

- **Bootstrap through an IAM role, not Identity Center** (tech lead decision, 2026-10-30, S259). The tech lead
  creates `AA-Bootstrap` (AdministratorAccess) in the management account, trusting only the nonprod account's admin
  role (itself MFA-protected). The local profile `aa-mgmt` chains into it from `aa365-admin` (1-hour sessions).
  The role's trust ARN is typed in the console and never committed. It is deleted once an Identity Center
  `AA-Admin` sign-in works (README §4 apply 2).
- **The organization is created by Terraform** in apply 1 (the account is brand new). This is simpler than a CLI
  `create-organization` followed by an import: no import block and no organization ID variable.
- **Identity Center gated on `identity_center_enabled`** (false for apply 1). The tech lead enables the organization
  instance with one console click in us-west-1 after apply 1; apply 2 then creates groups, permission sets,
  assignments and users. `sso.amazonaws.com` trusted access is declared only when the flag is true, so the console
  click, not Terraform, switches it on (AWS asks to enable a service's trusted access from that service).
- **Users in Terraform, data in the git-ignored tfvars**: `sso_users` (given name, family name, e-mail, group)
  creates `aws_identitystore_user` + one group membership each. Nothing personal is committed.
- **Trusted access list**: `aws_service_access_principals` replaces the whole list, so the base list plus
  `extra_service_access_principals` must hold every principal already enabled; README §4 has the check to run before
  each apply.
- **Member accounts in one map keyed by role** (`nonprod`, `ai`, `prod`). An invited account sets `account_id` and
  is imported by a `for_each` import block; prod leaves it null and is created. `ignore_changes` on name, e-mail,
  `role_name`, `iam_user_access_to_billing` (an invited account keeps its own; the API cannot read the last two),
  `prevent_destroy` on every account and on the organization.
- **Transitional place = directly under the root.** SCPs attach only to the OUs `NonProd`, `Prod`, `Suspended`
  (brief: never to the root). A freshly invited account therefore has no SCP of ours and can still leave if billing,
  credits or Bedrock break (blueprint §3 step 5, "OU Transitional" of the full design without a sixth OU).
- **SCP text as JSON templates** under `accounts/management/policies/`, minified with `jsonencode(jsondecode())`.
  Sizes after rendering with the defaults: 248 / 2,076 / 1,563 characters (limit 5,120).
- **SCP 2 has three statements**: trail protection, billing/tax/account-settings protection, and
  `ProtectExemptRoles` (AWS "protect IAM roles" example): create/delete/trust/policy/boundary/tag edits and
  `iam:PassRole` on the exempt role ARNs are denied unless the caller is itself an exempt role. Billing actions:
  `billing:Put*/Update*`, `payments:*`, `tax:*`, `cur:*ReportDefinition`, `account:PutContactInformation`,
  `account:PutAlternateContact`, `account:DeleteAlternateContact`, `account:PutAccountName`. The retired
  `aws-portal:Modify*` actions are dropped (AWS replaced them with the fine-grained actions).
- **SCP 2 exemptions by role-name pattern** (`ArnLike` with `*` for the account): `OrganizationAccountAccessRole`,
  `AWSReservedSSO_AA-Admin_*`, `aa-cis-infra-tf-apply` (today it manages the nonprod account's own trail),
  `aa-terraform-apply` (blueprint name of the future per-account apply role). A variable, so no account ID appears.
- **SCP 3 Bedrock statement**: `bedrock:*` outside `allowed_regions` is denied only when
  `bedrock:InferenceProfileArn` is absent (`Null` = true), the condition the Bedrock cross-Region inference SCP
  guidance uses. Geographic (`us.`) and global (`global.`) inference profile requests are routed by Bedrock and pass.
  The earlier `bedrock_extra_regions` list (`us-east-2`, `unspecified`) is removed.
- **Four permission sets, not three.** Session duration is a property of the permission set; "admin with 1-hour
  sessions in prod" and "full rights for a working day in nonprod" need two sets. `AA-Admin` (1 h),
  `AA-Developer` (8 h, nonprod and ai only), `AA-ReadOnly` (ViewOnlyAccess, prod), `AA-Billing`
  (AWSBillingReadOnlyAccess, management). Names are final: a rename destroys every assignment.
- **Budgets count gross cost** (`include_credit = false`, `include_refund = false`), so the AI account's Lift credit
  cannot hide spend; ACTUAL 80/100 % + FORECASTED 100 % per account, plus 50 % for the organization.
- **Anomaly detection: one CUSTOM `LINKED_ACCOUNT` monitor and one DAILY e-mail subscription per account.** E-mail
  subscribers cannot be IMMEDIATE (that needs SNS, not wanted in the management account).
- **Organization trail bucket in the management account** (lean: no log-archive account yet), SSE-KMS with its own
  key, versioning, Object Lock GOVERNANCE 365 days, Standard 90 days then Glacier IR, TLS-only, BucketOwnerEnforced;
  policy with the organization-trail write path `AWSLogs/<organization id>/*` bound by `aws:SourceArn`.
- **Centralized root access** (`aws_iam_organizations_features`) enabled with trusted access for
  `iam.amazonaws.com`: free, deletes nothing by itself.
- **Pins as `accounts/aa365`**: Terraform `1.15.5` exactly, AWS provider `~> 6.69`; lock file copied from the
  aa365 lock (same provider version 6.69.1, full hash set) so it is valid on CI's platform.
- **Partial S3 backend**: key, region, encryption and lockfile in code; the bucket (it carries the account ID) at
  init time. Local runs pass exported credentials (the workspace `bash -c` wrapper), because Terraform cannot answer
  the MFA prompt behind the chained profile.

## Changed

- The brief's "Identity Center groups Admin / Developer / Billing with permission sets": groups are named
  `aa-admins`, `aa-developers`, `aa-billing` (blueprint naming), with 4 permission sets (see Decisions).
- First draft imported a console-created organization and kept users out of Terraform; the S259 bootstrap decision
  (IAM role first, Identity Center click later) made Terraform create the organization and the users.
- Added `aws_iam_organizations_features` and the `account.amazonaws.com` / `iam.amazonaws.com` trusted access, from
  the lean blueprint's break-glass row; not named in the issue.
- No AI services opt-out policy, tag policy or backup policy: outside the 3-SCP scope of the issue.
- Review fixes (S259): SCP 2 `ProtectExemptRoles`, SCP 3 inference-profile condition, no live leave-organization test,
  trusted access check, billing action list, trail deletion through the CI apply role, Object Lock note in rollback.

## Tradeoffs

- **Bootstrap role chained from the nonprod admin role vs an Identity Center bootstrap user**: the chain reuses an
  existing MFA-protected identity and needs no Identity Center before the organization exists; it caps sessions at
  1 hour and ties day 1 to the nonprod account's admin role. Acceptable for a role that lives a few days.
- **Managing invited accounts as `aws_organizations_account`** gives Terraform the OU placement (`parent_id`) and the
  account ID for budgets and assignments, at the cost of a resource whose destroy would remove the account from the
  organization; `prevent_destroy` and the `plan_guard.py` rule (CI wiring item 5) cover that.
- **SCP 2 exemptions by role name**: names alone would be bypassable, because AdministratorAccess in a member account
  (`AA-Developer`, an Identity Center session that no IAM permissions boundary covers) could create a role with an
  exempt name or rewrite the trust of `OrganizationAccountAccessRole`, then assume it. `ProtectExemptRoles` closes
  that: only exempt roles may create or edit exempt roles. Consequence: `OrganizationAccountAccessRole` must exist
  in an invited account before it moves into an OU, and a legacy admin role used for bootstrap applies in the
  nonprod account must be appended to the exemptions in tfvars (or those applies move to an `AA-Admin` session).
- **CMK on the trail (1 USD/month)** vs SSE-S3 (free): kept to match the nonprod trail (AA-873) and to make reading
  logs an explicit KMS grant.

## Should know

- **Where the management account ID lives**: in the local, git-ignored `accounts/management/terraform.tfvars`
  (`*.tfvars` is ignored; only `terraform.tfvars.example` with placeholders is committed) and the local
  `~/.aws/config`; in a GitHub environment variable of the `org` environment once CI is wired (README §11). Never in
  a committed file. The nonprod admin role ARN of the `AA-Bootstrap` trust is likewise never committed.
- **Brand-new account, region trap**: its console opened in eu-north-1. Identity Center must be enabled in
  us-west-1 (README §2 step 4); an instance enabled elsewhere has to be deleted to move.
- Nothing was planned or applied; no AWS call was made. `terraform fmt`, `terraform init -backend=false`
  (providers from the local aa365 cache) and `terraform validate` pass.
- `account:CloseAccount` in SCP 1 is listed defensively; confirm the action name in the Service Authorization
  Reference at review. If it does not exist the statement is a no-op, and closing from inside already needs the
  member's root user, which centralized root access can remove.
- The Bedrock exception is tested with one real call per route, `global.` profile included, before the ai account
  moves into an OU (README §7 step 6).
- The agent's local profile (`aa365-admin`) must not resolve to any role in `scp_exempt_role_arn_patterns`: it is
  deliberately not exempt, so after the nonprod account joins an OU the agent cannot touch trails, billing settings
  or the exempt roles there.
- Deleting the nonprod account's own trail after the organization trail runs goes through the CI apply role
  (exempt), not a local admin apply (README §8).
- First apply expectation: about 32 adds, 0 changes, 0 destroys (README §4).
- Cost: about 1-2.5 USD/month (README §10). Organizations, Identity Center, SCPs, budgets without actions and
  anomaly detection are free.
- CI wiring (OIDC roles in the management account, GitHub environments `org` / `org-plan`, plan/apply/drift jobs,
  plan-guard rules) is listed in README §11 and not built.
