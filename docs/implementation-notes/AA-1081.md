# AA-1081 — the T7 Blog minimum seed on the Dev worker (`T7_BLOG_MIN_SEED_WORDS`)

Lane: l27-infra-1077-seed (S277). The CIS code (services/acp_shared/blog_seed.py, applied by
`slate.propose_slate` in the `t7_slate` job) ships the Blog minimum seed off. Tech lead decision S277: turn it on at
600 words (the AA-1077 memo, option C). This change sets it on the Dev worker.

## Decisions

- **Nullable number variable, no env while null.** `t7_blog_min_seed_words` in `modules/ecs/variables.tf`,
  `type = number`, `default = null`: a module call that does not set it renders the task definitions exactly as
  before. Same pattern as the AA-1049 worker switches (`t2_orchestrator`, `t9_seo_builder`, `s1_control`).
- **Validation: a whole number from 1 to 5000, as a conditional.** `var.x == null ? true : (floor(var.x) == var.x &&
  var.x >= 1 && var.x <= 5000)`, so `floor()` never sees a null. 0 is refused on purpose: the app reads 0 as off, but
  off has one spelling here (null = no env), like the other switches. 5000 is a sanity ceiling (the audit's longest
  Blog seeds are near 1,000 words; anything far above would move every Subject off Blog). Checked with
  `terraform plan` on a scratch config: unset/null renders `[]`; 1, 600, 5000 render the string value; 0, -5, 600.5,
  5001, "abc" and "600" (a string) are refused.
- **Worker only, own local.** `local.t7_blog_seed_env` goes into the worker container's environment only (the
  `t7_slate` job is the only caller of `propose_slate`; `GET /v1/slate` reads the stored result). Not folded into
  `aa1049_w3_env`, which is the AA-1049 W3 set with its own guard test.
- **Value written with `tostring()`**: ECS env values are strings; the app parses `int()`.
- **Live root:** `accounts/aa365/main.tf` module "ecs" sets `t7_blog_min_seed_words = 600`. The ecs module is
  instantiated only there, and aa365 is the Dev root, so only Dev gets 600.

## Changed

- `modules/ecs/variables.tf`: the variable.
- `modules/ecs/main.tf`: local `t7_blog_seed_env` + the worker environment list.
- `accounts/aa365/main.tf`: 600, with the decision and the rollback in a comment.
- `CONTEXT.md`: the runtime-switch list names the new switch.
- `tools/terraform/tests/test_aa1081_blog_min_seed.py`: offline structure test (Terraform Plan Guard Tests).

## Tradeoffs

- A number variable instead of a string: the plan refuses a typo ("6OO") instead of the app silently reading it as
  off (`blog_seed.min_seed_words()` returns 0 for anything that is not an integer).

## Should know

- The env reaches the running worker only through a new revision: Terraform apply registers the template revision,
  CIS Deploy Dev copies the latest revision and swaps the image, so the env ships with the next CIS deploy (or a forced
  new deployment of the latest revision). After the apply, diff the env names of the newest worker revision against
  the running one (lesson S250): the only difference must be `T7_BLOG_MIN_SEED_WORDS`.
- Live proof: the next `t7_slate` job result has `blog_coverage.min_seed_words == 600`.
- Rollback: set the variable to null, apply, then CIS Deploy Dev.
