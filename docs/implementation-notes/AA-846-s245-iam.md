# AA-846 (S245) part C: narrow the CI plan and apply role inline policies

One of three AA-846 branches in S245. Each branch keeps its own notes file (`-guard`, `-drift`,
`-iam`) so parallel PRs do not conflict on one notes file (lessons log, S242).

Draft for a local MFA apply: both policies are bootstrap objects (a CI apply of them is denied by
design), so the orchestrator applies this with targets after merge, from `main`.

## Decisions

- **Measured offline, not from IAM:** the apply role's single inline policy
  (`aws_iam_role_policy.tf_apply`) is rendered from the config with `terraform console`
  (`length(jsonencode(...))`, the same minified form IAM counts) in a provider-less scratch root.
  `origin/main` renders to **9,559** characters, the figure in the issue, so the method matches the
  live policy. This branch renders to **8,678** (limit 10,240): headroom 681 -> 1,562.
- **Removed grants (nothing uses them):**
  - `DynamoDBStateLock` (apply role) and `StateLock` (plan role): the backend locks with the S3
    lockfile only after the `-drift` branch; the lockfile writes are covered by AmazonS3FullAccess
    (apply) and `StateLockfile` (plan).
  - ECR push/pull verbs of `ECRPushPull` (`GetAuthorizationToken`, `BatchCheckLayerAvailability`,
    `GetDownloadUrlForLayer`, `BatchGetImage`, `InitiateLayerUpload`, `UploadLayerPart`,
    `CompleteLayerUpload`, `PutImage`). No workflow on the apply role (terraform-apply, db-migrate,
    db-schema-dump, db-isolation-probe) pushes or pulls an image; the app repos push with their own
    deploy roles, and ECS pulls with the task execution role. Terraform refresh needs only reads.
- **Merged statements (same actions, less per-statement overhead):** `ELBDescribe`,
  `EFSDescribeList`, `IAMPolicyRead` and the ECR reads -> `RefreshRead`; `IAMRoleRead` +
  `OIDCProviderRead` -> `IAMRoleAndOIDCRead` (duplicate `iam:ListRoleTags` dropped);
  `WAFv2WebACLCreate` folded into `WAFv2Manage`. ECR reads are written as `ecr:Describe*`,
  `ecr:List*`, `ecr:GetLifecyclePolicy*`, `ecr:GetRepositoryPolicy` (read-only wildcards).
- **Left as is:** the agent-session role's `DenyTerraformState` still names the lock table. It is a
  Deny, so keeping it costs nothing and stays correct if the table is ever recreated.
- 33 -> 27 statements. A pairwise diff of (action, resource, condition) between the two rendered
  policies shows only the removals above plus the three ECR read wildcards.

## Tradeoffs

- Bigger cuts (scoping `IAMInstanceProfileManage`, `APIGatewayManage` or the WAF statement to ARNs)
  would add ARN text and need a live AccessDenied check per resource; left for AA-806 follow-ups,
  which own the role design.
- Wildcards on ECR reads trade a little explicitness for size; they grant no write.

## Should know

- **Order matters.** Apply this only after the `-drift` branch (lockfile-only backend) is merged and
  no open Infra PR still carries `dynamodb_table` (a plan with the old backend config takes the
  DynamoDB lock and would get AccessDenied once `StateLock` is gone; rebase such PRs first).
- **Apply right after merge, before any CI full-root apply.** The PR's CI plan shows in-place
  updates of `aws_iam_role_policy.tf_apply` and `aws_iam_role_policy.tf_plan`; a CI apply would hit
  AccessDenied on them by design. Local targeted plan + apply from `main` with MFA credentials, then
  re-plan the same targets (must be "No changes"), then one CI full-root apply proves the narrowed
  role still applies everything.
- No new AWS resource, no cost change.
