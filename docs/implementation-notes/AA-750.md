## What calls what (live root `accounts/aa365`)

- **No trigger exists for any of the 7.** No `aws_lambda_event_source_mapping`, no
  `aws_s3_bucket_notification`, no EventBridge rule targets them. The only resource-policy grant is
  `aws_lambda_permission.api_gateway_authorizer` (API Gateway → authorizer).
- **Step Functions `aa-cis-dev-pipeline`** (`modules/step_functions`) is the only consumer of
  `seo`, `validation`, `export`, `content`. It is started only by `services/ingestion/handler.py`
  (`start_execution`) — i.e. by the `ingestion` Lambda, which itself has no trigger. The API never
  starts it; S0 upload and the pipeline run in the API / job worker (AA-22: "Step Functions
  deployed but bypassed"). `api/routers/v1_pipeline.py` still has a legacy `send_task_success`
  branch and a `GET /execution/{arn}` poller for old executions.
- **Authorizer**: the `tenant-key-authorizer` (`modules/api_gateway/main.tf`) still exists but no
  method uses it since AA-432 (`/v1/*` moved to `authorization = NONE`; JWT checked in FastAPI).
  Its id is part of the API Gateway deployment trigger hash.
- **brand-brief-parser**: the only caller is `POST /admin/tenants/{id}/brand-brief`
  (`api/routers/admin.py`), which invokes a function named **`acp-brand-brief-parser`** and uploads
  to **`acp-bronze-867490540162`** — the old acc1 names, destroyed in AA-271. So that endpoint is
  already broken, and `aa-cis-dev-brand-brief-parser` can never be reached. No frontend page calls
  the endpoint (tenants edit the brand in BrandTab → `/brand-identity`, sanitized in-process).
- **Code is shared with the API.** `services/ingestion/excel_parser.py`,
  `services/export/handler.py` (`process_export`, `mark_tour_rejected`, cache helpers) and
  `services/seo_intelligence/*` are imported by the API/worker in-process. Retiring the Lambdas
  removes AWS resources only, never these modules.

## Checks before retiring (WSL)

1. Per function: `aws cloudwatch get-metric-statistics --namespace AWS/Lambda --metric-name
   Invocations --dimensions Name=FunctionName,Value=aa-cis-dev-<fn> --start-time <now-90d>
   --end-time <now> --period 86400 --statistics Sum` → 0 every day.
2. Last log event: `aws logs describe-log-streams --log-group-name /aws/lambda/aa-cis-dev-<fn>
   --order-by LastEventTime --descending --max-items 1`.
3. Step Functions: `aws stepfunctions list-executions --state-machine-arn <pipeline arn>
   --max-results 5` → nothing recent.
4. Snapshot each function's code + config to `s3://aa-cis-bronze-005097885195/scripts/restore/`
   (`aws lambda get-function` → download `Code.Location`; `get-function-configuration`).
