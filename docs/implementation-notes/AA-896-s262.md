# AA-896 implementation notes (S262: per-App anomaly monitors in the management root)

Lane w4f-finops-896, branch `feat/aa-896-cost-anomaly`. Root repo companion: `docs/aa-896-finops`
(`docs/implementation-notes/AA-896-finops-s262.md`, FinOps page and the monthly report tooling).

## Decisions

- **Checked what exists first.** acc2: the AWS services monitor (imported) and the IMMEDIATE subscription to the
  alerts SNS topic (S243, `accounts/aa365/cost_anomaly.tf`). acc3: budget, daily and IMMEDIATE anomaly subscriptions.
  Management root (AA-1004, #514): organization budget, per-account budgets and one LINKED_ACCOUNT monitor + daily
  e-mail per account. Missing: a monitor per `App` cost allocation tag.
- **Tag monitors only in the management account**, so the new monitors live in `accounts/management`. They are
  gated by `app_tag_anomaly_monitors_enabled` (default false): the nonprod account is still billed by the reseller's
  organization, and `App` is not an active cost allocation tag in our management account yet, so a monitor would see
  nothing. The plan is empty until the variable flips.
- **Daily e-mail, not the alerts SNS topic.** An IMMEDIATE subscription needs an SNS topic in the same account; the
  alerts topic is in the nonprod account. Same recipients and threshold as the per-account monitors (`budget_alert_emails`,
  `anomaly_threshold_usd`).
- **One monitor per App value**, one subscription for all (at most 10 values, validated), so an anomaly names the app.
- **Tag activation stays a console step** (Billing, Cost allocation tags) instead of `aws_ce_cost_allocation_tag`:
  the resource fails while the key is not yet discovered in this payer's billing data, and the CI apply role has no
  `ce:UpdateCostAllocationTagsStatus` (adding it is a bootstrap IAM change).
