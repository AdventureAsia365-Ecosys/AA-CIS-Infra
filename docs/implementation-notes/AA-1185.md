# AA-1185 — S295 audit sweep (Infra part)

Issue: S295 security audit sweep, zero-cost edge, mail, public-repo and network fixes. Lane l5-sweep of S296.

## Decisions

- **WordPress test site: off by default (Q10), not a new digest.** No rebuilt digest of the pinned tag exists upstream on
  27/11 (7.1.5-php8.4-apache, php8.5-apache and latest were all built on 24/11, before the libzstd1 fix). Both switches
  go to `false`. A test window moves the pin first (`docs/runbooks/test-wp-window.md`).
- **The CVE exception stays until the image really stops (review fix, S296).** The nightly Image Scan reads the
  running digests from the cluster, and the WordPress container keeps running after the apply until the next Booking
  admin deploy. So the `.trivyignore` line and the root register row (exp 2026-12-02) stay in this wave; they are
  removed in one small Infra + root follow-up once `aws ecs describe-tasks` shows the Booking admin task with one
  container, before 02/12. The test allows only that line with that expiry.
- **One apply turns the site off.** The service drops its second load balancer (ECS starts a deployment of the revision
  it runs, which is a deploy-made revision, not the Terraform one), then the rules, target group, DNS record and
  port go. The container stops at the next Booking admin deploy (the family's latest revision has no sidecar).
- **Edge rules are prefix patterns** (`/wp-login.php*`, `/wp-admin*`, `/xmlrpc.php*`): three values, room for one more.
  The anonymous user list is removed in the mu-plugin, not at the ALB: the CIS connection test calls the signed-in
  `/wp-json/wp/v2/users/me`.
- **Admin group alert:** two EventBridge rules on the WORKFORCE pool. Page (identity): `AdminAddUserToGroup` into
  `cis-admin`, `booking-admin` or `crm-platform-admin`. Ticket (review fix, S296): every `AdminEnableUser`, in its own
  rule, because CloudTrail records it even on an enabled user and the CIS Staff page sends it on every Reset and Sync
  (`api/services/staff_directory.py`), so it is a record, not a page. A CIS Sync of a user who already is an
  administrator re-sends the group add and pages (rare, said in the rule description). The group list indexes
  `aws_cognito_user_group.workforce[...]`, so a rename fails the plan instead of silencing the rule. Guard:
  `tools/terraform/tests/test_aa1185_identity_alerts.py`.
- **AWS Health:** rule `aa-sec-dev-aws-health` in us-west-1 (ticket severity), plus `aws.health` in the existing
  us-east-1 forwarder pattern for the global and CloudFront certificate events. No new role.
- **NAT patching:** State Manager association, AWS-RunPatchBaseline Install, RebootIfNeeded, Sunday 21:00 UTC,
  `apply_only_at_cron_interval = true` so the first run is a watched manual run, not the apply.
- **IAM policy validation in CI:** a step in the required plan job runs Access Analyzer `ValidatePolicy` on every
  policy document the plan creates or changes; ERROR and SECURITY_WARNING fail unless the allow file names them. The
  plan role's ReadOnlyAccess already includes `access-analyzer:ValidatePolicy` (AWS managed policy reference, read
  27/11): no grant, no bootstrap.
- **CRM TripPlanner URL** is the custom domain `api-tripplanner.<zone>`, the host the TripPlanner web already calls.
- **DMARC rua** goes to the ops inbox already in tfvars; CAA allows only the four Amazon CA domains (every certificate
  of the zone is ACM since the Vercel retirement).

## Changed (vs the issue scope)

- Not in this PR, each with a reason in the PR body follow-ups: switching off the default execute-api endpoints (needs
  the CRM deploy with the new URL first, and a REST stage redeploy), security-group egress narrowing and the NAT
  domain filter (behaviour changes that need a watched apply per app), removing the legacy `sg-app` group (two
  orphaned network interfaces must be deleted by hand first), importing the `api-cis.` domain (SA-56), DMARC
  `p=quarantine` (after 2–4 weeks of reports), VPC-level REJECT flow log (has a log ingestion cost).
- The resource-ID lint moves to error mode for ARNs and account IDs in the docs pages (the agent files under
  `.claude/` keep warning: agents do not edit them, the tech lead rewrites them); the account IDs inside
  Terraform (`terraform.tfvars`, cross-account role ARNs) stay: moving them to CI secrets is its own change.

## Tradeoffs

- RebootIfNeeded on the single NAT instance means about a minute without private egress once in a while, at 04:00
  Vietnam time on Monday. NoReboot would leave kernel fixes pending forever; a NAT gateway is the prod answer (~33 USD).
- `drop_invalid_header_fields` drops headers with underscores. No app or edge sends one (checked the header names
  in Terraform and the app code); a third-party callback that does would lose that header.
- Deletion protection on the ALB and NLB: a deliberate removal needs its own apply to turn it off first.

  `lumiguides.it.com._report._dmarc.<inbox domain> TXT "v=DMARC1"` (hand step, that zone is not in Terraform).
