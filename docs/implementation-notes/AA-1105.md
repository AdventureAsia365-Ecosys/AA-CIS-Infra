# AA-1105 — AA Academy part 2: implementation notes (AA-CIS-Infra)

Slice S2 (registry, identity, edge, gateway, IAM). Root notes: AA-Ecosys `docs/implementation-notes/AA-1105.md`.

## Decisions

- **`learn` joins the CIS owner with a keyed expectation.** `db/owners.yaml` adds `learn` to `cis.schemas` and to
  `runtime_privileges.cis_app.schemas`, plus a new optional key `schemas_from: {learn: "420"}`. The isolation probe
  (`RuntimePrivileges.schemas_from`, `pending_schemas`) expects the default privileges on `learn` only once CIS 420 is
  registered, so merging this PR before the DB Migrate apply never turns the nightly probe red (same rule as
  `consumer_grants.expected_from`, AA-858). The runtime-grant query already passes on a schema that does not exist.
- **Cross-app cells**: `booking`, `tripplanner`, `crm_app` and `aa_app_user` must get 42501 on `learn.learner`, keyed
  on `420` (`aa_app_user` holds nothing until P7, root ADR 0022 d1).
- **Retention rows**: `db/check_retention_rows.py` gets `RETENTION_SCHEMAS = {"cis": {"learn"}}`: only the `learn`
  tables of the `cis` dir are checked (the older CIS schemas stay grandfathered). `--scoped` answers yes only when a
  scoped table exists, so CIS copies without `learn` tables do not mint the read token.
- **Academy host = a second alias on the agency distribution** (`academy_edge.tf`), not a new distribution: same
  origin, cache policy and origin secret; the wildcard certificate covers it. Route 53 ALIAS A + AAAA. ALB rule
  `crm_academy_default` at priority 9 (free; below the deny rule 20), host + secret, any path, to the CRM web. No
  `/crm/*` rule on this host. Its own file, because `test_crm_edge_live_check` pins the agency file's rules.
- **WORKFORCE client `academy-web`**: confidential, code flow (the module's clients are all code + PKCE on the app
  side), 15 min access / 12 h refresh like `crm-staff`; callback `/academy/auth/callback`, sign-out
  `/academy/signed-out` on `academy.lumiguides.it.com` and `localhost:3005`. Managed login branding covers it through
  the existing `for_each`. No group limit (the WORKFORCE triggers are client-agnostic).
- **CRM web task**: env `WEB_ACADEMY_HOSTS`, `ACADEMY_COGNITO_DOMAIN` (the WORKFORCE managed login, same as the staff
  console), `ACADEMY_COGNITO_CLIENT_ID`; secrets `ACADEMY_COGNITO_CLIENT_SECRET` / `ACADEMY_SESSION_SECRET` from new
  keys of `crm/dev/web`. `tools/identity/crm_dev_identity.py academy-web-secret` writes them (its session key is never
  equal to the agency or staff key); the staff-web-secret logic became one shared helper.
- **CIS API Gateway**: `learn/{learn_proxy+}` (ANY, NONE, HTTP_PROXY), added to the deployment `depends_on` and the
  redeploy trigger (AA-432/465/583 trap).
- **CIS task role**: `ReadLearnMedia` (GetObject `learn-media/*`) and `DenyLearnMediaWrites` (Put/Delete), next to
  the docs-reader pair. The academy-web client id reaches CIS as a code constant with an env override, so the CIS
  task definition is unchanged.

## Changed

- `db/rls_catalogue_rules.py` is a byte copy of AA-CIS-App `tests/integration/rls_catalogue_rules.py`, which gains
  `"learn": "cis"` in its own CIS PR. That CIS PR merges first; otherwise this PR's Copy Guard fails on the copy.

## Tradeoffs

- No feature switch on the two new task-definition secrets (the AA-1019 precedent): the runbook order (apply, write
  the keys, then deploy the web) is enough because the service ignores task-definition changes.
- The live edge check gets two academy checks (`--academy-host`) that hold after the AA-Partner academy deploy;
  before it, `/healthz` already answers from the web.

## Should know

- Cost: about 0 USD (no new distribution, certificate, NAT or log group; one ALB rule).
- Merge order: CIS owner-map PR, this PR, then the CIS 420 migration PR and its Infra copy (the Copy Guard ownership
  lint reads `owners.yaml`; the retention check reads the root master, so the root S1 PR merges before the copy).
- Apply order: Terraform Apply, `crm_dev_identity.py academy-web-secret --apply`, then the next CRM web deploy.
