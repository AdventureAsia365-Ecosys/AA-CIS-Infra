# AA-860 — X1 S21 (Infra side: read-only introspection for CIS 245)

Branch `chore/x1-s21-introspect`. Companion of AA-CIS-App `feat/x1-s21-cis-owner` (migration 245, CIS schemas and
objects to `cis_owner`; its notes `docs/implementation-notes/AA-860-S21.md` hold the design) and root
`docs/x1-s21-undo` (prepared `roles/` undo). This PR adds no migration copy: the byte copy of 245 comes in its own
Copy Guard PR after the CIS PR merges (orchestrator), and starts the CIS migration freeze that ends when S22's 246
probe passes.

## Decisions
- **A run-script, not a hand list.** 245 reads the objects it moves from the catalog at apply time (the schema
  reference has no standalone sequences, type owners, domains, ranges or statistics, so a list generated from it
  would have gaps). `db/scripts/x1_245_cis_owner_objects.py` (`READ_ONLY = True`) prints, from Dev and before the
  apply, the exact list 245 step 4 will move (`SCRIPT move <kind> <name>`, in the migration's order) and every
  condition a 245 guard would refuse (`SCRIPT refuse <reason> …`): rl-002's shape (`cis_owner` NOLOGIN, plain,
  member of nothing, CREATE on the database, only the master / `db_migrator` as members), 244 registered, a third
  owner or an unmoved kind in the CIS schemas, a SECURITY DEFINER routine, the FORCE RLS set, default ACL rows other
  than 244's `cis_app` rows. It also lists the views and whether the login can read them (245 counts the readable
  ones before and after the transfer; `catalog.*` needs the master's `pg_read_all_data`).
- **`MOVE_SQL` is the migration's step-4 query verbatim.** `test_move_query_is_245_step_4` compares them
  (whitespace-normalised) once `db/migrations/cis/245_x1_cis_owner.sql` exists here, so a later edit of either side
  fails CI. Until the copy lands the test skips; it was run locally with a temporary copy (pass).
- Names and counts only: every query reads catalogs (plus two registry flags), never table rows (unit test).

## Changed
- New `db/scripts/x1_245_cis_owner_objects.py`, `db/tests/test_x1_245_cis_owner_objects.py`, a README entry.
  No runner, workflow, Terraform or `owners.yaml` change; no env var; no secret.

## Tradeoffs
- The script duplicates 245's query instead of importing it (scripts get only their own file in the task); the
  verbatim test is the guard against drift.
- It cannot predict the behavioural block of 245 (counts as `cis_owner` / `cis_app` after the transfer): that runs
  only inside the 245 transaction. `summary ok=t` means "no shape guard would refuse", not "245 will pass".
