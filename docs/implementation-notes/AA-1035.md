# AA-1035 — R2 staff roles: WORKFORCE groups (Infra half)

Root ADR 0019 d3 / d9 (S265). CIS PRs: migrations 362-364 and the tenant-scope code; Booking PRs: bk-038 and the
finance role.

## Decisions
- Seven new WORKFORCE groups in `accounts/aa365/identity.tf` `local.id_staff_groups`: `cis-content_lead` (12),
  `cis-ai_ops` (14), `cis-customer_success` (16), `cis-finance` (18), `cis-tenant_qa` (24), `cis-support` (26) and
  `booking-finance` (75). The task named only `booking-finance`, but the CIS API takes the role from the `cis-*`
  group (`api/core/staff_identity.py GROUP_ROLES`) and the Staff page writes `cis-<role>`: without the six groups no
  person could hold a new role, and the live isolation check (a customer_success session) could not run on Cognito.
- Group names follow the existing rule `<app>-<role>` with the role code as stored (underscores), like
  `booking-content_creator`; the CIS code derives them the same way (`staff_directory.cis_group`).
- Ranks: every CIS group stays in 10-39 (clarifications.md section 3: "Booking starts at 40"); `cis-reviewer` keeps
  20 and is now an alias of content for one release (CIS 363 merged its rows).
- The pre token trigger's fallback `DEFAULT_STAFF_GROUPS` and `tools/identity/workforce_bootstrap.py STAFF_GROUPS`
  list the same groups (the existing parity tests check both against identity.tf).

## Changed
- identity.tf (7 groups), the trigger fallback list, the bootstrap tool list, one new trigger test.

## Tradeoffs
- Precedence order between orthogonal roles is arbitrary (one CIS role per person is the rule); it only decides
  when a pool edit leaves two `cis-*` groups. Higher power first: admin, content_lead, ai_ops, customer_success,
  finance, then the content side.

## Should know
- Apply this before a staff member is given a new role on the CIS Staff page: the directory adds the group with
  `AdminAddUserToGroup`, which fails for a group that does not exist (the write answers 502 "saved, Cognito pending"
  and Sync retries it).
- The Lambda env `STAFF_GROUPS` is built from the same map, so the apply also updates the trigger configuration.
