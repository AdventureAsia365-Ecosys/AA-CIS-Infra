# AA-1090 — TripPlanner R8: agency domains on the TripPlanner edge (Infra part)

Lane l12-tp-domain of S281. App side: AA-CIS-App `docs/implementation-notes/AA-1090.md` (table, job, editor) and
AA-TripPlanner-Web `docs/implementation-notes/AA-1090.md` (Host routing). NOT applied in the lane: the tech lead
approves the cost note first (root `docs/audits/2026-11-15-S281-tp-custom-domain/`).

## Decisions

- **Route by a per-distribution site header, not by Host.** An agency host is added at runtime by the CIS job, so
  neither the ALB host rule nor the WAF Host regex can list it. The TripPlanner distribution adds `x-aa-tp-site` = a
  random secret as an origin custom header (CloudFront overwrites any viewer value), the new ALB rule
  `tripplanner_web_alias` forwards on it + the origin secret, and the three WAF rules match it instead of the Host
  (`modules/waf` `tripplanner_site_header`, null = the old Host scope). The Host rule `tripplanner_web` stays for the
  public host. `tools/terraform/alb_rule_order.py` R3 accepts an exact site header in place of a Host (SITE_HEADERS).
- **The job owns aliases and the viewer certificate** (`ignore_changes`). With no agency host left it restores the
  Terraform values (the public host, the wildcard certificate).
- **Least privilege** (`modules/ecs/policies/tripplanner_custom_domain.json.tftpl`, rendered and checked by
  `tools/terraform/tests/test_aa1090_tp_custom_domain.py`): ACM request / tag only in us-east-1, DNS validation, with
  the job's tag; describe / delete only tagged certificates; describe the base certificate; Get / UpdateDistribution
  on the TripPlanner distribution only. Gated: both inputs empty = no policy, no env.
