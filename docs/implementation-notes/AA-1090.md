# AA-1090 — TripPlanner R8: agency domains on the TripPlanner edge (Infra part)

Lane l12-tp-domain of S281. App side: AA-CIS-App `docs/implementation-notes/AA-1090.md` (table, job, editor) and
AA-TripPlanner-Web `docs/implementation-notes/AA-1090.md` (Host routing). NOT applied in the lane: the tech lead
approves the cost note first (root `docs/audits/2026-11-15-S281-tp-custom-domain/`).

## Decisions

- **Route by a per-distribution site header, not by Host.** An agency host is added at runtime by the CIS job, so
  neither the ALB host rule nor the WAF Host regex can list it. The TripPlanner distribution adds `x-aa-tp-site` = a
  random secret as an origin custom header (CloudFront overwrites any viewer value), the new ALB rule
  `tripplanner_web_alias` forwards on it + the origin secret, and the three WAF rules match it instead of the Host
  (`modules/waf` `tripplanner_site_header`, null = the old Host scope). The Host rule `tripplanner_web` stays for the
  public host. `tools/terraform/alb_rule_order.py` R3 accepts an exact site header in place of a Host (SITE_HEADERS).
- **Agency domains on a distribution of their own (review fix pass).** The first cut put the agency domains on the
  public TripPlanner distribution, so one shared certificate named our wildcard and every agency host: an agency that
  dropped its validation record would stop ACM renewing the certificate of the public host too. Now
  `aws_cloudfront_distribution.tripplanner_agency` is a copy of `tripplanner_web` (origin, both custom headers,
  behaviours, viewer-request function; the offline test compares the two blocks) with no alias and the CloudFront
  default certificate. The public distribution is fully Terraform's again (no `ignore_changes`). Cost: 0 (CloudFront
  pay-as-you-go has no per-distribution fee; the VPC origin is shared).
- **The job owns the agency distribution's aliases and viewer certificate** (`ignore_changes` there only). With no
  agency host left it restores the Terraform values (no alias, the default certificate).
- **Least privilege** (`modules/ecs/policies/tripplanner_custom_domain.json.tftpl`, rendered and checked by
  `tools/terraform/tests/test_aa1090_tp_custom_domain.py`): RequestCertificate only in us-east-1, DNS validation, the
  job's tag and its three tag keys; AddTagsToCertificate in its own statement (ACM authorises it to tag at request
  time, and `acm:ValidationMethod` exists only for RequestCertificate, so the combined statement of the first cut would
  have refused every tagged request) with the same tag and keys; describe / delete only tagged certificates;
  Get / UpdateDistribution on the agency distribution only; an explicit Deny of tag / untag / delete on every
  certificate tagged `ManagedBy = terraform` (provider default_tags) and on `tripplanner_custom_domain_protected_cert_arns`
  (the wildcard the public host serves). The base certificate is no longer read at all. Gated: no agency distribution
  = no policy, no env.
