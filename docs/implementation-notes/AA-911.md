# AA-911: Preview-only Cognito clients and DNS for the fixed staff Preview hosts

Root ADR 0006a A11 (S246): one fixed Preview host per staff app. Decision **D-1 (Nghiệp, 21/10/2026) = option 2**:
the separate `*-preview` app client is pulled forward now, and the APIs cap that client_id at viewer, so a session
on a Preview host can never carry a real admin or Booking role. This branch (`feat/aa-911-preview-callback`) is the
clients + DNS PR. The bridge-era `booking.staff_users` script is a separate PR (`docs/implementation-notes/AA-911-staff-rows.md`).

## Decisions

- **Hosts:** `booking-preview.lumiguides.it.com` (Vercel `aa-booking-admin`) and `aa-cis-preview.lumiguides.it.com`
  (Vercel `aa-cis-frontend`). Paths follow the apps: callback `/api/auth/callback/cognito`, sign-out `/login`.
- **Two NEW WORKFORCE clients (D-1):** `booking-staff-preview` and `cis-admin-preview`, keys in
  `local.id_workforce_clients` with the same settings as the production client (confidential, code + PKCE, scopes
  `openid email profile`, `ALLOW_USER_AUTH`, 15 min access / 12 h refresh, rotation, COGNITO only). Each is
  registered with ONLY its Preview host (`identity_variables.tf`). The production clients `booking-staff` and
  `cis-admin` keep exactly the URLs they have on `main`: a Preview host is never a production callback, so preview
  code can never finish a sign-in with a production client.
- **Managed login style:** `aws_cognito_managed_login_branding.workforce` iterates over every WORKFORCE client, so
  each preview client gets the same Adventure Asia style (created, not replaced; the existing three are untouched).
  Without a style, managed login v2 pages on `staff-auth.` do not render for that client.
- **`breakglass` is unchanged**: break-glass sign-in stays on Production only.
- **No Secrets Manager secret for the client secrets:** the existing pattern keeps Cognito client secrets in
  Terraform state and in the Vercel env var only (root secrets register rows `COGNITO_CIS_ADMIN_CLIENT_SECRET`,
  `COGNITO_BOOKING_STAFF_CLIENT_SECRET`); Nghiệp copies each value by hand. The preview secrets follow it.
- **The pre token trigger is not changed.** It sees only `callerContext.clientId`, and client ids cannot be passed
  to it without a Terraform cycle (it already uses client NAMES for EXTERNAL). The cap lives in the APIs, which see
  the verified `client_id`.
- **DNS targets** come from Vercel `get_domain_config` (`recommendedCNAME` rank 1) for each project, read
  21/10/2026: they equal each project's existing target (`booking.` and `aa-cis.`). The takeover rule in the
  variable description still holds: add the domain to the Vercel project BEFORE applying this.
- **ECS task policy comment**: `booking-jwt-signing-key` is dropped from the "CIS code reads" list (comment
  only, no IAM change; the secret is read by `GetSecretValue` on `*`, and it is deleted by the orchestrator after
  the CIS bridge removal is live).

## Tradeoffs

- One shared Preview host per app means one preview at a time can be signed in to; fine for Dev.
- A new client means new client ids in both frontends and both APIs. They are known only after the apply, so the
  app branches ship with an empty preview client id (the preview client is refused, fail closed) and the ids are
  filled in by a small commit after this apply (ship plan).
- Two more clients and two more styles in the WORKFORCE pool: free (Cognito bills MAUs, not clients; a user who
  signs in on both Production and Preview is still one MAU).
