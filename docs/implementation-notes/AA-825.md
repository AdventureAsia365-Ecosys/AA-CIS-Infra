# AA-825 — Infra: daily retention trigger + archive/ lifecycle

CIS side (retention kinds, routes, migration 233) lives in AA-CIS-App
`docs/implementation-notes/AA-825.md`. This file covers the AA-CIS-Infra change only.

## Decisions
- **Reuse the ops-probe Lambda** (`accounts/aa365/dfs_balance.tf`, function
  `aa-cis-dev-dfs-balance-check`) instead of a new Lambda/role. The CIS route docstring already
  names it as the caller. Only a second `aws_scheduler_schedule` is new; it uses the existing
  invoke role and the `aa-cis-dev-acp` group (the CI role's scheduler grants are scoped to it).
- **Own schedule, not one more entry in the 06:15 probe list.** The retention jobs count for the
  Deploy Dev guard while queued/running and sit behind the place-pipeline backlog
  (BACKGROUND_MAX_RUNNING = 1). 06:15 UTC is 13:15 ICT (working hours) and right after the 06:00
  ACP ingest. `retention_daily` runs at **20:30 UTC (03:30 ICT)**, flexible window 30 min, so it
  always fires before 00:00 UTC and the UTC day the API keys its idempotency on
  (`retention:<kind>:<day>`) is the intended one.
- **The event chooses the paths.** Scheduler `input` = `{"paths": [...], "secret_id": ...}`. With
  no `paths` the handler keeps its old default (the four probes), so the 06:15 schedule behaves as
  before. Requested paths are filtered against `_ALLOWED_PATHS`; anything else is logged
  (`ops_probe path_refused`) and skipped, so an invoke cannot aim the admin secret at an arbitrary
  route.
- **Admin secret read at run time.** Both schedules pass `secret_id` (the `aa-cis/dev/admin-secret`
  ARN, `var.secret_admin_arn`); the handler calls `secretsmanager:GetSecretValue` (already granted
  to the exec role; reachable through the NAT instance). If the read fails, it falls back to the
  deploy-time env value, so nothing breaks if the read path is wrong. The env value was not
  removed (that would mean editing an underscore env var in config, which Nghiệp does by hand).
- **archive/ lifecycle**: new rule `retention-archive-to-ia` on the bronze bucket's existing
  lifecycle configuration: prefix `archive/`, transition to `STANDARD_IA` after 90 days (DM-7
  "S3 archive objects": infrequent-access after 90 days). **No expiration**: the per-table expiry
  is not decided yet, and the archive is the only copy of deleted rows. The existing
  `raw-archive/` rule (Glacier 90 d, expiry 7 y) is unchanged; the two prefixes do not overlap.

## Changed
- `accounts/aa365/lambda_src/dfs_balance_check/handler.py`: event-driven path list + allow-list,
  run-time secret read with env fallback. The probe default and the never-raise behaviour are kept.
- `accounts/aa365/dfs_balance.tf`: `var.retention_schedule_expression` (default
  `cron(30 20 * * ? *)`), `aws_scheduler_schedule.retention_daily`, and `input` (secret_id only) on
  `aws_scheduler_schedule.dfs_balance_daily`.
- `modules/s3/main.tf`: second rule in `aws_s3_bucket_lifecycle_configuration.bronze`.

## Tradeoffs
- The handler does not raise when the retention POST fails (same as the probes), so Scheduler/Lambda
  do not retry. The call is idempotent per UTC day, so a retry would be safe, but a missed day only
  delays the run by one day, and the failure is in the Lambda log (`ops_probe http_error`) and in
  `GET /admin/job-runner/retention` (no job for that day). There is no alarm on this Lambda yet.
- IA has a 128 KB minimum billable size and 30-day minimum. Objects under 128 KB are not
  transitioned (AWS default `transition_default_minimum_object_size`), so small batch files stay in
  Standard.

## S251 — Booking retention archive grant (AA-825 reopened)

### Decisions
- **Inline policy `booking_ecs_task_retention_archive`** (`accounts/aa365/booking.tf`) on the Booking task role:
  `s3:PutObject` on `<bronze>/archive/booking/*` only, as the AA-Booking AA-825 notes asked ("Infra follow-up").
  PutObject only: the archiver never reads, lists or deletes; a restore is an operator task with the admin role.
- **Same bucket as the CIS archive** (the AA-825 archive bucket, `archive/` lifecycle to STANDARD_IA after 90 days
  above), a Booking-only prefix, so the CIS archive (`archive/<table>/`) stays out of the Booking role's reach.
  Objects get the bucket's default SSE (AES256); the Booking archiver also sets `ServerSideEncryption=AES256`.

### Changed
- `accounts/aa365/booking.tf`: the policy above + the task-role header comment.

### Tradeoffs
- A separate inline policy (like `booking_ecs_task_supply_media`) instead of one more statement in
  `booking_ecs_task`: one feature, one policy, removable on its own.

### Should know
- Cost: $0 (IAM). The archive objects are gzipped JSON Lines of failed / cancelled `booking.job` rows: a few KB a
  month on Dev.
- Apply: `-target=aws_iam_role_policy.booking_ecs_task_retention_archive` (1 to add). No service restart: the task
  role's credentials pick the policy up within minutes.
- Needed before the first live `bk_retention_job` run that has failed / cancelled candidates (incl. the S251 Dev
  manual_override proof run); succeeded-only runs and `bk_retention_inbox_redact` need no S3.
- `terraform validate` passed locally (`init -backend=false`); `terraform fmt -check` clean.
