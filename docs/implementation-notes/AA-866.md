# AA-866 — deploy/apply/migrate limited to main

## Decisions
- AA-CIS-App env `dev`: deployment branch policy = custom, branch `main` (same as Booking `dev`), set via the
  REST API on 17/10/2026. `prod` already allows protected branches only (main). Only deploy-dev.yml (push main /
  dispatch) and eval-regression.yml (dispatch) use `dev`, so nothing legitimate is blocked.
- AA-CIS-Infra is private on GitHub Free: environments cannot carry branch rules there. terraform-apply.yml now
  has the same job-level `if: github.ref == 'refs/heads/main'` that db-migrate.yml already had.
- The `cicd_split.tf` trust comment claimed a branch rule + reviewer on `prod`; corrected.
- IAM `token.actions.githubusercontent.com:ref` condition: trial on two scratch roles first (positive control on
  the trial branch, negative control on main) before touching the bootstrap roles (tf-apply, app-deploy), which a
  human applies with the MFA admin profile.

## Accepted risk (record)
- Repo-level secrets in AA-CIS-App (E2E admin login, Vercel automation bypass, Vercel token) are readable by any
  workflow on any branch of the repo. Compensated by the secrets register (U-26) and D-18. Update (S261): the
  original record assumed only Nghiệp could push; the aa-agent GitHub App (ADR 0011, S247) pushes too, so the
  accepted risk is re-assessed in Linear AA-873; revisit again when a second person gets write access.

## Should know
- A branch that edits terraform-apply.yml can remove the `if`; the IAM ref condition is what closes that.
