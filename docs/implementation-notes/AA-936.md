# AA-936 (CRM-08) — AA-Partner client host on the CRM edge

Card CRM-08 (root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §6.3, §2.1 hosts). AA-Partner branch
`feat/aa-936-slice1` serves the inquiry form at `/c/f/<key>` on the client host and the public intake API at
`/crm/public/v1`. This branch (`feat/aa-936-client-host`, on `main` since the CRM web runtime merged as #335) gives that host an edge.

## Decisions

- **A second CloudFront distribution** (`crm_client_edge.tf`) instead of an alias on the partner one: adding a name
  to the partner certificate replaces the certificate of a live host; the two hosts never share cookies anyway. The
  VPC origin, the origin-verify secret and the managed cache / origin-request policies are shared.
- **ALB rules** (`alb_rules.tf`): `crm_client_public` (6: go-dev. + secret + `/crm/public/*`) -> CRM API,
  `crm_client_default` (11: go-dev. + secret) -> CRM web. Every other API path on this host falls to the web, which
  answers 404 off `/c/*`. `alb_rule_order.py --source` OK (6 rules).
- **Why the API is reachable on the client host at all**: the form page posts to its own origin, so the API's
  per-visitor limits key on `CloudFront-Viewer-Address`; a relay through the web would make every visitor the web's
  NAT address.
- **Env**: `WEB_CLIENT_HOSTS` (web) = the client host + `var.crm_web_client_hosts`; the API gets
  `INTAKE_PAGE_ORIGINS = https://go-dev.<zone>`, `RATE_LIMIT_INTAKE_PER_MINUTE = 5`,
  `RATE_LIMIT_INTAKE_FORM_PER_HOUR = 200`.
- **E2E mailbox reader** trusts AA-Partner's `e2e` environment on main too (workflow `E2E Dev` reads the synthetic
  agency users' sign-in codes); same read-only policy. The trust pins both `sub` (the repo id + `environment:e2e`)
  and `ref` = `refs/heads/main`.

## Should know

- Cost: ≈ $0/month on Dev (distribution and certificate free, traffic inside the free tier, alias queries free).
- Apply order: after the CRM web runtime (#335, web target group; merged). The plan replaces nothing on the partner host.
- `tools/terraform/crm_edge_live_check.py` probes the client host too (review S249): `client-root` (`/` -> the web's
  404, or 503 with no web task), `client-public` (`/crm/public/v1/forms/short` -> the API's 422 JSON, or 503 with no
  API task) and `client-no-api` (`/crm/health` on the client host must NOT reach the API). Run it after the apply:
  `python3 tools/terraform/crm_edge_live_check.py --cf-domain <crm_edge distribution>.cloudfront.net`.
- **Before applying the trust change** (review S249): AA-Partner has no `e2e` GitHub environment yet (checked S249:
  only `dev` and `release`). Create it with a deployment branch policy of `main` only before the first E2E run. The
  `ref` condition already refuses any other branch; `workflow_dispatch` needs write access, so forks cannot start it.
