# AA-993 — delivery pipeline (AA-CIS-Infra part)

Design: root repo `docs/audits/2026-10-26-S252-aa993-delivery-pipeline/design.md` (D5 pre-push hooks, Phase B).

## H1 — pre-push hook, local only

Files: `scripts/pre-push.sh`, `scripts/install-hooks.sh`, `.githooks/pre-push`, `.gitignore` (track the two
scripts, ignore `.venv/`). No workflow or CI change: CI wiring is H2.

Install once per clone: `scripts/install-hooks.sh` (`git config core.hooksPath .githooks`, every worktree of the
clone). Undo: `scripts/install-hooks.sh --uninstall`. Bypass one push: `git push --no-verify`.

### Decisions

- **Selection follows the workflows' path filters.** Each check is one PR workflow; fast mode runs it when a file
  changed vs `origin/main` (committed `origin/main...HEAD` plus uncommitted tracked edits) matches that workflow's
  `pull_request.paths`, copied with GitHub glob rules (`*` stops at `/`, `**` crosses it). Commands are the workflow
  steps, run with one interpreter (`$AA_PREPUSH_PYTHON`, else `.venv/bin/python` of the worktree or main checkout,
  else `python3`). The comment next to each pattern list names the workflow it comes from: change both together.
- **Terraform.** `terraform fmt -check -diff` on the changed `.tf`/`.tfvars` files (full mode: `-recursive` on the
  repo). `init -backend=false -lockfile=readonly` + `validate` on each touched root (HCL, `.tfvars` or lock file of
  `accounts/<root>/`, or a `modules/<m>/*.tf` that root calls; the live root when no root calls the module).
  `TF_DATA_DIR` sits under the worktree's git dir, so the hook never touches the real `.terraform/` of a root that
  was initialised with the S3 backend; providers come from `TF_PLUGIN_CACHE_DIR`, else `~/.terraform.d/plugin-cache`
  when it exists, else a cache under the clone's git dir. The pinned version is read from `terraform-plan.yml` at run
  time; a different local version prints a note.
- **Network and AWS steps stay in CI** and are listed at the end of every run: `terraform plan`, gitleaks, the copy
  compares against owner main (Migration Copy Guard, Contract Copy Guard), `check_connection_budget.py
  --verify-sources` (local run drops the flag). Retention rows: run locally; a scoped (CRM) copy reads the registry
  from the root checkout's `origin/master` when the root repo sits two levels up (or `AA_ECOSYS_ROOT`), else CI only.
- **A missing tool or Python module is a skip, not a failure**, printed with the reason (CI still runs it). `--ci`
  (reserved for H2) turns a missing tool into a failure and never selects by diff.
- **Run all selected steps, sequentially**, then report every failure with the exact command, the last 25 log lines,
  the full log path (`<git dir>/aa-prepush/last-run/`) and a fix hint; then the bypass line. Never two tools at once.

### Changed vs the design

- D5 says `terraform fmt -check -recursive` for Infra. Fast mode checks only the changed files: the repo is not
  fmt-clean today (`accounts/acc1-bedrock/main.tf`, `accounts/acc3-bedrock/batch.tf`, `modules/monitoring/main.tf`
  drift), so a recursive check would block every push. `--full` keeps `-recursive` and is red until those three files
  are formatted; H2 must format them in the PR that adds `terraform fmt -check` to `terraform-plan.yml`.
- Infra has no `ci.yml` and no coverage gate: `--full` runs every check of every workflow instead.
- A Python-only change under `accounts/aa365/lambda_src/` does not trigger `terraform validate` (no HCL changed).

### Tradeoffs

- Copying the path filters keeps the hook exact today but can drift when a workflow changes; H2 removes most of that
  by having CI call the same script. Until then `--self-test` pins the selection on 25 fixture diffs.
- A shared plugin cache in the home folder (when it already exists) avoids a fresh AWS provider download per
  worktree; init + validate of the live root takes about 3–7 s and peaks near 550 MB RSS.
