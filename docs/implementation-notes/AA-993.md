# AA-993 — delivery pipeline (AA-CIS-Infra part)

Design: root repo `docs/audits/2026-10-26-S252-aa993-delivery-pipeline/design.md` (D5 pre-push hooks, Phase B).

## H1 — pre-push hook, local only

Files: `scripts/pre-push.sh`, `scripts/install-hooks.sh`, `.githooks/pre-push`, `.gitignore` (track the two
scripts, ignore `.venv/`). No workflow or CI change: CI wiring is H2.

Install once per clone: `scripts/install-hooks.sh` (`git config core.hooksPath .githooks`, every worktree of the
clone). Undo: `scripts/install-hooks.sh --uninstall`. Bypass one push: `git push --no-verify`.

### Decisions

- **Selection follows the workflows' path filters.** Each check is one PR workflow; fast mode runs it when a file
  changed vs `origin/main` (committed since `git merge-base origin/main HEAD`, plus uncommitted tracked edits, listed
  with `diff -z` so spaces, non-ASCII, quotes and backslashes in names are never quoted away) matches that workflow's
  `pull_request.paths`, copied with GitHub glob rules (`*` stops at `/`, `**` crosses it). Commands are the workflow
  steps, run with one interpreter (`$AA_PREPUSH_PYTHON`, else `.venv/bin/python` of the worktree or main checkout,
  else `python3`). The comment next to each pattern list names the workflow it comes from: change both together.
- **Terraform.** `terraform fmt -check -diff` on the changed `.tf`/`.tfvars` files (full mode: `-recursive` on the
  repo). `init -backend=false -lockfile=readonly` + `validate` on each touched root (HCL, `.tfvars` or lock file of
  `accounts/<root>/`, or a `modules/<m>/*.tf` that root calls; the live root when no root calls the module), skipped
  for a root whose directory the change deleted (no `accounts/<root>/*.tf` left).
  `TF_DATA_DIR` sits under the worktree's git dir, so the hook never touches the real `.terraform/` of a root that
  was initialised with the S3 backend; providers come from `TF_PLUGIN_CACHE_DIR`, else `~/.terraform.d/plugin-cache`
  when it exists, else a cache under the clone's git dir. The pinned version is read from `terraform-plan.yml` at run
  time; a different local version prints a note.
- **Network and AWS steps stay in CI** and are listed at the end of every run: `terraform plan`, gitleaks, the copy
  compares against owner main (Migration Copy Guard, Contract Copy Guard), `check_connection_budget.py
  --verify-sources` (local run drops the flag). Retention rows: run locally; a scoped (CRM) copy reads the registry
  from the root checkout's `origin/master` when the root repo sits two levels up (or `AA_ECOSYS_ROOT`), else CI only.
- **Fail closed.** A tool or Python module that a selected step needs and that is missing here fails the run (D5/H1
  give no skip), and the report prints an install line per tool: Terraform (pinned version, HashiCorp apt repo or
  `tfenv install`), `sudo apt-get install -y jq|shellcheck`, lychee (release binary or `cargo install lychee`), Python
  modules (`scripts/install-hooks.sh --venv` or the exact pip line). `AA_PREPUSH_ALLOW_MISSING=1` turns a missing
  tool back into a printed skip; `--ci` (reserved for H2) ignores that opt-out and never selects by diff.
  `install-hooks.sh` prints the same install lines in its tool list.
- **Fail closed on the diff too.** No merge base with the base ref (orphan branch, shallow clone), a path holding a
  newline, or any git error while listing changed files runs every check (`--full`) instead of none. A base ref
  that is not available locally does the same (the hook never fetches).
- **Fail closed on the pushed ref.** The hook checks the working tree at HEAD. Pushing HEAD or an ancestor of HEAD is
  covered; pushing any other commit (for example another branch while main is checked out) stops the push and says
  to check out that branch or bypass with `--no-verify`.
- **CI shell parity.** Each step runs with `bash -e -c`, like a GitHub `run:` step without `shell:` (`bash -e {0}`),
  so a failing command inside a multi-line step (e.g. `jq` in the db/scripts shape loop) fails locally as in CI.
  The plan-guard "refused" step starts with `set +e` as the workflow does.
- **Interpreter.** `AA_PREPUSH_PYTHON` is made absolute against the directory the script started from (steps that
  `cd accounts/aa365` keep working); a version other than the `python-version` the workflows pin (3.12) prints a note.
- **Hook environment.** The registry read from the root checkout unsets `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`
  (and the other repo-locating variables), so a hook environment cannot point those git calls at this repo.
- **install-hooks.sh.** `--uninstall` removes `core.hooksPath` only when it is `.githooks` (anything else needs
  `--force`). Install and uninstall warn when the clone's `.git/hooks` holds non-sample hooks that the change disables
  or re-enables.
- **Run all selected steps, sequentially**, then report every failure with the exact command, the last 25 log lines,
  the full log path (`<git dir>/aa-prepush/last-run/`) and a fix hint; then the bypass line. Never two tools at once.

### Changed vs the design

- D5 says `terraform fmt -check -recursive` for Infra. Fast mode checks only the changed files: the repo is not
  fmt-clean today (`accounts/acc1-bedrock/main.tf`, `accounts/acc3-bedrock/batch.tf`, `modules/monitoring/main.tf`
  drift), so a recursive check would block every push. `--full` keeps `-recursive` and is red until those three files
  are formatted; H2 must format them in the PR that adds `terraform fmt -check` to `terraform-plan.yml`.
- Infra has no `ci.yml` and no coverage gate: `--full` runs every check of every workflow instead.
- A Python-only change under `accounts/aa365/lambda_src/` does not trigger `terraform validate` (no HCL changed).

### Tradeoffs

- Copying the path filters keeps the hook exact today but can drift when a workflow changes; H2 removes most of that
  by having CI call the same script. Until then `--self-test` pins the selection on 28 fixture diffs.
- Failing on a missing tool blocks pushes on machines without lychee or shellcheck (this one, S252) whenever docs or
  the hook change. That is the point: a skipped check is a check that silently did not run. The opt-out is one
  environment variable, named in the failure report.
- A shared plugin cache in the home folder (when it already exists) avoids a fresh AWS provider download per
  worktree; init + validate of the live root takes about 3–7 s and peaks near 550 MB RSS.

### Should know

- `--self-test`: 39 assertions (28 fixture diffs incl. space + Vietnamese `.md`/`.tf` names and a deleted root, full
  mode, 7 glob edge cases, fmt targets, and two scratch git repos: odd names listed unquoted, no merge base = exit 1).
- Review fixes (second commit) checked by hand: `--list --base <orphan commit>` prints "no merge base ... running
  every check" and selects full mode; the hook fed a non-ancestor sha exits 1 with the check-out message; fast mode
  on this branch without lychee/shellcheck fails both steps with their install lines, and passes with
  `AA_PREPUSH_ALLOW_MISSING=1` (printed as skips).
- `terraform init -backend=false` + `validate` pass on `accounts/acc1-bedrock` and `accounts/acc3-bedrock` (S252, run
  one at a time with the hook's command): `--full` in H2 will not start red on validate, only on fmt (three files
  above).
- Measured (S252): planted `terraform fmt` drift in `accounts/aa365/custom_domains_variables.tf`, run through
  `.githooks/pre-push` with a git-style stdin line: blocked, exit 1, printed
  `terraform fmt -check -diff -no-color accounts/aa365/custom_domains_variables.tf` and the bypass line. Fast mode
  wall time 4.4–4.6 s for that one-file diff (6 checks, 10 steps), max RSS about 545 MB (`terraform validate`).
- shellcheck 0.11.0 `-S warning`: clean (only SC2016 info notes on intentional single-quoted jq/sed text).
