# AA-937 — CRM-09 F1 / F2 complete: Infra part (lane aa-937, S249)

Source: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §4.1 (documents: client-side `docs` DEK, then
SSE-KMS as a second layer, Fix A7), §4.3 (the F1 / F2 split; the isolation probe asserts 42501 for every NOLOGIN reader
on `crm.trip_traveler` and the vault tables, Fix A1), card CRM-09. The app side is AA-Partner `feat/aa-937-f1-f2`
(migration `crm-006`, byte copy on `chore/aa-937-crm-006-copy`).

## Decisions

- **Documents grant on the task role, objects only** (`crm_app.tf` `CrmDocumentsObjects`): `s3:PutObject`,
  `s3:GetObject`, `s3:DeleteObject` on `aa-crm-<env>-documents-*/tenants/*/documents/*`, the key shape the app writes
  (the `crm.document` CHECK refuses any other key). No `ListBucket`, no version or retention action: the app never
  lists and the bucket keeps 7 days of replaced versions by lifecycle.
- **SSE-KMS through S3 only** (`CrmDocumentsSseKms`): `kms:GenerateDataKey` / `kms:Decrypt` on the CRM data key with
  `kms:ViaService = s3.<region>.amazonaws.com` and `kms:EncryptionContext:aws:s3:arn` = the documents bucket (Bucket
  Keys). The key policy statement `CrmRuntimeS3Objects` (AA-932) already allows exactly this for the task role; the
  existing `CrmDataKeyEnvelope` statement cannot, because it accepts only the `{tenant_id, purpose}` context.
- **`DOCUMENTS_BUCKET`** in the API task definition (bucket name, not an ARN). It reaches the running task on the next
  AA-Partner deploy (the deploy copies the family's latest revision). Without it the API's document routes answer 503
  `documents_not_configured`; the rest of the card works.
- **Isolation probe cells keyed on `crm-006`** (`db/isolation_probe.py`): `vault.<reader>` for each of the four CRM
  NOLOGIN roles (no privilege on `crm.traveler`, `traveler_health`, `traveler_relation`, `document`, `trip_traveler`,
  `note`, `consent`, `form_submission`, `tenant_key`, `integration_credential`, `member`; `crm.trip_traveler` must exist
  for the cell to pass) and `views_only.<reader>` for `crm_ai_reader` / `crm_insights` (no privilege on any base table
  of `crm`). Catalog facts (`has_table_privilege`) from the catalog login, like the other role cells: the probe never
  uses `SET ROLE`. Pending until `crm-006` is registered.
