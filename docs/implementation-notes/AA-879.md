# AA-879 — CI gate parity, Infra part: the connection-budget check (U-61, folded in by S243 N-12)

U-61 = the rest of N3: C2.3c "a CI script that parses the Terraform values and fails on an over-budget sum"
and C2.3h `idle_session_timeout` on role `tripplanner`. This PR builds C2.3c. C2.3h is **not** here (see
Should know).

## Decisions

- **Manifest + checker in Infra, not in the root repo.** The process counts (ECS `max_capacity`,
  `worker_max_count`, Lambda reserved concurrency, Booking deployment overlap), the role files and
  `max_connections` all live here, and Infra has real CI (the root repo has no required CI). The root C2.2 table
  stays the human-readable version; `db/connection_budget.json` is the machine-readable one.
- **Every number is read from where it lives, the manifest only says where.** Terraform values by regex on the
  `.tf` files (stdlib, no HCL parser; an override in `accounts/aa365/*.tf` wins over a module default); role
  limits from the last `ALTER ROLE … CONNECTION LIMIT` in `db/migrations/roles/*.sql`, else `cis/*.sql` (comments
  stripped first); `max_connections` from `local.rds_max_connections`, cross-checked against the manifest's
  value for the instance class in Terraform (a resize without a measured `max_connections` fails).
- **Pool sizes are checked against the app repos' `main`** (`--verify-sources`, the same GitHub contents fetch as
  the Migration Copy Guard, public repos, `GITHUB_TOKEN` only for the rate limit). The workflow also runs nightly
  because an app PR can change a pool without touching Infra.
- **The budget is over today, so the check carries two accepted overages instead of turning red.** Real values
  (21/10/2026): `cis-api` main pool **10** (C2.2 target 5, "today 10"), api `max_capacity` 7, worker 10 × 3,
  TP browse 15 + assembly 5 (the C2.2 table still shows 10 + 10), Booking 5 × 2, `db_migrator` 3, reserves 15.
  → `cis_app` 100 > 90, total **162 > 135**. With the main pool at its target 5: `cis_app` 65, total 127 (fits).
  Shrinking the pool is a CIS runtime decision tied to the `aa859_main_pool_gauge` baseline, so it is not made
  here. Each accepted overage has a reason, `accept_up_to` = today's value (any growth fails) and `until`
  2026-12-15 (≤ 60 days; renewing needs a new reason).
- **Not modelled**: the `cis_app` per-job pools (`cis-job` export/recompute 5, S1 Jev gates 4, grounding 2 per
  in-flight rewrite), the eval pool and ad-hoc `asyncpg.connect` calls (C2.2 prose: ≈ 63 per api + worker task
  set). They have no single size in code; the `cis_app` `CONNECTION LIMIT` 90 stays their backstop.
- **Booking processes = `deployment_maximum_percent` / 100** of one task (Dev runs 1 task, no autoscaling),
  like the C2.2 row.

## Tradeoffs

- Regex over HCL breaks if a block is reshaped (for example `max_capacity` becomes a variable). It fails closed
  ("pattern not found"), which forces the manifest to be updated with the code — acceptable for 7 values.
- The nightly run reads app `main`; a pool change merged in an app turns this workflow red the next night, not on
  the app PR. Catching it on the app PR would need a check in each app repo; not worth it for 6 values.

## Should know

- **Root follow-up (orchestrator)**: the C2.2 table in root `docs/architecture/data-standards/03-scaling.md` is
  stale: TP reserved concurrency is 15 (browse) + 5 (assembly), not 10 + 10, and the `cis-api` main pool is still
  10. Update the table, or decide the main-pool shrink to 5 (AA-CIS-App `api/main.py`), which also removes both
  accepted overages.
- **C2.3h `idle_session_timeout` for `tripplanner` is not done**: it is an `ALTER ROLE` (a new `rl-NNN` roles/
  file applied by DB Migrate), the TP pool must first retry one acquire on a server-closed connection, and C2.3h
  asks for a Dev test with a thawed Lambda before enabling. That is a TripPlanner code change + a role file + a
  live test, not CI parity; it needs its own slice.
- This repo is private on GitHub Free, so branch protection is not available here (API 403); the job cannot be a
  required check. The nightly run and the PR run are the guard.
