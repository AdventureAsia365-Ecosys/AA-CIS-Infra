# AA-1138 — the CRM draft stage's Claude Haiku 5.5 entry on acc1 (Infra half)

Lane l8 of S285 (Claude Code). The AA-Partner half is crm-078 (the route) and its code PR (named connection
`bedrock_acc1`, per-connection cap); this PR gives the CRM task role a way into acc1's Bedrock.

## Decisions

- **Reuse `AA1-Bedrock-Invoker`, add a trust statement.** Root ADR 0001a Note S278 allows only the invoker role (and
  the break-glass role) on acc1, so no new role there: a second statement trusts the AA-Partner CRM task role with its
  own ExternalId (`aa1138-crm-bedrock-acc1`), so the CIS and CRM assume calls stay distinguishable in CloudTrail and
  either trust can be removed alone.
- **The CRM grant is AssumeRole only, in its own file** (`modules/environment/crm_llm_acc1.tf`): `crm_llm.tf` and its
  test stay as they were (Nova Lite on acc2 is the CRM's fallback). The model scope lives on acc1 (the role's policy,
  13 chat models); the CRM calls only the models of its route.
- **acc1's ID only through the existing secret input** (`local.bedrock_acct_payer`, repo secret
  `BEDROCK_ACCT_PAYER_ID`), passed to the module as `bedrock_acct_payer`; unset = no grant and no env.
- **Switch** `crm_llm_acc1_enabled` (default false, true in terraform.tfvars), like the other CRM switches.

- **The CRM's Claude entry uses the `us.` inference profile (review S285).** The invoker role granted only the
  `global.` profiles of the 13 chat models; a `global.` profile may serve a prompt in any AWS region, and the agency
  terms keep CRM text in US regions (root ADR 0009 decision 10: no `global.` profile for a tenant stage until the
  terms cover it). `local.crm_us_models` adds exactly one resource, the `us.` profile of Claude Haiku 5.5 in us-west-1
  (it routes to us-east-1, us-east-2, us-west-1, us-west-2 only); its foundation-model forms were already granted.
  CIS keeps its `global.` profiles. Before the first CRM draft, check live that acc1 lists
  `us.anthropic.claude-haiku-5-5` ACTIVE (read only).
- **Records (review S285).** The new trust sends scrubbed agency text through acc1. The root records that said
  "only the CIS service" are updated in a root PR of the same wave (ADR 0001a note S285, ADR 0008a §5 amendment, DPA
  Annex 3, AI Use Register CRM row); this PR ships with or after it.

## Tradeoffs

- The CRM could reach all 13 chat models the invoker role allows. A session policy on AssumeRole could narrow it to
  the route's models; not done (the CRM's route is migration-controlled and its spend is capped by its own setting).
