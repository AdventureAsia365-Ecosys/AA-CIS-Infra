## Decisions

- **S3 gateway endpoint on the private route table only** (`modules/vpc`, `aws_vpc_endpoint.s3`). Live read
  (01/11/2026, `describe-route-tables`): the VPC has four tables: public (IGW), private (NAT instance, 2 subnets),
  db (local route only, 2 subnets) and the VPC main table (no subnet). The private table is the only one with
  workloads that call S3. The db table keeps no route out of the VPC. No endpoint existed before.
- **Default endpoint policy.** A custom policy (only our buckets) would also have to list the AWS-owned ECR layer
  bucket and any bucket of another account a workload reads; getting that wrong breaks image pulls. Bucket
  policies stay the access control, unchanged. No bucket policy in this repo keys on `aws:SourceIp` or
  `aws:SourceVpce` (grep, 01/11/2026), so moving the traffic off the NAT Elastic IP changes no decision.
- **NAT recover alarm**: `StatusCheckFailed_System`, Minimum over 60 s, 2 periods (AWS's recommended recover alarm
  shape), actions = `arn:aws:automate:<region>:ec2:recover` + the alerts topic, OK e-mail too (house rule). The
  existing `StatusCheckFailed` alarm stays: it also covers instance (guest OS) failures, which recover does not fix.
- **OIDC: `ref` pin instead of new `sub` conditions.** Every GitHub OIDC role in `accounts/aa365` already pins the
  audience and an exact immutable subject per repo (guarded by `test_sec_access_analyzer.py`). The remaining gap in
  the issue's sense was the roles whose subject is an environment (`environment:dev`, `environment:scrub-corpus`)
  without the `ref` claim: Booking, CRM deploy and CRM scrub-corpus. They now require `ref = refs/heads/main`
  (`StringEquals`), like the CIS deploy, Terraform apply, DB auto-apply and e2e mail roles already did.
  Evidence that nothing breaks: every job on these roles runs in a GitHub environment whose deployment-branch policy
  is `main` (read with `gh api .../environments/<env>/deployment-branch-policies`, 01/11/2026: Booking dev, Partner
  dev / scrub-corpus / e2e, CIS dev / e2e, Infra dev-db-auto), and a reusable workflow carries its caller's ref.
- **Booking drops the `ref:refs/heads/main` subject context.** No Booking job assumes the role without the `dev`
  environment (the role ARN is an environment variable of `dev` only; the repo has no repo-level `AWS_ROLE_ARN`).
- **Read-only plan roles unchanged** (`aa-cis-infra-tf-plan`, management `aa-terraform-plan`): their subjects are
  `pull_request` and `ref:refs/heads/main`; the ref is already in the subject.
- **Identity Center alert on `AssumeRoleWithSAML`, not `ConsoleLogin`.** CloudTrail on this account, 90 days: 10
  `AssumeRoleWithSAML` events for the `AWSReservedSSO_AdministratorAccess_*` role, all in us-east-1; 8 had a
  `ConsoleLogin` one second later, 2 had none (CLI/SDK sessions). One event per session covers both paths; adding
  `ConsoleLogin` would mail twice per console sign-in. The event is read-only, so the rules use
  `ENABLED_WITH_ALL_CLOUDTRAIL_MANAGEMENT_EVENTS` and the existing us-east-1 forwarder gains a third branch.
- **One rule per permission set** (`AdministratorAccess`, `AA-Admin`), so the mail names the permission set without
  reading the role ARN. Role ARN wildcard `arn:aws:iam::*:role/aws-reserved/sso.amazonaws.com/*AWSReservedSSO_<set>_*`
  matches the default and the regional role path. Patterns proven with `aws events test-event-pattern` (read-only)
  on synthetic events: admin default path / regional path match, the other set and AA-Developer do not.
- **Action pins**: each major tag resolved read-only (`gh api repos/<o>/<r>/git/ref/tags/<tag>`, annotated tag
  dereferenced for `aws-actions/configure-aws-credentials`) to the commit it points at today, so no workflow changes
  behaviour; the comment names the full release tag that points at the same commit.

## Tradeoffs

- The recover alarm costs 0.10 USD/month (the account is past the 10-alarm free tier); the issue's Done-when said
  "$0". Everything else is 0 USD (gateway endpoint free; EventBridge rules on service events free; the forward is a
  custom event at 1 USD per million).
- Adding the endpoint route resets S3 connections open through the NAT at that second; SDK retries absorb it.
- A pinned SHA does not move with the major tag: updates now come only through Dependabot PRs (weekly, grouped).
