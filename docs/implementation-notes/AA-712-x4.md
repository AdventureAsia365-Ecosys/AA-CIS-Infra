## Decisions

- **The DRY RUN is a reviewed run-script, not ECS exec.** The frozen tables are `tripplanner.*`: the CIS runtime
  (`cis_app`) cannot read them since X1 S18, so exact counts need the master (DB Migrate `mode=run-script`,
  `READ_ONLY = True`).
- **It also previews CIS 270.** For each grant 270 revokes it prints the grantor and whether it is the object's owner:
  cis_owner's REVOKE removes only grants it made (or inherited through 245's ALTER OWNER), so `revoke_ready=false`
  means 270's guard would refuse; then the leftover grant is removed by a master run-script instead.
- **Verdict logic mirrors tp-018's guards** (no dependent outside the eight, no write on or after the cutoff), so a
  `drop_ready=true` DRY RUN predicts a clean apply. Read counters are reported, not judged: they count since the
  stats reset; two dispatches some minutes apart show whether anything still reads.
- **Tested locally** on PostgreSQL 16 with a stand-in of the eight tables and the five CIS objects, in a
  `default_transaction_read_only` session: clean set → `drop_ready=true revoke_ready=true`; a later `tour_day` row and
  a view on `tour_stop` → `drop_ready=false` with both reasons. `pg_stat_statements` was not available locally (the
  script reports `unavailable` then).

## Review round (S248)

- **The DRY RUN prints what tp-018 will lock.** Seven of the eight frozen tables hold 11 foreign keys to CIS's
  `shared.destinations`; the DROP removes their RI triggers there and takes ACCESS EXCLUSIVE on it for the length of
  the DROP (every catalog-view reader waits behind it, up to lock_timeout). New line
  `SCRIPT will_lock table=<t> fks=<n> from=<…>` (reported, not part of the verdict). SQL checked on a local
  PostgreSQL 15 stand-in in a read-only transaction (internal FKs between the eight excluded). tp-018's header and
  approval package now say the same; apply while the job tables are idle and retry on a lock timeout.
- **Branch 2 (270 copy)** follows the CIS 270 review fix (schema USAGE checked after the revoke, all seven table
  privileges in the guards); byte copy re-taken.
- **Branch 4 (tp-018 copy)** follows the tp-018 header fix (Locks, exception to ADR 0007 §10 and DM-3.8/3.9); byte
  copy re-taken.
