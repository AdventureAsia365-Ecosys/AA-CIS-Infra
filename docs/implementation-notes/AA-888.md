# AA-888 — Docs lint in AA-CIS-Infra

Scope of this PR (S245 lane): bring the docs-lint checks that run in the AA-Ecosys root repo (root PR #105) to this
repo, plus the weekly freshness report. The ADR index (`docs/adr/README.md`, PR #211) was already here.

## Decisions

- **Vendored tools.** `tools/docs/` is a copy of AA-Ecosys `tools/docs/` and the schema a copy of
  `docs/templates/frontmatter.schema.json`, byte-identical with AA-Booking (only `tools/docs/README.md`
  differs). Not yet identical with AA-Ecosys `origin/master`: `docslib.py`, `check_docs_text.py`,
  `check_frontmatter.py` and `test_docs_tools.py` carry the additions below, which go back to the root in AA-Ecosys
  branch `ci/aa888-docs-tools-sync`; after it merges, all three copies of the seven files are identical. Same reason as Booking: one copy pattern for every repo, no cross-repo token for a lint job.
- **Three backwards-compatible additions to the tools** (meant to go back to the root): `check_docs_text.py --all`
  (every tracked Markdown file minus journals: `README.md`, `CONTEXT.md`, `db/README.md`, `tools/*/README.md` are
  outside the root default scope), `--block KINDS`, and `CONTEXT.md` in the front-matter scope.
- **Resource IDs: VPC IDs and API Gateway hosts fail, the rest warns** (`--mode warn --block vpc,apigw`). STYLE.md
  says the lint warns in private repos, because Infra legitimately holds the account map, ARNs in IAM notes and
  bucket names. But STYLE.md also forbids `sg-`/`subnet-`/`vpc-` IDs and API Gateway IDs in any prose, there were
  none here (0 findings before this PR) and they change when resources are re-created, so they can block now. The
  17 remaining warnings are account IDs and ARNs in `README.md`, `CONTEXT.md`, `docs/agent-session-role.md` and one
  user-pool ID in `tools/identity/README.md` (left as warnings, not part of this issue).
- **Path filter** on `pull_request` (Markdown, `tools/docs/**`, `docs/templates/**`, the workflow): private repo,
  Actions minutes count, and there is no branch protection on this plan, so a skipped check blocks nothing.
- **gitleaks not repeated**: `secret-scan.yml` already scans every PR.

## Changed

- New: `.github/workflows/docs-lint.yml`, `tools/docs/*`, `docs/templates/frontmatter.schema.json`.
- `docs/agent-session-role.md`: the two backslash-continued AWS CLI commands (put-user-policy, assume-role) are now
  one line each, with `--region us-west-1` added. They were the only findings of the new check.
- `CONTEXT.md` (tools tree) and `README.md` (workflow list) mention the new workflow and tools.

## Tradeoffs

- Copies can drift between root, Booking and Infra; accepted, see the README rule. A later drift check could
  compare against the root from the root repo's own CI (it can read Infra with a token it already needs elsewhere).
- Blocking VPC IDs is stricter than STYLE.md's wording ("warns in root and Infra"); the root STYLE.md line should be
  updated to say "VPC resource IDs and API Gateway hosts fail in Infra too".
