# Lean repo guard (AA-1161, phase 1) — AA-CIS-Infra part

Tech lead decision S285: every repo keeps code, tests, config and text docs; screenshots are few and compressed;
build artifacts, binaries and large dumps never go into git. Phase 1 adds the guard in all six repos (one PR each,
S286 lane l5). Phase 2 (history rewrite) waits for a tech-lead decision page (root
`docs/audits/2026-11-20-S286-session/aa1161-phase2-decision.md`).

## Decisions

- **One guard, vendored byte-identical.** `tools/repo/lean_guard.py` + `tools/repo/test_lean_guard.py` are the root
  copies (root `tools/repo/README.md` documents them and the `cmp` loop), like `tools/docs`. Stdlib only, so no repo
  installs anything for it.
- **Rules** (a change = the three-dot diff base...head, added or changed files only): raster image > 500 KiB
  (`image-size`), raster images > 10 MiB together (`image-total`), `*.zip` with a `dist` folder in its path
  (`dist-zip`), ELF / Mach-O (incl. universal) / PE executables by magic bytes whatever the name (`executable`), any
  file > 5 MiB (`file-size`). SVG is text: only the 5 MiB rule (a generated diagram in the root is 543 KiB). A pure
  rename (same blob) and a deletion are never checked: they add nothing to history. One finding per file.
- **`.lean-allow`** (repo root, optional): `<path or glob> <reason>` per line, a reason is mandatory, catch-all globs
  are refused (exit 2); an allowed path is exempt from every rule and from the image total. Read from the head commit.
- **Limits are constants**, the same in every repo (tech lead policy, AA-1161). They are not app runtime thresholds:
  a git hook has no admin settings page, and a per-repo env override would let repos drift. Follow-up only if the tech
  lead wants them tunable.
- **Push time:** wired into the repo's existing `scripts/pre-push.sh` as an always-on check (like gitleaks), outside the
  pure diff-selection function, so the self-test fixtures did not change. `--allow-missing-base`: without a fetched
  base it notes and passes (CI checks every PR).
- **CI:** a blocking job `lean` added to the existing `change-guard.yml` (pull_request + merge_group, no paths filter,
  bot PRs too); the root has its own `lean-guard.yml` (no unfiltered root lint workflow exists). Blobless sparse clone
  (`filter: blob:none`, only `tools/repo` checked out); `--prefetch` fetches the changed blobs in one round trip;
  `--find-renames=100%` keeps rename detection to exact renames so no other blob is fetched.

## Changed

- `tools/repo/lean_guard.py`, `tools/repo/test_lean_guard.py` (new, byte-identical to the root copies).
- `scripts/pre-push.sh`: check `lean-guard` on every local push (not `--ci`), header documented.
- `.github/workflows/change-guard.yml`: job `lean` (blocking), header line.
- `.claude/CLAUDE.md`: the rule in 3 lines.
- **Removed `dist/lambdas/*.zip` (9 files, ~98 MB in the tree, ~80 MB of history).** Zero functional change: no `.tf`, workflow or script references them (`git grep` for `dist/`, the zip names and `filebase64sha256`: only old implementation notes). Every live Lambda is already built from source: the four `accounts/aa365` Lambdas by `data "archive_file"` (`source_code_hash = output_base64sha256`), the three TripPlanner Lambdas from S3 objects their own CI uploads (`ignore_changes` on the hash). The zips were the ACP / CIS Lambdas retired in AA-477 and AA-750. `terraform plan` therefore cannot change; no apply needed.
- `.gitignore`: `/dist/`.

## Tradeoffs

- Blocking from day one (not warn-first like the two change-guard jobs): the tech lead asked for a refusal, and a
  false positive has a cheap way out (`.lean-allow` with a reason, reviewed in the PR).
- Not a required check yet: required checks are branch protection (tech lead). A red `lean` job still blocks
  `ship_merge.py` / `ship_wave.py`, which wait for every check.
- Magic-byte check reads 4 KiB of each changed blob; a 1,179-file range ran in ~3 s locally.

## Should know

- Compress before committing: `apps/AA-CIS-App/.venv/bin/python tools/docs/compress_images.py <files or folder>`
  (root repo; PNG to 256 colours, JPEG quality 75, names kept; `--webp` for new audit images).
- To change a rule or a limit: edit the root copy, copy both files to the five repos in the same wave, run the `cmp`
  loop from root `tools/repo/README.md`.
- No test needed beyond `tools/repo/test_lean_guard.py` (18 cases: 600 KiB image and `dist/x.zip` refused, a compressed
  screenshot accepted, total budget, ELF / Mach-O / PE, `.lean-allow`, rename, deletion, non-ASCII names, CLI).
