# AA-991 — downstream freshness probe + auto-sync proof harness

Linear: AA-991 "[S1 propagation] Downstream freshness probe + proof that automatic sync works". Session S251
(25/10/2026), coding lane `aa991`. Baseline numbers: the S251 read-only coverage audit (`cis_app`, ECS exec),
root `.tmp-session/s251/audit-s1prop/coverage.txt` + `coverage2.txt`.

## Decisions

- **Delivery = the AA-986 liveness gate pattern, unchanged.** A new workflow `db-freshness-probe.yml` runs a
  READ_ONLY `db/scripts/aa991_freshness_probe.py` through the DB Migrate run-script mechanism (migrator task, runner
  sha256 check, master login read in the task) and `db/freshness_gate.py` reads the task log. No new IAM, no
  Terraform, no new task env name (the S12 test `test_no_new_environment_variable_names` covers the new workflow).
- **The probe reads as `cis_app`** (`SET LOCAL ROLE cis_app` inside its read-only transaction). The S251 baseline
  was measured as `cis_app` (container `DATABASE_URL`), every table it reads has a `cis_app` grant and, where RLS is
  on, a `<table>_cis_app_all` policy; reading as the master would see a different row set on FORCE RLS tables. The
  master is a member of `cis_app` (rl-001). A refused role switch is an error (red), never a silent master read.
- **"Tour changed" = `GREATEST(published_tours.updated_at, v_tour_liveness.changed_at)`.** `updated_at` moves only
  on a Master publish (lifecycle service `publish`, AA-645 d06); `changed_at` covers pause / retire / restore. A
  stale link counts as *aged* when its tour changed more than 24 hours before the probe (the issue's threshold; Dev
  has no traffic, so no other grace).
- **Two classes of metric.** `stale` = a link that should follow its source automatically (counts in enforce
  mode); `info` = a coverage or by-design number, reported with its S251 baseline, never red. The class lives in the
  probe's `METRICS` (one value per metric, like `expect` in the liveness probe).
- **Routes and ranking are checked by parity, not by timestamps.** Route detection keeps an unchanged route
  (no write, old `created_at`) and ranking is a platform-wide versioned swap, so "older than atoms" is a weak signal
  (kept as `info`, S251 baseline 3). The probe instead re-derives what the jobs would build from the current data:
  every (tour, segment) pair of active atoms must have a current `atom_ranking` row, no current row may sit on a
  pair that is gone, and the current `acp_contract.route` set must equal `derive_routes()` (a verbatim port of
  `services/acp_contract/route_detection.py` `_runs` / `_spans` / `LEAST_DAYS` / `LEAST_PLACES` / `MOST_DAYS`) over
  the current non-excluded ranking.
- **Report-only first.** `db/freshness_gate.py` `ENFORCE = False`: the night is red only when the probe itself
  fails (task exit, not READ_ONLY, no verdict, broken JSON, errors, visibility floor). Counts are compared with the
  S251 baseline and a rise above it is a warning. Enforce = red on any `stale` metric with aged > 0; switched on by a
  one-line PR once AA-988/989/990 close, or for one run by the dispatch input `enforce=true` (the red → green alarm
  test of the Done-when).

- **Sharper metrics next to the S251 ones.** Where the S251 query mixes legitimate and stale rows, the probe keeps
  the S251 query as `info` (baseline comparable) and adds a gated, sharper twin: atoms without a segment (info) vs
  tours with place atoms but not one segment (stale); `geo.tour_place` rows on inactive atoms for all tours (info)
  vs active tours only (stale); SEO expired for all rows (info) vs active tours (stale); every place atom without a
  card link (coverage, AA-784, info) vs links lost in tours that were carded before (stale).
- **Tenant versions older than Master are `info`.** AA-990 scope 5 / AA-986: the tenant is told and nothing is
  overwritten, so the number is by design and must never turn the night red.
- **Angle requests on inactive atoms are `stale`** (S251 finding 14/25): a T8 request on a replaced atom is a broken
  link for the tenant. Aged by the later of the tour's change and the atom row's own `updated_at`.
- **Proof harness = local driver + read-only container snapshot.** The proof needs admin API writes (trigger) and
  DB reads (per-layer timestamps); the RDS is private, so every poll is one short S3-mediated ECS exec of
  `aa991_layers.py` (cis_app, read-only) and the driver keeps the state. No long process in the api task (S234
  lesson: deploys kill it). Default trigger = `POST /admin/tours/{id}/versions/{live}/promote` (re-publishes the live
  approved version through `process_export`, re-atomizes with force): the same chain as a new S1 version after the
  gate, without paying the S1 writer; `--path s1` uses `POST /admin/run-tour-async` (the admin S1 route).
  Lifecycle default = pause / activate (reversible, no tenant notice); `--action retire` uses trash / restore.

## Changed

- The issue's scope 3 asks for "one new synthetic tour and one existing tour edited by hand". This lane ships the
  harness for an existing tour (rewrite) and the AA-986 pause / retire path; a synthetic new tour needs an S0 ingest
  (staging upload + decide) that writes customer-visible rows — left to the orchestrator as a follow-up if the
  existing-tour proof is not enough.
- Scope 4 (session-start checks + master plan tracker) is root-repo work, not in this Infra PR.

## Tradeoffs

- **Master login + SET ROLE vs ECS exec as cis_app.** The nightly could have been an ECS exec in the api container
  (cis_app natively) but ECS exec from Actions is not a pattern here, the CIS task role is the app's, and the run-script
  path already has the sha256 checks, the read-only session and the log plumbing. SET LOCAL ROLE gives the same row
  set as the S251 audit.
- **Report-only first** instead of a threshold per metric: today's numbers are the backlog of AA-988/989/990, a red
  night every night would teach people to ignore it. Warnings on a rise above the baseline keep regressions visible.
- **Route parity port** duplicates ~40 lines of AA-CIS-App code; the alternative (timestamps) gives false stale on
  every unchanged route. The port is pinned by unit tests of the five route rules; a change in route_detection.py
  must change the probe (written in the probe docstring and db/README.md).
- `orphan_segments` excludes segments still referenced by a current ranking row or route, so a stale ranking does not
  double count as an orphan; its S251 baseline (8,578) did not test the references, so the first run can only be ≤.
