# AA-887 (S245): front-matter on CONTEXT.md

Close-out step of the documentation standard: `CONTEXT.md` gets the YAML front-matter defined by the root
schema `docs/templates/frontmatter.schema.json` (AA-Ecosys repo), so agents and the catalog can read its id,
owner, scope and freshness without parsing the page.

## Decisions

- **id `ARCH-06-infra`**: one catalog entry (ARCH-06, "CONTEXT.md per repo") with one page per repo, so the page adds a
  kebab-case suffix as the schema allows.
- **type `explanation`, status `active`**: the catalog lists ARCH-06 as an explanation; the page is the current
  truth Nghiệp already works from.
- **title = the H1 exactly**, YAML-quoted (it contains an em dash).
- **applies_to `[aa-cis-infra, ecosystem]`**: this repo owns resources for every app; audience adds `devops`.
- **last_reviewed 2026-10-19**: the date of the last content commit to this file. This PR does not re-check the
  content against the live system, so it does not move the date to today (root `docs/STYLE.md`: no fake freshness).
- **related**: root catalog IDs (ARCH-01 ecosystem architecture, ARCH-05 ADR indexes, ARCH-08 data standards) and
  this repo's `docs/adr/README.md`.

## Changed

- Only the front-matter block above the H1. No body text changed.

## Tradeoffs

- GitHub renders front-matter as a small table above the page; accepted, because agents read the fields directly.
- No local lint job in this repo yet (the app-repo docs lint is a separate issue); the block was validated with a
  one-off script against the root schema instead.

## Should know

- Nothing parses `CONTEXT.md` at runtime or in CI: every reference in code is a comment. No deploy workflow
  watches this path, so merging triggers no deploy.
- The block holds no account ID, ARN or resource ID.
